# 创意上下文增量消融实验结论

日期：2026-07-11

## 结论先行

当前最值得进入生产验证的不是更多 Agent，而是一段很短的组合上下文：

1. 用完整故事包约束保证钩子、人物、能力、危机、对手、连载引擎和终局来自同一条因果链；
2. 在模型内部执行第一人称决策审计，但禁止输出审计清单；
3. 不默认注入完整脑洞 Skill；只有候选已经暴露出明确缺陷时，才选择一个紧凑原则做定向修复；
4. 不默认增加一次总编重写。它在两类确认题材中都稳定输给重写前版本，并增加延迟、截断和删坏闭环的风险。

因此，推荐的最小创意链路是：

`简单用户意图 → 3 个完整 StoryPackage 候选（内置隐式决策审计） → 严格总编辑二选一/三选一 → 锁定 CoreStorySeed`

框架负责候选竞争、事实一致性和后续记忆，不再在创意产生前预填大量方法论、钩子、Skill 目录和评分维度。

## 实验设计

- 生成模型与裁判模型固定为同一个 `openai/MiniMax-M3`；
- 相邻层级做匿名二选一；
- 每组交换 A/B 位置再判一次；
- 两次结果不一致记为 `UNSTABLE`，不强行选胜者；
- 空响应、非法 JSON、候选生成失败均记为 `INVALID`，不回退默认分；
- 裁判不奖励格式完整、术语数量、篇幅或规则复杂度；
- 五个评分维度固定为：点击与新鲜度、因果闭环、人物智识、长篇引擎、情绪承诺。

增量层级：

- `L0_bare`：简单用户请求；
- `L1_story_package`：增加紧凑的完整故事包约束；
- `L2_decision`：增加内部第一人称决策审计；
- `L3_selected_skill`：只增加一个压缩后的脑洞 Skill 原则；
- `L4_one_revision`：在 L3 后再做一次严格总编重写。

## 关键结果

### 亡者职业 / 悬疑奇幻确认题

题目：现代职业与死亡、亡者未完人生有关的长篇悬疑奇幻。

| 相邻增量 | 位置互换结果 | 结论 |
|---|---|---|
| L0 → L1 | 一票 L0、一票 L1 | 结构增强与新鲜度存在真实张力 |
| L1 → L2 | 两票均为 L2 | 决策审计稳定增益 |
| L2 → L3 | 一票 L2、一票 L3 | 脑洞 Skill 没有稳定净增益 |
| L3 → L4 | 两票均为 L3 | 默认总编重写稳定负收益 |

L2 的胜因不是字段更多，而是：主角明确排除了低成本安全方案；时间窗口、线索不可逆和人物执念共同证明高风险行为是局部最优；对手使用制度、档案和错位委托反制，而不是降智阻拦。

### 都市成年人关系确认题

| 相邻增量 | 位置互换结果 | 结论 |
|---|---|---|
| L0 → L1 | 一票 L0、另一票 JSON 非法 | 裸模型在人物选择与新鲜度上仍可能更强 |
| L1 → L2 | 两票均为 L2 | 决策审计再次稳定增益 |
| L2 → L3 | 一票 L2、一票 L3 | 脑洞 Skill 再次没有稳定净增益 |
| L3 → L4 | 两票均为 L3 | 总编重写再次稳定负收益 |

两类确认题合计：

- `L1 → L2`：4/4 个有效位置票均支持 L2；
- `L2 → L3`：2 票 L2、2 票 L3，没有净胜；
- `L3 → L4`：4/4 个有效位置票均支持 L3，即拒绝默认重写。

## 对当前框架最重要的解释

### 1. 结构不是越少越好，也不是越多越好

裸模型经常能产生更自然、更意外的人物与开篇，但容易只够一部短篇，或依赖“每卷换案子”的重复引擎。紧凑 StoryPackage 能修复这一点，但如果继续增加规则，会把创意推向解释性企划、职业名词拼接和模板化完整。

所以 StoryPackage 应当是输出契约，不应成为预先替作者做完内容选择的设定表。

### 2. 人物智识是当前最确定的高价值上下文

“如果我是这个人，我会怎么做”不能做成 15 个字段的独立 Agent，也不应把替代方案清单写进成品。有效版本只有几句话：

- 至少比较一个更安全、更便宜或更直接的方案；
- 若仍冒险，必须由信息边界、时间压力、价值观、不可替代收益或对手封锁证明它是局部最优；
- 对手也按同等智力行动。

这段内容应直接放在创意生成调用里，作为静默推理约束；只在裁判指出重大决策失败时，才启动一次定向修复。

### 3. Skill 的正确位置是“候选后的选择性增益”，不是“生成前的知识堆叠”

压缩后的单一脑洞 Skill 已经比当前全目录注入轻得多，但仍未产生稳定净胜。它有时提升机制新鲜度，有时反而让人物情感与因果闭环变弱。

生产方案应当允许选择 `0` 个 Skill。只有当候选被裁判明确判为“名词拼贴、机制可替换、职业与异常不咬合”等特定问题时，才选择一个 Skill 原则进行一次局部变体生成。

### 4. 默认总编重写不应进入主链路

两类确认题中，重写前版本获得 4/4 位置票。重写层出现了三类损害：

- 删除已经成立的长篇引擎或终局选择；
- 为追求文案锐度压缩掉关键因果；
- 增加一次高延迟调用，并两次触发输出长度耗尽。

总编模型应优先做选择与指出单一致命缺陷，不应默认整稿重写。只有明确缺陷、明确保留项、明确修改边界时才允许 repair。

## 推荐的生产修改顺序

### P0：建立 Lean Concept 路径

新增可开关的精简路径，只保留：用户意图、短 StoryPackage 输出契约、静默决策审计。禁止注入完整 methodology、完整 Skill catalog、预生成 hook、章节级效果目录和多维解释性 rubric。

一次生成 3 个完整候选，而不是让多个 Agent 分别生成钩子、能力、人物和世界后再拼装。

### P0：总编辑只做候选选择

用本实验的五维标准做匿名候选比较；禁止默认分。输出被截断、JSON 无效或模型空响应时标记 `INCONCLUSIVE`，不得自动放行。

总编辑选中一个完整候选后，锁定不可变 `CoreStorySeed`：核心钩子、人物欲望与缺陷、能力规则、第一危机、对手、长篇引擎、终局问题。

### P1：定向修复代替全稿重写

只有当裁判给出一项明确硬伤时修复一次，例如：

- 主角无视显然更安全方案；
- 对手为了剧情突然变蠢；
- 能力、代价与冲突不构成因果；
- 长篇只能机械重复同一动作；
- 新奇点只是名词拼贴。

修复提示只包含原候选、一个缺陷、必须保留的 CoreStorySeed 字段，不再加载全套框架。

### P1：Skill 允许零选择

先生成完整候选，再由缺陷路由器判断是否需要一个 Skill。Skill 只提供 3 至 5 行语义原则，不注入全字段契约，更不注入所有 Skill 全文。

### P2：用真实书籍结果做 A/B

在相同题目、相同模型、相同随机样本数下比较：

- 当前生产全链路；
- Lean Concept；
- Lean Concept + 单次定向 repair。

至少评估概念、卷纲和前三章三个断面。只有 Lean 路径在概念胜出且没有在前三章退化，才替换默认路径。

## 评测器自身发现的问题

实验过程中真实发现并修复了三种会制造假结论的评测故障：

1. 模型空响应导致整批结果丢失；现改为逐条检查点并记 `INVALID`；
2. 裁判隐藏推理吃掉输出预算，JSON 被截断；现提高预算且不使用默认分；
3. JSON 解析器误把内部 `a_scores` 当外层结果；现从最外层对象解析，并支持从原始裁判结果重建报告。

这些故障与当前生产门禁“输出截断后使用默认分继续放行”属于同一类风险。生产裁判必须失败显式化，不能失败乐观化。

## 2026-07-11 午间复验与生产决策

新增三题材、每题 1 个样本的完整双向盲评，产物位于
`output/creative-context-ablation/20260711T115646/`。本轮结果：

- `L0 → L1 StoryPackage`：3/3 稳定支持 L1；
- `L1 → L2 决策审计`：1 次 L1 胜、1 次不稳定、1 次裁判无效；
- `L2 → L3 单一压缩脑洞原则`：3/3 稳定支持 L3；
- `L3 → L4 默认整稿重写`：1 胜、1 负、1 不稳定，仍无稳定净收益。

与前两题确认实验合并解读：紧凑 StoryPackage 是目前最稳定的基础增益；第一人称
决策审计仍保留为候选内部证据和人物逻辑硬门，但不额外启动独立 Agent；压缩脑洞
原则只注入杂交候选，对照候选保持纯题材，让同一裁判决定是否采用；默认整稿重写
不进入主链路。

生产链路据此实现为：多个同源 `CoreStorySeed` 候选 → 单轴硬门淘汰 → 冠军生成
`ConceptContract`（HookCard + SerialityProof + 分层 StorySpine）→ 卷级映射 → 章纲级
不可逆推进验证。新建 200 章以上项目没有合同或容量不足时，不得进入规划。

## 2026-07-11 下午：真实长篇门禁与模型路由复验

生产实验不再让候选一次性同时写钩子和 500 章证明，而改为两段：先生成紧凑
`CoreStorySeed` 并裁判钩子，只给前两名扩展 `SerialityProof`。容量证明必须给出连续覆盖
目标章数的阶段范围、可重复故事单元频率与数量，并再经六轴长篇裁判；弱证明只允许在
冻结钩子的前提下定向修复一次。

真机连续实验暴露并补齐了四种“表面宏大、实际注水”的假长篇：阶段只写到第 50 章却
声称支持 500 章；用随机折寿或器官衰竭冒充代价；用行业术语替代题材魅力；靠年度仪式
或同类案件低频重复拉长篇幅。新增门禁分别检查阶段覆盖、机制内生因果、题材保真、
大白话可读性、读者承诺存活与故事单元密度。

同时确认一个运行时根因：概念生成、钩子裁判、长篇扩展和长篇裁判此前全部走
`planner/strong`，但当前部署的 `strong` 仍解析为 `openai/MiniMax-M3`，没有模型独立性。
代码现已把生成模型与统一裁判模型拆为两个 catalog 路由，并在验证产物中记录实际键；
但 2026-07-11 的可用性实测显示，DeepSeek 余额不足、NVIDIA NIM 返回账号函数 404、
Qwen 无模型权限、MiMo 认证失败，只有 MiniMax M2.7/M3 可调用。故生产配置暂时显式使用
M3，不能把“环境中存在密钥”误报为“模型可用”，也不能假装已经完成跨模型裁判。

当前结论不是“已经稳定生成顶级钩子”，而是门禁已经从强行选一个，改为证据不足就
没有冠军、长篇构思在进入后续多 Agent 规划前停止。下一步质量提升的最高杠杆是恢复
一个真实可用、不同家族的强生成模型和固定裁判模型，再按同题盲测决定生产默认路由。

### Docker 镜像复验补充

第一轮新镜像都市 500 章实验错误放行“我在葬礼上继承死人的债，可催债的鬼魂比活人
更讲理”，其承载证明随后退化成民间借贷、账册和关系变现。由此确认原七轴仍会把
“结构字段齐全”误认成“一句话已经有故事”。新增 `story_motion` 硬门：一句话自身必须
同时出现主角会持续做的动作和会学习/反制他的阻力；俏皮反差、能力说明、身份加秘密，
不得依赖后文机制圆成故事。同时将“继承死人的债/替死人还债/人情债关系网变现”加入
已验证污染俗套。

第二轮新镜像同题实验不再强行选冠军。最接近合格的候选是“小区监控员从监控死角捡回
未发生画面，替刑警复原凶手想杀却未杀成的一刻”，钩子分 7.4，但长篇裁判明确以
renewability=4、unit_density=4、promise_survival=5 淘汰：案件模板易重复，不能靠虚报
单元数支撑 500 章。该结果符合“先搞定一句话且证明能长写，否则不进入规划”的目标。

## 2026-07-11 晚间：干净种子、因果飞轮与近失定向修复

本轮用独立 `concept_seed` 通道反复验证都市黑科技 500 章输入，明确清空
`concept_lab_bundle` 与 `hook_spec`，排除了旧创意包污染。实验依次发现并修复：

1. 原 `63/84` 微单元下限是算术错误；500 章按 2-4 章微单元计算，当前确定性下限为
   167，真机候选实际给出 167-186 个单元后才可能进入长篇裁判；
2. “同源补强”曾错误冻结弱持续动作，导致六路候选全部复述“做一条路线、被封杀一次”；
   现只冻结人物、能力、对手与产业冲突，允许重建持续行动；
3. 钩子裁判曾被后附 SerialityProof 抬分，把平行重复误判为 8.35；现明确只按一句话的
   标志性规则评分，“做一个产品、资本再封杀一次”新颖度上限为 6；
4. 60/80 字硬限制会把 81 字候选在裁判前误杀；现建议 40-90 字、硬上限 120 字，并将
   人物小传、决策证明和三级长篇结构留在独立字段；
5. 第二轮此前是失忆重抽。现首轮 6 路探索，后续每轮仅用 2 路围绕最佳近失及真实失败轴
   定向修复，最多三轮，总候选上限从 12 降为 10。

最终镜像任务 `c1085b7f-75f0-4b36-af2a-248059ecc48a` 没有创建书籍、没有进入规划。
最佳候选钩子通过八轴门，但 500 章长篇裁判给 escalation=7、unit_density=7，低于 7.5
硬线；后续两轮定向修复仍未产生合格候选。该结果说明门禁已经能拒绝“钩子尚可、长篇
必注水”的种子，但不代表当前单模型生成已达到榜单顶尖稳定性。
