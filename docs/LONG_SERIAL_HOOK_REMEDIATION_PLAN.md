# 长篇一句话钩子完整开发与修复计划

## 目标状态

系统不是“能拒绝烂钩子”就算完成，而是同时满足：

1. 对合理题材输入能稳定生成让目标读者想点、人物聪明、因果闭合的一句话钩子；
2. 钩子背后的同一个故事承诺能够支撑 300-500 章，而不是靠换对象、换地图或重复案件注水；
3. 失败时在项目、市场、人物、世界观和书籍规划之前停止；
4. 所有放行都有 HookCard、SerialityProof、确定性审计和独立裁判证据；
5. 提示词和 Agent 数量只保留经对比实验证明有净收益的部分。

## 已确认根因

- 当前候选生成提示过重，负面规则、人物证明和长篇结构争抢一句话表达空间；
- 同源补强曾把用户种子中的弱循环也冻结，导致多路候选只是换措辞；
- 同模型生成与裁判存在共同盲区，后附完整设定会抬高平庸钩子的分数；
- 数字齐全不等于长篇成立，必须同时检查因果飞轮、阶段换玩法和不可逆积累；
- 全量重抽浪费调用，最佳近失的定向修复更可控；
- 只验证单一都市黑科技种子不能证明跨题材稳定性。

## 开发阶段

### Phase 1：基准与实验合同

- 固化 viable、weak-seed、anti 三组案例；
- 记录 Current 与 Lean 的精确提示、候选、模型路由、分数和成本；
- 输出 pass@1、pass@3、pass^3 与位置互换盲评；
- 禁止无效裁判使用默认分。

### Phase 2：Lean 候选生成臂

- 只保留紧凑 StoryPackage；
- 决策合理性作为候选内部要求，不启动独立 Agent；
- 只注入一条“第一眼意外、解释后必然且改变后续状态”的脑洞原则；
- 一句话只承担标志性发现/行动和立即后果；
- 长篇证明继续由入围后的独立 SerialityProof 负责。

### Phase 3：同门禁 A/B

- Current 与 Lean 使用相同模型、候选数、裁判、阈值和长篇证明；
- 先跑离线/注入模型测试，再跑真实模型；
- Lean 未达到评测晋级线则不替换生产默认。

### Phase 4：门禁与下游合同

- HookCard 只保存冻结的一句话故事承诺；
- SerialityProof 验证微单元、不可逆积累、势力生态、阶段覆盖和终局汇聚；
- ConceptContract 作为下游唯一创意事实源；
- 卷纲和章纲必须映射同一合同，偏离即停止而不是自动圆回。

### Phase 5：真实 Docker 验收

- 至少跑一个合格案例和一个弱种子案例；
- 合格案例只停在 Conception 审批态，不启动规划；
- 弱种子没有项目行、没有 workflow、没有队列任务；
- 核验 Web、DB、Redis、任务文件和容器健康状态一致。

## 完成标准

以 `.claude/evals/long-serial-hook-pipeline.md` 的 Promotion Rule 为准。
单次随机成功、单题材通过、字段齐全或单元数量达标，均不能作为完成证据。

## 2026-07-11 实施进展与剩余验收

已完成的生产修复：

- 原始创意生成拆成 `minimal / methodology / guarded / enhanced` 四个可复现实验臂；
- 原始创意生产默认选用 `methodology`：只增加“异常首次出现后仍迫使主角作出不同选择”这一条规则；
- 原始创意裁判补齐人物理性、AI 拼装和愚蠢代价硬门，按次折寿/失忆/伤身不得由均分抵消；
- 评估器不再跳过“没有冠军”的失败样本，所有提示臂两两比较，双边失败也显式记录；
- ConceptContract 保留完整 `unit_families` 和 SerialityProof，并把证明字段全部纳入 lineage hash；
- 2000 章容量有独立下限，不能再被 1000 章上限或虚报单元数量绕过；
- v2 项目停止重新生成旧 HookSpec，ConceptContract 成为规划唯一创意事实源；
- VolumePlan 必须使用准确的 phase id/ref、unit family 和 accumulation track/delta 映射；
- 章纲必须继承本卷 phase/family，引用既有状态，给出不可逆状态，并满足故事单元密度。

当前实验证据：

- 仙侠每臂 6 个候选：minimal 0/6，methodology 2/6，guarded 2/6，enhanced 2/6；
- 都市+历史每臂 8 个候选：minimal 0/8，methodology 1/8，guarded 2/7，enhanced 1/8；
- enhanced 在都市+历史的 AI 拼装均分为 4.625，明显劣于 methodology 的 2.5，且人物逻辑、题材保真更低；
- methodology 产出“外卖骑手因预演路况成为站长，反从被算法压榨者变成压榨执行者”等自然因果候选；
- enhanced 仍集中出现亡者、遗愿、胎记手术、时间票据、代坐协议等过度组装，证实重上下文会改变模型选材分布。

尚未完成：用 `engine_first + methodology` 跑完整锦标赛并人工复核冠军；通过后切换生产默认，重建 Docker，创建一本只停在 Conception 的测试书，再核对 Web、DB、任务和容器证据。未完成这些步骤前不得宣称修复结束。
