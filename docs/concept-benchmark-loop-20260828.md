# 创意对标闭环：以榜单为目标的自我修复流程（2026-08-28）

用户定的设计：**榜单书就是标准答案**，不需要人工标注。同样的输入参数，
框架生成 vs 真实爆款，盲评胜率即分数；靠近它就是达标。

## 为什么这个设计比之前的都好

我前面试过三种验证方式，全部失败或不可用：

| 方式 | 结果 |
|---|---|
| 语料库长篇 vs 中短篇的开头特征 | 四维度差值全在 ±5%，**无分离** |
| 阅读榜长篇 vs 新书榜 | 好 vs 好，**对照组设计错误** |
| 框架自评（appeal 83.9 分） | 与用户判断相反，**自己判自己** |

用户这个设计解决了三件事：
1. **有绝对标准**：目标书真的跑到了 500-2200 章，不是「看起来能跑」；
2. **输入受控**：同样的分类/标签/频道，差距只来自创意本身；
3. **不需要标注**：省掉「先让用户标 30 条」这个前置阻塞。

## 三条设计约束（缺一条，测出来的分就是假的）

### C1 同格式比同格式

我们产出的是**一句话创意**，榜单给的是**完整简介**（带【标签行】、分行、对白）。
直接对比，判官光看格式就能认出谁是谁——测的就不是创意质量而是格式差异。

所以先用 LLM 把榜单简介**压成同格式的一句话**，压缩时**只许删不许编**
（prompt 明写「不许添加原文没有的人物、设定、情节或评价」）。

### C2 盲

左右随机互换；判官提示里不出现「AI/生成/框架/投稿」这类暗示。

### C3 只用已证明的长篇

阅读榜 + ≥500 章 + 简介 >120 字 → 306 本。这些书**真的跑到了**那个长度。
新书榜（中位 93 章）不进池子——它们还没证明自己。

## 闭环流程

```
① 抽样      从 306 本目标书里随机抽 N 本（固定 seed，可复现）
② 压缩      榜单简介 → 同格式一句话（只删不编）
③ 生成      用该书的「分类+标签+频道」跑生产 prompt，出一句话创意
④ 盲评      随机左右 → 四轴逐项选优 + 总胜 + 一句「输的差在哪」
⑤ 报告      总胜率 + 四轴分项胜率 + 逐条判词
⑥ 诊断      从判词里找系统性缺陷（不是逐条改，是找模式）
⑦ 修复      改 prompt / 加判据
⑧ 复测      同 seed 同 N 重跑，compare 两轮
```

**四条轴**（判官逐项选，不是打分——避免分数聚集）：

- `sustain` 能持续产出同类故事，还是开局高光之后没了
- `escalate` 升级是换玩法，还是换更大的名词
- `hook` 更想点开
- `concrete` 设定具体可想象，还是概念口号

分轴的意义：总胜率只告诉你输了，**分轴告诉你输在哪**，第 ⑥ 步才有抓手。

## 判定规约

- **基线**：修改前的胜率，作为锚点。预期远低于 50%。
- **有效改进**：同 seed 同 N 复测，总胜率提升**且**至少一条轴同向提升。
  单看总胜率会被判官噪声骗（仓库已实证判官单轴 std 0.7-1.1）。
- **达标线**：胜率 ≥ 40%。不追 50%——目标书是**已验证的爆款**，
  平手就意味着框架产出与爆款同级，那是上限不是及格线。
- **样本量**：N=12 只够看大效应（>20 个百分点）。定案前 N≥30。

## 已知限界

- **单一判官家族**：判官与生成同为 M3，存在同源高估（仓库实证 0.15-0.20）。
  跨家族判官是后续改进项。
- **单日快照**：目标池来自 2026-08-26 抓取。热度是活数据。
- **压缩引入噪声**：把简介压成一句话本身有信息损失，对目标书不利
  ——**这个偏差方向对我们有利**，所以胜率是乐观估计，不是悲观估计。

## 用法

```bash
.venv/bin/python scripts/concept_benchmark.py run --n 12 --tag baseline
# 改 prompt 之后
.venv/bin/python scripts/concept_benchmark.py run --n 12 --tag after-fix
.venv/bin/python scripts/concept_benchmark.py compare baseline after-fix
```
