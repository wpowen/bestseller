# 创意质量攻坚方案（2026-08-27）

用户定性：现在的设定是「应付差事」，没有竞赛出来的东西撑不起一本书。
目标：让框架产出**榜单级别**的创意，而不是「一个还不错的想法」。

本方案分三个角色视角：产品（定义什么是合格）、开发（调研与技术实验）、
测试（对比验证设计）。**每一条都标注证据等级**，不把假说当结论。

## 一、产品视角：什么叫「合格的创意」

### 1.1 产品决策：合格线分三层，不混为一谈

| 层 | 定义 | 失败后果 | 依据 |
|---|---|---|---|
| **L1 语体合格** | 简介长得像榜单书（口播腔、极简、有情绪标点） | 重生一次 + 留痕 | A 类证据最强，可立即落地 |
| **L2 结构合格** | 概念带得动长篇：可重复单元 / 限制阶梯 / 对手生态 / 终局方向 / 情感锚点 | 只降权不淘汰 | 字段已在，判官轴缺失；加轴有干涸风险 |
| **L3 品味合格** | 不出现让读者生理不适或审美崩坏的设定 | 需用户定标准 | 无客观判据，**必须由用户给标注** |

**产品原则**：L1 可以机器判，L2 需要标注数据，L3 必须人定。
不允许把 L3 交给模型自评——那正是现在「83.9 分但用户说很差」的来源。

### 1.2 明确不做的事

- **不把榜单简介原文贴进 prompt 当示例**。仓库定过案（2026-08-24）：
  prompt 里点名的示例句会被整批复印成句式骨架。蒸的是**技法形状**，不是词句。
- **不给新判据发杀权**。新检测器只挣「重生一次 + 留痕」。
- **不用框架自评当验收**。见 §三。

## 二、开发视角：调研与技术实验方案

### E0 · 修复榜单抓取（前置，不做实验做修复）

`fetch_fanqiehub_snapshot` 传的参数已不被 API 接受 → 200 + 空数组 → 静默失效。
修：去掉失效参数、改为拉全量后本地按 `分类/平台/榜单类型` 切分；
**加一条「空响应即报错」的守卫**——本仓库 2026-08-08 记过同款，现在又犯，
说明「静默空成功」是这个客户端的结构性弱点。
产出：2219 条落库，`fanqie_ranking_snapshots` 不再是空表。

### E1 · 语体迁移实验（最高置信度，先做）

**假设**：把简介的目标语体从「第三人称书面陈述」改为「对读者说话的口播腔」，
可显著提升读者点开欲。

- **自变量**：简介生成 prompt 的语体块（类别级描述，无例句）
- **因变量**：①「我/！/对白/【】/段落数」五项落入榜单分布的比例；②盲评点击率
- **设计**：同一批 premise（N≥12），A=现状 prompt，B=加语体块，各生成 3 次取中位
- **成功判据**：B 组五项指标中位全部进入榜单 p25–p75，且盲评（§三）胜率 ≥60%
- **风险**：口播腔可能与「轻松/严肃」基调冲突——需按基调分档，
  严肃题材不强推玩梗腔（对应调研到的「按语体反向触发」思路）

### E2 · 结构技法蒸馏（需要标注，第二步）

**目标**：从 2219 条榜单简介里蒸出**技法形状**，不是词表。

- **方法**：分题材分层抽样（37 分类 × 男/女频），每格抽 20 条，用 LLM 逐条抽取
  「这本书每章在干什么」（可重复单元）、「主角受什么限制」、「对手是谁」、
  「终局指向哪」四项**结构标注**
- **产出**：一张「题材 × 结构要素」矩阵 + 每格的形状描述（不含原句）
- **验证**：拿 32 条框架负样本走同一抽取流程，看哪些格子系统性为空
  ——**这才是「爆款该具备什么」的真答案**，而不是我拍脑袋列清单
- **风险**：LLM 抽取有主观性 → 每条抽两次，不一致的丢弃并记录一致率

### E3 · 判官加轴（依赖 E2 的标注，第三步）

E2 拿到标注后，把系统性缺失的维度做成判官轴。

- **落地形态**：**只进 composite 加权，不设硬地板**（与 protagonist_agency 同处理）
  ——改「谁赢」不改「谁出局」
- **理由**：config 里 2026-07-17 记着收紧概念层阈值 → 淘汰赛干涸 → 回落保底概念，
  比任何被拒候选都差
- **权重来源**：不拍脑袋。用 E2 标注做回归，看哪些维度与「榜单 vs 框架」的
  区分度最高，按区分度分配权重
- **干涸监控**：每次改权重后跑 N=10 本，记录淘汰赛干涸率；超过基线即回滚

### E4 · 极简化实验

**假设**：简介从 411 字压到榜单中位带（238–290 字）提升完读率。
与 E1 同批做，作为 B 组的附加约束，单独记录效应。

## 三、测试视角：对比验证方案

### T1 · 图灵式盲测（主验收，最硬）

**设计**：把 N 条框架简介与 N 条同题材榜单简介混合、去除书名与平台特征，
交给独立判官（**不同模型家族**，避免同源高估——仓库已实证同源高估 0.15–0.20）
做二选一「哪本更想点开」。

- **基线**：现状框架简介 vs 榜单简介的胜率（预期远低于 50%）
- **成功判据**：改造后胜率提升且**统计显著**（N≥60 对，二项检验 p<0.05）
- **为什么这个设计硬**：它不问「像不像榜单书」，直接问「读者会选哪本」，
  且正样本是真实爆款，天花板明确

### T2 · 分布落位回归（快速回归，每次改动都跑）

五项确定性指标对着 1139 本榜单分布查分位，落在 p5 或 p95 外即红。
**便宜、可自动化、每次提交都能跑**，用于防止改动把某一维度推向极端。

### T3 · 负样本复验（防止只学会「像」）

拿 32 条历史负样本作为固定回归集：改造后重新生成同题材简介，
必须在 T1 盲测里胜过它们自己的旧版本。防止指标好看但实际没变好。

### T4 · 干涸与成本监控

每轮实验记录：淘汰赛干涸率、平均 LLM 调用次数、构思耗时。
**任何一项相对基线恶化 >30% 即视为实验失败**，无论质量指标多好。

## 四、执行顺序与里程碑

| 阶段 | 内容 | 依赖 | 验收 |
|---|---|---|---|
| M0 | E0 修抓取 + T2 分布回归落地 | 无 | 2219 条落库；T2 可在 CI 跑 |
| M1 | E1 语体迁移 + E4 极简化 | M0 | T1 盲测胜率相对基线显著提升 |
| M2 | E2 结构蒸馏（37×2 分层标注） | M0 | 「题材×结构」矩阵 + 框架缺失格子清单 |
| M3 | E3 判官加轴（按 E2 区分度定权重） | M2 | T1 再次提升且 T4 无恶化 |
| M4 | L3 品味标准（需用户标注） | 用户输入 | 用户给出 20-30 条正负标注即可开工 |

**M1 之后就应该能看到简介层的明显变化**；M3 才动概念层。
先动简介是因为它证据最强、风险最低、见效最快。

---

## 五、需要用户提供的输入

1. **L3 品味标准**：现在唯一完全没有客观判据的一层。
   最小可用形态是 20–30 条标注（这条可以 / 这条不行 + 一句理由）。
   「舔东西恶心」是第一条，但一条撑不起判据。
2. **盲测的判官口径**：是「你会点开哪本」还是「哪本更可能爆」——两者会选出不同的东西。

---

## 六、本方案自身的风险

- **E2 的 LLM 标注可能不可靠**：用双次抽取+一致率兜底，一致率 <70% 则该维度不进 E3
- **榜单是当日快照**：热度是活数据，单日快照不可轻判固化（仓库 2026-08-08 定过案）。
  E2 抽样需跨多日重复，或明确标注「基于 2026-08-26 单日快照」
- **过拟合平台**：所有正样本来自番茄。若目标平台不同，结论未必迁移
