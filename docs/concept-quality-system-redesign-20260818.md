## 一、定罪：为什么坏设定能全链过审（内部取证结论）

这本书不是漏网，是**每一层杀权被逐次拆掉后的必然产物**：

| 环节 | 发生了什么 | 病根 |
|---|---|---|
| 原始池 | 井种子 freshness 7.0 恰踩 floor 7.0 过线 | 阈值边缘无缓冲 |
| 项目卡淘汰 | 全池唯一 freshness 9.0 的候选被 tone_fit=3.0 杀掉 | light 基调约束把新鲜候选过滤殆尽 |
| 决赛终审 | 8 个钩子判语清一色「套路熟」，冠军 freshness 4.0=恰好不触灾难线(4.0)，软失 2 根≤容忍 3 根 | **必出冠军**结构 + 2026-08-01 防误杀放宽留下的缝 |
| S1-S5 判卡 | s1(欲望防守型)+s2(赌注负和) 两票定罪→重展开一次→**revised 不复核**，终稿 wants 仍防守型 | 白判 |
| chief_editor | 抓到 8 条真矛盾（七代vs十八代/云梦泽溺死vs被井叫下去/血脉觉醒标签vs井口加护不可叠加血脉）| **advisory 零消费方**，coherence 0.62 落档无人读 |
| 确定性门 | debt_dominated=true 重生一次仍 true 照过；金手指极性门「看不到上升感」polish 一次照过 | 一次重生=免死金牌 |
| 意图对表 | 用户勾「升级流/血脉觉醒/爽文」，成品是还债文（升级引擎整个推迟到 renewal_sources）| **没有任何门做意图↔成品对表** |
| 表达层 | blurb 冠军被 canon 名 bug 误杀（取到废弃提案的「陆川」）→ 发货 v0 初稿；story_appeal 报告未持久化，验收证据链断 | 两个真 bug |

**三条缺失的判据轴确认为零杀权**：①设定自洽/世界事实一致性 ②创意新鲜度 vs 市场（参照集仅 4 条简介）③受众意图匹配。

## 二、市场基线：榜单设定的可执行判据（70 本在榜男频蒸馏）

数据：docs/research/board_blurb_sample_20260811.json（100 本实抓）中男频 70 本逐本细读 + 网络补充 10 本。

**三条结构性结论**：
1. **榜单从不解释来历，只解释规则**。穿越/重生/系统/全民降临/传承/民俗体系是读者已签的「免检通行证」；「全民降临」结构还顺带回答"为什么是主角"（人人都有，主角是例外变体）。真正被严格要求的是金手指的**输入-输出-限制**三件套，48/100 本简介含硬数字；限制条款是主发动机不是补丁。
2. **爽型在概念句就用词法结构宣告**：数值碾压(数字+倍率)/身份反差(两极具名)/规则玩弄(越X越Y悖论句)/见证打脸(第三方反应预演)。爽点从不自述。
3. **新鲜度合法区间=[0,1] 个新变量**：57% 是「熟套路+恰一处新变量」，形态固定为**熟机制×异场景嫁接**（乱世×外卖/领主×看广告/神豪×县城限制）；全新孤立概念在榜单上**不存在**（≤3%）。堆 ≥2 处新变量=认知过载（榜内反例《星路仙踪》热度垫底）。

**12 条判据**（概念层 C1-C6 一句话可判 / 展开层 E1-E6 需完整设定，每条 0/0.5/1，好坏例均为真实榜单书，全文见调研报告，判什么/怎么判已可直接进判官 prompt）：

- C1 通行证或自带规则（好例《每天六千万，只能在县城花》/坏例《星路仙踪》）
- C2 爽型三秒可指认 ∈ {数值碾压/身份反差/规则玩弄/见证打脸/囤积独活/收集成长}
- C3 反差两极具名（"表面是__实为__"两格都是具体身份词）
- C4 新变量计数∈[0,1] 且须为熟机制×异场景嫁接
- C5 行动循环可见（"主角每天/每次__获得__"可填）
- C6 冲突量级匹配题材（第一个冲突方须是题材级实体）
- E1 规则可演示性（第一章≤500字一个事件演示输入→输出差）
- E2 限制条款能生成 ≥3 个不同情节
- E3 悖论/复利引擎（越X越Y 或可叠加）
- E4 世界规则先行主角是例外（两句式改写：第一句不含主角）
- E5 第三方见证槽位具名
- E6 目标数值化/终点可见

《九姓井口只认我》按此表 **1.5/12**（榜单头部 8-11，零新变量执行流也有 5-7）。
E4 是「无法自圆其说」的形式化定义：写不出不含主角的世界规则句=凭空例外。

## 三、受众体系：现状与规则卡（受众线结论）

现状：**四套互不相通的画像体系**（构思/包装层 genre_persona+persona_click_judge、
章级 persona_simulator、审稿人格 critic_personas、平台档案 platform_profiles），
分辨率只到「频道」级；「进入门槛上限/首爽最迟章数/题材内容预期」三类字段任何一套都没有。
⚠️ 2026-08-01 产品裁决在案：完整画像表不得回灌构思 prompt（只许类别级预期）。

方案：`config/audience_rule_cards.yaml` 作 SSOT（频道×题材一张卡），字段：
target_reader 一句话/阅读场景/进入门槛上限(数值[待人类语料分位数标定])/必给爽点类型+
首爽最迟章数+压制耐受(A档1.5章)/绝对雷点(归确定性检测器)/题材内容预期(must_have)。
男频玄幻样卡与全部字段依据已在调研报告。消费方：判官角色扮演+章合同确定性字段+
检测器阈值+现有四套体系改为引用卡。头部突围书(tier: breakout)整卡豁免。

## 四、体系设计（对应用户四点要求）

### R1 完整筛选/评分/评判逻辑（分层，每层写明杀权）

```
原始池 → C层判官(C1-C6，评分+域多样性) → 项目卡展开
  → S层判卡(S1-S5 故事结构，已在跑) + E层编辑判官(E1-E6 设定质量)【新】
  → 世界事实一致性确定性对表【新】 → chief_editor 矛盾清单→director 必裁回执【新】
  → 意图对表门(default_tags/effect_skills ↔ 成品)【新】 → 表达层(现有+修bug)
```

杀权铁律不变：新判官零杀权，定罪→方向性重展开+复核；只有**全池不过线**时允许
「重开池」而不是硬选冠军（修「必出冠军」结构病）。

### R2 市场对比打分
- C/E 判据的好坏例锚定真实榜单书（判官读例证≠写手读例证，不违种词铁律；
  例证只进判官 prompt，绝不进生成 prompt）。
- 终审参照集从 4 条扩到按题材抽 12 条在榜简介（board_blurb_sample 已有数据）。
- freshness 修正：freshness 与 predictable 同病两读数合并占 1 个软失名额；
  raw 层与终审层分歧 ≥2.5 触发加采样复核（判官单票噪声中位 0.17 已定量）。

### R3 双视角 LLM 审核
- **读者角**：C2 爽型指认（判官必须写出爽型名，写不出=证据）+ persona_click（已有硬门）。
- **编辑角**：E1-E6 判官，逐条证据引文，2 票定罪交集，卷入方向性重展开。
- 两通道分开调用（注意力稀释教训：缺陷清单塞进评分调用=全员扣帽子）。

### R4 受众调研与设定方法
规则卡 SSOT + 注入点分配表（见三）。生成端只注入 target_reader 一句话+
genre_expectations.must_have 类别+首爽死线（尊重 2026-08-01 裁决）。

## 五、落地排期

P0（本轮）：
1. S 判卡 revised 复核（白判修复）
2. 世界事实一致性确定性对表（数字/世代/死亡地点/专名跨字段 diff，warn+一次定向修复）
3. chief_editor contradictions 结构化进 director prompt 必裁清单
4. E 层编辑判官（E1-E6）按 S 判卡同构接线（证据引文/2票/零杀权/重展开）
5. C 层判据并入 raw_idea_rank 判官 rubric（带榜单锚例）

P1：意图对表门；必出冠军→重开池；freshness 软失合并+跨层分歧复核；
blurb canon 名取终稿 bug；简介标签堆首行确定性打回；story_appeal 持久化修复。
P2：audience_rule_cards.yaml SSOT 落地+四套体系归一；进入门槛数值用
.distillation_private 分位数标定；金锚回放验收（榜单 12 锚 ≥8 分、井认主 ≤3 分）。
