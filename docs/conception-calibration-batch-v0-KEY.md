三类各自的用途：
- **金锚**（真实榜单书概念改写）：用户若普遍给「点」→ 口味与市场对齐，
  且这些条目成为用户口味的正锚点
- **灰锚**（刻意植入已定案缺陷）：用户若普遍给「不点」→ 缺陷清单被人工确认；
  若给「点」→ 该"缺陷"要重新审视（可能是我们误判）
- **生成组**（我按方法论 v2 规则手写）：用户判断直接成为蒸馏原料——
  哪条被点、为什么，就是下一版规则

## 评完之后怎么用

1. **金锚命中率**（用户给金锚的「点」率）→ 口味-市场对齐度
2. **灰锚淘汰率**（用户给灰锚的「不点」率）→ 缺陷清单的人工确认
3. **生成组得分** → 逐条理由蒸馏成规则；被点的条目反推共性，
   没被点的对照灰锚归因
4. 下一轮：规则更新 → 重新生成 → 混池排名向金锚收敛（设计方案 1.5 的达标线）
