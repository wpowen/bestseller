# 构思链路深度调研：91 次调用为什么产出平庸（2026-08-17）

> 触发：用户判定《丑石赖我求切开》（custom-xuanhuan-1786953202）的构思质量差。
> 该次构思耗时 42 分钟、91 次 LLM 调用、LLM 延迟合计约 34 分钟。
> 本文全部结论有真机证据，标注出处。

---

## 一、产物的可指认缺陷（不是"感觉差"，是能指出具体哪里差）

产物：鉴石学徒石枳能听见石头说话，三天后开石大典，丑石追着他回铺子。

| # | 缺陷 | 证据（产物原文） | 违反的既有标准 |
|---|---|---|---|
| 1 | **金手指自我稀释** | series_engine/story_motion：「每开一次石头，身边就多一个能听石的人」——主角唯一性能力**每次使用就扩散给别人**，「全砦只有他能听」第一卷就变假 | 爽文方法论 v2 分档表：B 档金手指规则最严，「新增设定即退订」；能力排他性是金手指的核心价值 |
| 2 | **欲望防守型，无上升感** | wants：「真正想保住的是那间属于自己的小铺」——保住、不被骂，全是防守 | `story_appeal.yaml` progression_cap 正是为此设的（无上升阶梯→封顶 66），但它只在**简介层**把关，构思层无此检查 |
| 3 | **赌注两头输，无赢的画面** | stakes：失败=学费利滚利铺面被收；**成功=听石藏不住，要么献祭要么沦为活鉴石器**——赢的后果也是灾难 | 读者三段律要求「账上留下能带走的东西」；两头输的结构让读者从第一章就看不到赢 |
| 4 | **字段退化** | logline == premise **逐字相同**；blurb 为空字符串 | 三个字段职责不同（一句话钩子/前提段落/营销简介），同文=某环节直接抄写而非生成 |
| 5 | **tags 与故事脱节** | tags 含「废柴逆袭/越阶战/王朝争锋/血脉觉醒」——故事里**一个都不存在**（是矿镇赌石+隐藏能力故事） | tags 是从题材包抄的，不是从故事长出来的；下游按 tags 路由（爽点档位/审计阈值）会全部错配 |

书名《丑石赖我求切开》与 one_liner（「谁能赌涨靠的不是眼力，是石头自己愿不愿意被看见」）本身是合格的——**概念种子不差，差在把种子长成故事的那几步**。

## 二、结构性根因（三条，按证据强度排序）

### 根因 A：全链同源——91 次调用全部是 MiniMax-M3，淘汰赛在选评委自己的口味

真机证据（llm_runs，本次构思全部 20 个环节）：

```
concept_tournament_raw_idea_pool    M3 ×4     ← 生成 36 个点子
concept_tournament_raw_idea_rank    M3 ×12    ← M3 给 M3 的点子排序
concept_tournament_candidate        M3 ×4     ← M3 展开成项目卡
concept_tournament_engine_kernel    M3 ×4     ← M3 写长篇发动机
concept_tournament_judge            M3 ×15    ← M3 评 M3
concept_tournament_finalist_judge   M3 ×4     ← 「独立复核」也是 M3
（其余 conception_* 全部 M3）
```

`config/concept_tournament.yaml` 注释明写「finalist_pool_size: 4 —— M3 初筛后
只送少量候选给**独立模型**复核」，但 `finalist_judge_model_key: minimax-m3`。
**注释承诺的跨家族复核从未存在。**

这为什么必然产出平庸：2026-08-17 刚定量过**同源高估**——M3 判官给 M3 产物
打分比人类基线高 2-4 倍（写手判官同族时判官读不出真实质量）。淘汰赛的机制
是「生成很多→评审淘汰」，当评审和生成是同一个模型时，**淘汰赛收敛到的不是
读者觉得好，是 M3 自己的口味中心**。91 次调用做的事等价于：让一个人从自己
写的 36 个点子里选出自己最喜欢的——选得再认真，也跳不出这个人的品味上限。

既有铁律早已写明却未在此执行：「达标证据须跨家族判官（同源高估 0.15-0.20）；
绝对分不可信只用相对盲评」——榜单对标执行了，概念淘汰赛从未执行。

### 根因 B：中间产物全部丢弃——不可审计、不可见

`conception_result.conception_log`（含点子池全文、每轮评分、淘汰理由）在
`web/server.py:3795` 被取出后**没有任何下游写入**（grep 全库为零）。
llm_runs 的 `request_payload_ref`/`response_payload_ref` 在构思调用上全为 NULL。

后果：
- **事后无法审计**哪一环丢了质量（本次调研只能从最终产物反推）
- **前端无从展示**「构思了什么」——用户问"到底构思了哪些内容看不到"，
  根子不是前端没做，是数据没存
- 36 个点子里可能有比胜出者好的，但没人知道

### 根因 C：高概念→下沉读者的翻译层缺失（已知遗留，从未排期）

记忆《概念淘汰赛(高概念先行)》定案时明写：「概念层均值回归→淘汰赛落地，
真机 A/B 大胜；**下一层=高概念→下沉读者翻译最后一公里**」。这一层至今没做。

本次产物正是这个缺口的样子：概念种子（石头有意愿、人替石头谈判）是有高概念
潜质的，但没有一步把它翻译成下沉读者的爽点语言——变成了氛围向、防守型、
两头输的文青故事。淘汰赛判官的 `engine_judge_floor` 检查结构轴，
**没有任何一轴检查「赢的画面在哪」**。

## 三、耗时的去向（顺带回答"42 分钟正常吗"）

不是卡死，是真在跑：

| 环节 | 次数 | 合计耗时 | 说明 |
|---|---|---|---|
| raw_idea_pool | 4 | **855s** | 每次生成 12 条完整 pitch（6000 token），单次约 3.5 分钟 |
| engine_kernel | 4 | 321s | 长篇发动机 JSON |
| raw_idea_rank | 12 | 289s | 每批 4 条排序 |
| conception_review | — | 258s | |

42 分钟里 LLM 延迟占 34 分钟。**慢的根源与质量的根源是同一个**：若判官
换成非同源模型且有判别力，池子可以砍半（36→18）而不损质量——现在的大池子
是在用数量补判别力的不足，而同源判官让这个补偿失效。

## 四、修复方案（按投入产出排序）

| 优先级 | 修复 | 改动量 | 预期 |
|---|---|---|---|
| **P0-A** | **判官换家族**：`judge_model_key` / `finalist_judge_model_key` 至少一个换成非 M3 家族（DeepSeek 系——记忆已证「DeepSeek 比 M3 听话」且已接入） | 配置 2 行 | 直接打断「自己评自己」；兑现配置注释本来的承诺 |
| **P0-B** | **conception_log 落盘**：写 `planning_artifact_versions`（artifact_type=conception_log）或 `output/<slug>/conception-log.json` | ~20 行 | 可审计 + 前端可见性的数据基础（用户两个诉求一次解决） |
| **P1-a** | **构思层确定性守卫**（audit_only，无杀权）：①金手指排他性（story_motion 不得描述能力扩散给他人）②wants 上升感（防守型词汇检测，复用 progression 词表）③字段退化（logline==premise 或 blurb 空即报） | ~80 行 | 本次 5 个缺陷里的 3 个可被确定性拦截 |
| **P1-b** | **高概念→下沉读者翻译层**：胜出概念后加一步「翻译判官」，判据用爽文方法论 v2 的三段律+分档表（赢的画面/上升感/排他金手指） | 新 prompt + 1 调用 | 补上已知遗留的最后一公里 |
| P2 | 池子砍半（36→18）+ rank 批次合并 | 配置 2 行 | 构思时间 42→约 25 分钟（在 P0-A 落地后才安全） |

### 铁律约束（都付过学费）

- 新守卫一律 **audit_only**（无杀权——门禁误杀已定案 4 次）
- prompt **不种词**（翻译判官判据只写结构：「赢落到有名字的人脸上」，
  不写打脸/逆袭 token）
- 改完必须**真机验证**（重启 worker + 跑一本构思，查 llm_runs 的 model_name
  确认判官真换了——配置写了不等于跑的是它，本项目栽过 6 次）

## 五、本次调研没做到的（诚实边界）

- **无法审计本次 36 个点子的池子质量**——中间产物没存（根因 B 的直接受害者）。
  「池子里本有更好的点子被同源判官埋没」是推断，不是实证；要实证需先落地 P0-B
  再跑一本书。
- 产物缺陷清单（第一节）是我按既有标准的判读，用户的"差"可能还包含
  我没捕捉的维度——欢迎补充，好翻译成守卫。
