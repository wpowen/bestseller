> 对应《构思榜单级改造方案》P0：把业务判据接进淘汰赛。
> 这份是**判据措辞本身**——它决定判官按什么判，正是上次教训的核心，

> 设计约束：①不种词（判据只写结构，不出现打脸/逆袭等 token）

## 一、故事层判据（六条，每条附判定问题与引文要求）

### S1 欲望攻性（wants 不得纯防守）

**判**：主角的核心欲望里，是否至少有一件是「要拿到此刻还不属于他的东西」？
纯粹「保住/守住/不被X」为防守型。

**引文要求**：逐字引出 wants 字段中表达"要得到什么"的句子；引不出即防守型。

**分档差**：A 档防守型直接不合格；B/C 档允许防守型为表层、但必须能引出
一条隐含的上升路径（例：守住铺子是为了→有资格参加大典）。

> 本次事故实例：「真正想保住的是那间属于自己的小铺」——引不出任何
> "要拿到"句 → S1 不过。

### S2 赌注有赢面（stakes 不得两头输）

**判**：如果主角赢了，他得到的东西是否**净为正**？
「成功的后果也是灾难」= 两头输结构。

**引文要求**：分别引出「赢了得到什么」与「赢了失去/招来什么」的原句，
两相对照后判净值。

> 事故实例：成功=「听石藏不住，要么献祭要么沦为活鉴石器」→ 净为负 → S2 不过。

### S3 金手指排他且不自泄（series_engine 不得描述能力扩散）

**判**：主角的核心能力在故事推进机制里是否保持排他？
「每使用一次，别人也获得/学会/继承」类的机制 = 自我稀释。

**引文要求**：引出 story_motion / series_engine 中描述能力归属变化的句子。

> 事故实例：「每开一次石头，身边就多一个能听石的人」→ S3 不过。

### S4 承诺可持续（promise_survival，沿用 rank 层已有措辞下沉到故事层）

**判**：核心机制在第一次完整展示后，能否持续产生**同类但不同**的
选择与场景？依赖一次性谜底、会耗尽的次数、无限重复同一动作的不算。

### S5 三秒可述（下沉读者翻译）

**判**：用一句不含任何生造名词的话，说出「主角接下来要赢什么」。
说不出，或必须先解释两个以上设定名词才能说清 → 不过。

**引文要求**：判官必须**写出这句话**（不是打分）——写不出即为证据。

### S6 字段完整性（确定性，不进判官——直接代码检查）

logline ≠ premise 逐字相同；blurb 非空；tags 中每个题材动作词
（如「逆袭」「越阶」）必须能在 premise/story_spine 中找到对应情节支撑，
找不到的 tag 记 TAG_UNGROUNDED（audit_only）。

## 二、输出格式（强制证据引文，复用已验证的双通道）

```json
{
  "s1_wants_aggression": {"pass": true, "quote": "逐字引文…", "note": "≤20字"},
  "s2_stakes_upside":    {"pass": false, "win_quote": "…", "cost_quote": "…"},
  "s3_exclusivity":      {"pass": false, "quote": "…"},
  "s4_promise_survival": {"pass": true,  "quote": "…"},
  "s5_three_second_pitch": {"pass": true, "pitch": "他要在开石大典上当众赢下全砦最狠的矿王"},
  "verdict": "revise|pass",
  "revise_direction": "只给方向不给措辞，≤40字"
}
```

判定规则：**两票定罪**——同一条判据两次独立调用都 fail 才算 fail
（判官噪声已定量，单票不可信）；任何 fail → verdict=revise，
把 revise_direction 回填给 candidate 重展开一次（最多 1 次，不无限循环）。

## 三、接线位置（一处，不散点）

`concept_tournament`：candidate 展开完成后、engine_kernel 之前，
对每张项目卡跑一次故事层审（S1-S5 判官 + S6 确定性）。
理由：在最贵的 engine_kernel（321s）之前拦住故事层跑偏，省时间也省 token；
engine_kernel 之后的产物由既有 engine_judge 继续负责结构轴。

## 四、验收（改完怎么证明有效）

1. 用本次事故的产物（石枳卡）回放：S1/S2/S3 三条必须 fail 并给出与
   本文一致的引文——判据能抓住已知坏例
2. 用校准批次 v0 的 6 条金锚回放：不得有金锚被判 revise 两次以上——
   判据不误杀好例（零冤案关）
3. 真机跑一本构思，llm_runs 里可见新判官调用与证据引文
