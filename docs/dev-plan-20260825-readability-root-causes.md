# 开发方案 · 「完全没有可读性」的上游根因（2026-08-25）

用户报：新书完全没有可读性，并问「创意竞赛是怎么审核通过的」。
框架自己的整书质量账本同意用户：7–11 章 **has_decision 0/5**、3/5 章
`functional_shape=flat`、`passed=false`。**正文层的门没有放行过这本书。**
放行发生在**概念层**，以及一条部署竞态。

---

## 已修

### A · 部署竞态：修复在磁盘上，进程里没有

容器 **10:23:54** 重启，`llm.py` / `golden_three_repair.py` /
`outline_llm_judge.py` 三个文件 **10:27:01** 才落盘——差 4 分钟。Python 不热加载，
运行中的进程导入的是旧模块，提交 `6632f9ae`「LLM 调用参数三处截断病」
**从头到尾没生效过**，而它修的正是输出被截断。

> 判据不是「文件里有没有」——src 是 bind mount，文件永远最新。
> 是 **文件 mtime vs 容器 StartedAt**。我第一次核查部署时查的是文件，结论错了。

**已修**：14:49 重启，复核全部文件 mtime 早于启动时间。

### B · `prompt_version` 写死，内容变了版本号不变

`concept_tournament.py` 里 `prompt_version="v2"` 是常量。当天 v2d prompt 重构
改了内容，`llm_runs` 里报的仍是 `v2`——「这本书用的新 prompt 还是旧 prompt」
在数据层查不出来，只能去比 mtime。**一个内容变了却不变的版本号比没有版本号更坏：
它让部署核查得出错误结论。**

**已修**：`prompt_version_stamp()` → `v2+<system+user 的 sha256 前 8 位>`。

### D · 追读性判官整段挂在写死的 `chapter_count >= 200` 后面

它评的六条轴 `renewability / escalation / anti_reset / coherence /
promise_survival / unit_density` **全是「读者要不要追下去」的判据**。
200 章的书在真机上几乎不存在 → 对所有正常书完全空转，`seriality_judge` 恒为 `{}`，
「评了没发现」与「压根没跑」不可区分。

**已修**：`seriality_stage_mode()` 三档 —— ≥`seriality_min_chapters`(200) 维持
既有行为（判官带杀权）；≥`seriality_advisory_min_chapters`(8) 跑判官但
**只留痕不否决**；更短则跳过。**三态都落回执。**

> 分档而不是一刀放开：config 里 2026-07-17 记着收紧概念层阈值 → 淘汰赛干涸 →
> 回落保底概念（比任何被拒候选都差）的教训。仓库对新检测器的规矩也是
> 「只挣重生和留痕，不发杀权」。

### E · 判官八条轴没有一条问「主角要不要做选择」

批准的故事引擎是纯被动循环（外部压力每轮施加、主角每轮应对）。
**正文 `has_decision 0/5` 是这个引擎的必然产物，不是写手写砸了。**

**已修**：新增 `protagonist_agency` 轴（prompt 用**类别式**描述、不给例句——
2026-08-24 定过案：prompt 里点名的示例句会被整批复印成句式骨架）。
权重 0.10，从「写得通不通顺」那几条各匀 0.025（它们此前合计 0.45 过重：
一个概念可以完全自洽、完全没意思）。合计仍为 1.000。
**刻意不进 `_FLOOR_AXIS_LABELS`**——只改排序不改淘汰，避免干涸。

### F · appeal 重生循环整包覆盖书名淘汰赛

书名有两个互不知情的选择子系统：

```
7757  书名淘汰赛      13 候选 + arena + 默认族降权 → 冠军《擀面胖婶的三息辨火》
8188  appeal 重生     premise/简介/标签/书名当一个包重生成 → 《逐出师门我颠大》
```

出厂书名**在淘汰赛回执里一次都没出现**。连带后果：淘汰赛的确定性门
（长度带/接地/查重）与默认族降权对出厂书名**全部失效**——当天早些时候为
债务族加的书名降权，保护的是被丢弃的那个冠军。

**已修**：`adjudicate_late_title()`，不重跑淘汰赛、不加 LLM 调用：挑战者过一遍
**同样的确定性门**再对决，干净就让它赢（appeal 本就是为点击率而跑），
带缺陷才退回冠军，**换不换都留痕**。

### G · 主角身份分裂：一本书出厂带两个名字

真机分布：身份骨架（book_spec/cast_spec/identity_manifest/快照/logline）＝**阿灶** 231 次；
读者可见（premise/synopsis/上架简介/world_spec.factions）＝**姜燎** 34 次。
正文里 **第 3 章起叙述改口再没改回**（1–2 章阿灶 26/53 次，3–11 章姜燎 18–28 次）——
第 3 章正是决定追读的位置。

- **G1a** 一致性检查此前只遍历结构化身份产物，真机上那五个全一致 → `issues: []`
  **零检出**；`premise`/`synopsis` 不在清单里。**已修**：纳入散文产物，做确定性
  在场核对（不重新解析人名——那条路依赖一个刻意 fail-closed 的抽取器）。
- **G1b** `_identity_mismatch_is_advisory` 把三份正文拼成 blob 判任意命中，
  logline 命中即放行。拼接粒度看得见「0/3」，看不见「1/3 vs 2/3」。
  **已修**：逐产物计数，规范名在非空产物中不足半数即判分裂；
  没提任何人名的产物不计为反对票（避免误判）。
- **G1c** `advisory_codes` 此前**无条件**计算，与 `issues: []` 同时出现，
  读起来像「抓到了但放行」，实际是「压根没抓到」。**我据此得出过错误结论。**
  **已修**：只在真有同码 issue 时才标 advisory。

## 查过之后**撤回**的一条

### C · ~~软缺计数不看差距大小~~ —— 不成立

原判断：`freshness 4.5 / genre_fidelity 4.5` 被 `soft_miss_allowance: 3` 放行，
是因为软缺计数把「差 0.1」和「差 2.5」同记 1 次。

**撤回理由**：`test_hook_floor_can_allow_three_non_catastrophic_soft_misses`
用 `freshness 4 / click 5 / predictable 6.5`（差 2.0/2.0/1.0）**刻意断言应当通过**。
真机那本是 4.5/4.5/6.5，结构完全一样。按仓库自己的校准，这个候选本来就该过。
**地板不是缺陷**；没有数据就动它，正是 config 注释里 2026-07-17 那个错误
（收紧 → 干涸 → 回落保底概念）。

真正的缺口是 D 与 E，两条都是**加测量**而不是**收阈值**。

## 验收口径

| 项 | 硬指标 |
|---|---|
| 部署 | 全部 `src/**.py` 的 mtime 早于容器 `StartedAt` |
| B | `llm_runs.prompt_version` 形如 `v2+<8位指纹>`，改 prompt 后指纹变化 |
| D | `seriality_stage` 回执恒非空；12 章书 `mode=advisory` 且不产生否决 |
| E | 候选记录里有 `judge_protagonist_agency`；权重合计 1.000；该轴无硬地板 |
| F | `title_tournament.late_adjudication` 回执恒非空；出厂书名 ∈ {冠军, 过门的挑战者} |
| G | 分裂书判 `advisory=False`；`advisory_codes` 非空 ⇒ 必有同码 issue |

**不算数的**：某一本书碰巧干净。只有**回执链**和**跨书重复**才算证据。
