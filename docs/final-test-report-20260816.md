## 一、结论摘要

**核心成果**：句法注水（时刻切片）闭环建成并在 **n=50 真机尺度验证成立**——
新书患病章 **1/50**，对照上一本 **17/50**；病灶出生地（扩写轮）从
**+6.8/次、62% 恶化** 变为 **Δ+0.00**。

**本轮共定罪并修复 10 个缺陷**，其中 **6 个只有靠真跑一本书才会暴露**
（9667 个单测全绿也测不出来）。

**尚未解决**：修复端对重症章只治愈 6/17（预防端已解决），根因是 DITTO
自我强化，真解需「从场景卡再生」；爽点结算与终章闭合仍无确定性尺子。

同代码采样 引文 {8.63, 4.42} vs 不引文 {0.29, 2.20, 2.35}/千字。
已写入代码注释与单测，防止重试。

## 六、运维教训

- **`pkill` 硬杀 Docker Desktop 会让全栈容器消失**（数据卷完好，
  `docker compose up -d` 可完整恢复）。改用 `osascript quit` 并耐心等待。
- **跑书期间不要重启容器**：worker 被杀 → 自愈把孤儿 run 收尸 → 书死在
  planning。本轮因此损失一次构思。
- `data/` 此前不是活挂载，改检测器规则需 rebuild；已在 compose override 补上。
