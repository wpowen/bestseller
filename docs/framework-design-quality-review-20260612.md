# 框架故事设计能力体检报告（基于《神仙都是我招的》v3 全程跟踪）

> 2026-06-12 · 证据来源：zhaoshen-hr-v3-1781180702 从 premise 到正文的全链路人工跟踪
> 结论先行：框架的设计管线是 premise→book/world/cast→十卷规划→分批章纲→物化→正文；
> **吸收主题的能力强，保持身份与连续性的能力差**；质量随管线深度衰减，章纲批次层是重灾区。

## 1. 分层质量评估

| 层 | 评级 | 证据 |
|---|---|---|
| world_spec 世界观 | **B+** | 信力经济学/显圣税/封印=岗位/司衡全部吸收进世界规则；premise 公理层利用率高 |
| cast_spec 人物 | **C** | 机制吸收深（离职赠礼/守岗消散/37人名单全进了人物弧线）；但 generate_character_names 名字池**覆盖 premise 显式名册**（孟拂→周澈、老金→九嶷），IP角色（杨戬/八戒/悟空/老君/哪吒）整层丢失，需人工 roster 补丁 |
| volume_plan 十卷规划 | **B-** | 主题脊柱意外地强（"代班者的退场体面""撤编的伦理""空椅不坐"，卷10功德余额=0 的收束有水准）；但①每卷形态单调（卷3/4/5/6/8/9全是"签下第N位神明三选一"配额结构，500章必然审美疲劳）②premise 中后期资产利用率断崖：三方格局/灵山香火宝/武斗轨/大IP/历劫制**全部没有进卷计划**③reader_hook_to_next 十卷全是同一句模板话（死字段） |

| 闸门体系 | **C** | 能抓真问题（causality/商业就绪/身份契约都抓对了），但规划层闸门**只拦不修**：hook闸门模板自伤、causality拦死自愈循环、商业闸门无修复通道——验收契约断裂在规划层重演 |
| 修复层 | **C** | json-repair/身份锁/标题去重等机械修复有效；语义级修复（剧情重复/字段缺失）为零，全靠人工 |

## 2. 根因（架构级，非提示词级）

1. **批次间无叙事台账**：批次N看不到"前文已消耗的事件/冲突/兑现"，每批都从卷目标重新推演→同弧线反复重写。标题去重是在症状层打补丁。
2. **字段契约后置**：opening_situation/参与者/因果契约在批次验收时不查，到物化和商业闸门才爆——生产与验收隔了两层。
3. **premise→cast 身份直通断裂**：名字池先于 premise 名册，显式人物名单被覆盖（机制吸收、名字丢弃）。
4. **premise 资产利用率随深度衰减**：world_spec 几乎全吸收→volume_plan 吸收主题丢资产→章纲批次只看卷目标局部窗口，中后期资产（IP/组织线/威胁阶梯/历劫表）彻底蒸发。
5. **死字段用模板兜底**：reader_hook_to_next 十卷同一句——兜底掩盖了"模型没产出"的信号。
6. **卷形态无多样性约束**："签神配额"结构连续六卷，没有 arc-type 轮换检查。
7. **黄金三章无特殊处理**：用通用批次生成器写全书最重要的三章，线性履历式开局是必然产物。

## 4. 对照实验结论（人工 vs 框架）

本书当前执行 = 框架产出 + 人工修复（hook种子/cast roster/字段补全/整卷重排/黄金三章重写）。纯框架路径在 hook 闸门即死；放行后产出的是"同一个故事讲六遍"的卷一。**人工重排部分（三案件+环环相扣+冷开场黄金三章）就是 P0-P2 修完后框架应该自动达到的基线**——本文档的改进项以此为验收标准。
