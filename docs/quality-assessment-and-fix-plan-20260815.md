## 一、中立评价（综合四角色 + 量化）

### 1.1 结论一句话

**概念与开篇达到出版水位（开篇效率一维超人类基线），但被三层病拖死：句法模板复读（28%章）、对话/事件双饥饿（全书）、跨章事实漂移——现状上架是扑街书，且主动匹配 2026 番茄 AI 处置画像。**

### 1.4 根因链（DB 取证还原）

```
写手首稿字数不达标（欠产或超产）
  → 补字数扩写轮：模型用「时刻切片」注水（字数最便宜的写法）
      ch38: v1=4命中/1198字 → v2=41命中/4403字
  → editor 看见病文 → 模仿并放大（ch25: 12→31）
  → 章级选稿 settled_at_closure：不比质量，谁是最后的稿谁发布
  → 全管线无一把尺子能看见句法模板（deslop 0 调用）
  → 病稿出厂
```

三条旧案的合流：「注水在保护自己」(08-06) + 「选优只看下限致发布最差稿」(07-26) + 「反AI味死代码」(08-15上午)。

## 二、产品方案（PRD）

### 2.1 目标与非目标

**本轮目标（P0，生产线止血）**：任何一本新书，句法模板病章率从 28% 压到 <5%，且不引入新的阻断风险。

**非目标**：C 类内容设计病（对话饥饿/爽点结算/事实漂移/结局）——它们是下一轮管线设计工作，混进本轮会稀释验证。

### 2.2 需求（按优先级）

**R1 句法模板检测器（确定性，新增）**
- 检测三族：时刻切片（「的那一瞬」「N里」接续）、原样复读句（≥8字句子章内≥3次）、破折号密度
- 阈值用人类语料分位数校准（.distillation_private，94.7万章），p99 为红线
- min_chars 护栏（≥600字才计），速率制不是计数制
- **铁律：只挣重生和留痕，无杀权**（不产 blocks_write，不产 production_block）

**R2 扩写轮 prompt 加疫苗**
- 补字数/扩写路径的 prompt 显式禁止时刻切片注水，给出正确的扩写方向（加事件/加对话，不加切片）
- 这是病的出生地（+6.8/轮，62% 恶化），prompt 不改，检测器就是在给无限重写循环喂料

**R3 章级选稿引入质量信号**
- promotion 决策从 settled_at_closure 升级为：先按检测器信号过滤（病稿降权），再按字数带就近
- 修复形状按既有 scene 级修复（is_current 语义）等价迁移到 chapter_draft_versions
- 兜底：全部候选都病时选最轻的，绝不空手（复用「无current回退提升最新草稿」教训）

**R4 重写触发闭环**
- 检测器红 → 触发一次定向重写（带具体病句引文），重写 prompt 不粘贴病文全文（防 editor 模仿放大，B4）
- 预算有界：每章最多 2 次定向重写，用尽则带病发布并留痕（防无限循环烧token，07-25教训）

### 2.3 成功判据（验收锚点）

1. ch25 原文过检测器 = 红；ch1 原文 = 绿（ground truth）
2. 人类语料抽样 200 章过检测器，误报率 <2%
3. 真机端到端：真书跑一章欠产场景，扩写轮产物病密度不高于首稿
4. 检测器在真机留痕（quality_report 有记录）且全程无一次 blocks_write

## 三、开发方案（已实现，2026-08-15）

### 3.0 关键更正（接线分析推翻一项前提）

**deslop 不是死代码**：本书实际跑了 84 次（全库 5609 次）。「0 调用」是查询盲区——deslop 用
`logical_role="writer"` + `prompt_version="deslop_revise"`，按 logical_role 分组永远看不见。
真病因：**时刻切片不在检测器任何 category 里**（ch25 命中 43 处、detector 报 0）→ findings
从不提它 → `_badness()` 对它无感 → 保留全部病的重写稿被 keep-better 照收。84 次 deslop
治的全是它看得见的病。

### 3.1 改动集（7 处）

| # | 文件 | 改动 |

### 3.2 外部调研落进设计的三件事

- **not-x-but-y-bench 方法论**（构式家族正则+千字率+人类分位数）：与本设计同构，人类基线 0.065/千字符先例

### 4.0.1 迭代中被真机证伪／定罪的四件事

1. **给写手引用病句 = 种词**：同代码 A/B（ch25，每千字）引文 {8.63, 4.42} vs 不引文 {0.29, 2.20, 2.35}。判官侧「逐项证据引文」有效，生成端相反。已改为「类别+改法」零 token，并加单测锁死。
2. **写手收到的指令本身是坏的**：形状是 `「<病句>」：<why[:60]>` —— 逐字引用病句 + why 里带病句范例 + 改法被 `[:60]` 截断丢失，等于「给它看模板、不告诉它怎么改」。修后同三章：ch7 4.30→1.86、ch8 6.32→3.53、ch24 6.24→3.90。
3. **轮数不是杠杆**：rounds=4 与 rounds=2 无稳定差异（ch24 6.86 vs 3.90），方差主导。
4. **注水第三次自保**：ch26 输入输出逐字节相同 —— 不是没改，是并链后 2773→1733 字被长度闸判「太短」`break` 扔掉。修为「留下短而干净的稿，下一轮只补长度（同一条疫苗话术）」，ch26 从纹丝不动变为 5.35→2.10。
5. **长度有两把尺子**：deslop 用 `len()`（含标点/空格/markdown）比生产 LENGTH 门的 `count_zh_chars` 虚高 ~15%，此循环认为够长的稿下游照样 LENGTH_UNDER。统一后字数守约 15/17→17/17。
