# novel-generator Skill 深度分析与融合方案

**日期**: 2026-08-17
**分析对象**: `qwen-agent/.../novel-generator 2/`（kimo, v1.0.3, MIT-0, 9 文件 / 68KB）
**对照对象**: 本仓库 bestseller（660 个 py 模块 / 490 个 service / Postgres 落库 / 门禁-判官-检测器三层）

---

## 0. 结论先行

这不是一个"框架"，是**一张写给单个 Agent 的写作提纲**。它把长篇小说生成压缩成四步（提示词补全 → 大纲 → 逐章 → 记忆回写），全部靠祈使句驱动，没有任何可证伪的量具。

在能力维度上它是我们的**真子集**，只有三处例外。因此融合的价值不在"抄功能"，而在两件事：

1. **抄形状**——它的 `.learnings/` 是人可读、可编辑、生成前必读的文件；我们的同类事实埋在 Postgres JSONB 里，而唯一的 markdown 导出（`story_bible_export.py`）文件头明确写着"writer pipeline never reads from these files"。
2. **当镜子**——它所有的质量手段，恰好是我们已经用真机数据证伪过的那些做法（固定爽点公式、范文示例、自检清单）。它把我们的旧病以最纯粹的形态陈列了一遍。

一句话：**它是提纲，我们是流水线；它唯一强过我们的地方是"人能一眼看懂这本书现在是什么状态"。**

## 1. 可以借鉴的点（按价值排序，附我们的缺口取证）

### A. 失败教训的「前馈」闭环 —— 最高价值，且我们是真空

skill 的 `ERRORS.md` 字段设计是：问题描述 / 影响范围 / 修正方案 / **预防措施**。最后一栏是关键——失败不只是被修，还被沉淀成一条"下次别这样"，且下一章生成前必读。

我们的取证：

| 我们的同类模块 | 实际接线 | 是否覆盖长篇章节路径 |
|---|---|---|
| `forbidden_terms_learner.py` | 只被 `cli/main.py` 和 `fanqie_short_export.py` 引用 | ❌ 只在番茄**短篇**导出路径 |
| `retry_ledger.py` | 只被 `worker/tasks.py` 引用 | ❌ 管的是 token 预算，不是质量 |
| `degradation_tracker.py` | 只被 `conception.py` 引用 | ❌ 只覆盖构思阶段 |
| `rejection_repair_playbook` | quality_levers 内部 | ⚠️ 修当前章，不前馈下一章 |

**长篇正文路径上不存在任何"上一章为什么被毙 → 下一章生成时知道"的通道。** 这与记忆里反复定案的病同形：同一缺陷（母题族饱和）跨书复发 4 次，因为我们没有 per-book 病历。

这是典型的"能力长在我们的书不走的那条路上"。

### B. 章节「自述元数据」= 可证伪的回执

skill 每章头部要求模型自报：本章概要 / 本章爽点 / 情绪曲线 / **涉及角色** / **涉及地点**，章末自报钩子与下章预告。

它自己只是拿来当模板。但真正的价值在于：**这是模型对自己产出的一份可被确定性代码核对的自述。**

- 自报"涉及角色 = [A, B]" → 用确定性代码核对正文里 A、B 是否真的有台词/动作
- 自报"本章爽点 = 炼丹碾压" → 核对该爽点是否有落点，还是只在自述里存在
- 自报"涉及地点" → 直接喂给连贯性核对

这正是我们已验证有效的唯一稳定模式（判官先行那一轮：`goal_quote` 逐字引文核对是全场唯一没冤案的通道）。

我们当前的 `chapter_acceptance_contract` 是**下发**给写手的契约，缺一份**回执**。加回执的边际成本接近零，但让"契约声称的"和"正文实际的"之间第一次可以做差。

### C. 伏笔的「数值不变式」

skill 给了两条硬指标：状态为"伏笔待回收"的条目 **≤ 5 条**；**没有超过 30 章仍未回收**的伏笔。

我们的取证：`foreshadowing.py` 算 `balance_score` / `dead_zone_chapters` / `orphan_clue_codes`（按每条线索自己的 `expected_payoff_by_chapter_number` 判孤儿）；`payoff_ledger_gate.py` 只有 `max_hook_only_ratio = 4.0`。

缺的是**「在飞伏笔存量」**这个全局量——它直接对应读者体感：在飞的坑超过某个数，读者就记不住了，记不住就弃书。按每条线索单独判孤儿，抓不到"每条都没超期、但同时挂着 14 个坑"这种情况。

数值本身不要照抄——我们有 `.distillation_private` 的 94.7 万篇真实出版章，人类分位数校准这条路已经跑通过（破折号那次）。先用 5/30 当占位，再标定。

### D. Mermaid 图解产物

我们全库只有两处 `mermaid`（`framework_self_closure.py` / `benchmark_capability_audit.py`），都是框架自检用。story-bible 导出是纯 markdown 表格。

人物关系图 / 势力分布 / 等级体系 / 剧情时间线用 mermaid 出图，成本几乎为零，纯导出侧、零生产风险，但对"我作为作者能不能一眼看出这本书哪里塌了"的提升是量级的。这是本次分析里**唯一一条可以直接抄、不用改造**的。

### E. 交付语义收敛

skill 用了整整一节强调：交付路径**只**列本轮产出的正文章节，记忆/大纲/图解一律不进列表。

看着琐碎，但对应我们一个真实痛点（记忆已定案）：盖戳数与覆盖率对不上，两个口径答的是两个问题。一份"本轮真正产出了什么正文"的收口清单，是有用的收敛。

## 2. 可以修改的点（引入前必须改造，否则是回归）

### A. 爽文节奏公式 —— 危险，必须从「规定量」降级为「观测量」

```
每 1-2 章：小打脸    每 3-5 章：中打脸
每 8-12 章：大高潮   每 15-20 章：卷终决战
```

我们已有实证：**碾压密度是属性不是质量标记**（爽文断链那一轮的证伪结论）。把这类固定节拍写进生成端契约，正是跨书同质化的生成端来源——和"天道泛滥 = 品类叙事模板层母题默认"完全同形。

而且我们已有更好的东西：`config/webnovel_method_cards.yaml` 的 `emotion_genre_map`（9 种 target_emotion × plot_modes）+ 13 式章末钩子受控枚举，比"十大套路"精细一个量级，且**先定情绪再定冲突**的顺序是对的。

**处置**：这份公式只能进**审计侧**（"这本书的爽点间距分布是什么"），绝不进生成侧。

### B. `examples.md` 是种词炸弹 —— 禁止整段进 prompt

林凡 / 赵天罡 / 苏婉儿 / 青云宗 / 炼丹系统——这正是我们已定案的 baked-names 跨书同质化源（主角恒陆沉那一案）。

更严重的是句法层面：seed 锚定那一轮的定量结论是**旧措辞令句法骨架被复印 24/24，改成「只取方向、禁沿用句式」后降到 0/12**。任何整段范文进 prompt，等于发一份句法模板让模型复印。

**处置**：若要吸收，只能走我们已有的 `prose-craft-distill` 路子——蒸**技法骨架**、合成跨题材例、禁带具体名词。

### C. 三处自检 checklist 全部无效

skill 有三份 `- [ ]` 清单（提示词质量检查 / 章节连贯性检查 / 质量检查），都是**生成者自己勾自己**。

我们的实证：清单式 prompt 产矛盾文案（四条倒计时互斥、35 岁 vs 三十年，对每把词表尺子都不可见）；缺陷清单塞进评分调用 = 注意力稀释、全员扣帽子。

**处置**：改造为独立判官通道 + 逐项证据引文 + 2 票定罪（我们已有这条流水线，46 次在榜书判定零冤案）。

### D. 严重度自评（low/medium/high/critical）没有刻度

同源高估问题我们已量化：写手与判官同为 MiniMax-M3 时，自家判官高估 2-4 倍。让写自己的模型评自己失败的严重度，读数没有参照系。

**处置**：严重度必须由确定性检测器的人类语料分位数给出，或跨家族判官。

### E. 「每章 2000-3000 字」全局常量

与 `writer-underproduces-length-contract` 的定案冲突：字数必须是**章合同锚**（同源字数带，std 从 679 降到 241），不是全局常量；而且抬可见目标已被 C 臂强证伪。

### F. 「不要让反派太愚蠢」这类否定式指令

已定案：**否定式指令点名母题词 = 种词**（债 / 账 / 寿 / 记忆全禁）。"反派"、"愚蠢"同理会把注意力吸过去。

### G. 宿主协议噪声占 SKILL.md 约 1/4

产物目录 / 交付路径格式 / 千问 AI 打标合规，与创作质量零关系。但它本身是一条反面教训——真正谈"怎么写好"的内容只剩约 60%。这与我们 `prose-prompt-diet` 那一轮的病同形：prompt 被非创作内容挤占。

## 3. 可以完善的点（它缺、我们也缺，或我们缺得更隐蔽）

### A. 记忆只增不减 —— 对 1000-2000 章目标是硬约束

`CHARACTERS.md` 每章追加、`PLOT_POINTS.md` 每章追加，50 章后必然超上下文。skill 完全没有**分层与遗忘**（近期全量 / 远期摘要 / 按需检索）。

我们有 `memory_recall.py` 的衰减调度（`[+3, +10, +30, +80]`），但那是"角色记忆节拍"这个叙事功能，不是**上下文预算管理**。我们的目标是 1000-2000 章，这条必须自己解决，skill 提供不了答案，只提供了警示。

### B. 记忆是派生物，但没有反向校验

写入时机是"该章生成完毕后立即写入"。如果正文写错了（角色状态、地点），记忆会把错误**固化成事实源**，后续章节据此继续错。缺"记忆 ← 从成稿抽取"的核对方向。

我们有 `continuity_ledger_writer.py`，同样要问它是从**成稿**抽还是从**计划**抄——从计划抄的话，同病。

### C. 全书节奏表只到 80 章

`plot-structures.md` 的宏观节奏表止于"终章卷（71-80章）"。长度可扩展性为零。

### D. 无跨书维度

不查重、不比对市场、不看榜单、无读者留存概念。我们的 `market_validation` / `benchmark_arena` / `reader_persona` 是护城河，不该被这类 skill 的简洁性诱惑而退化。

### E. 无成本与失败预算

对照 `retry_ledger.py` 的诞生原因（一次门禁自恢复无限循环烧 88 万 token）：skill 里没有任何一处提到"重试几次放弃"。

### F. 只有作者视角，没有读者视角

爽点设计全是"怎么装逼打脸"，没有一句"读者在第几章会弃书"。我们的三段律（赢要落到有名字的人脸上 / 被具体的人看见 / 账上留能带走的东西）是读者侧共识，skill 里完全没有对应物。

### P0-2 设计要点（章节自述回执）

- 写手在正文外附一份结构化 self-report：`{summary, payoff_kind, emotion_curve, characters[], locations[], hook}`
- 新增确定性核对器：`characters[]` 里每个名字必须在正文出现且有动作/台词；`locations[]` 必须在正文出现；`hook` 必须落在末段
- **只发 warn、只留痕，不给杀权**——遵守"新检测器只挣重生和留痕"这条已定案的规矩（门禁自伤那一轮 4 处误杀全是我给新检测器发了杀权）
- 落库到 quality_report，跑满一本 50 章书之后再看要不要升格

### P0-3 设计要点（伏笔在飞存量）

- `foreshadowing.py` 增加 `open_clue_count` 与 `max_clue_age_chapters` 两个观测量
- 阈值先用 5 / 30 占位，标注为"未标定"
- 用 `.distillation_private` 语料跑人类分位数标定后再落阈值（这条路走通过）
- 先 `audit_only`

### P1-4 设计要点（教训前馈）—— 最容易做坏的一条

这是价值最高也最危险的一条。做错了就是又一份"缺陷清单塞进生成调用"，我们已经量过后果：注意力稀释、全员扣帽子。

约束条件：

1. **必须是证据引文，不是规则条目** —— 前馈的是"第 12 章你写了这句：『……』，判官定罪为切片注水"，不是"不要写切片注水"
2. **必须有硬上限** —— 每次注入 ≤ 3 条，超出的按最近复发排序淘汰
3. **必须有退休机制** —— 连续 2 章未复发即退出，否则单调增长必然重演清单病
4. **必须落在写手 prompt，不是判官 prompt** —— 判官侧塞清单已被证伪
5. **必须有 A/B** —— 走 L2 git-stash 归因 + L3 真机 live 栈，遵守 `dev-verification-standard`

## 5. 好 / 差的显式判断

**好的部分**

- 记忆系统的**形状**：读在前、写在后、按类分文件、生成前必读——这个循环本身是对的
- `ERRORS.md` 的字段设计（影响范围 / 修正方案 / **预防措施**）——最后一栏是精髓
- 伏笔的**数值不变式**（≤5 在飞、无 >30 章未回收）——把体感变成了可测量
- 章节自述元数据——无意中提供了可证伪的回执面
- 交付语义收敛——只交付正文
- 篇幅纪律：68KB 就能跑起来

**差的部分**

- **所有质量手段都是祈使句**："要有爽点"、"对话要有个性"、"反派不要太蠢"——没有一个可证伪的量具。这是它与我们的根本分野：我们花了几十轮才学会"不可测量的规则等于没有规则"
- **套路库是内容级模板而非机制级语法**：十大套路直接规定"退婚打脸"、"拍卖会装逼"，注定跨书同质化。我们的 `motif_library` / `story_design_grammars` 走的是机制级抽象，方向正确
- **自评闭环**：生成者 = 检查者 = 严重度评定者，三位一体，读数无参照系
- **不可扩展**：记忆单调增长、节奏表止于 80 章
- **宿主协议噪声**占据 1/4 篇幅

## 6. 整合结论

不要把这个 skill 当作"要融合的框架"，它没有可融合的架构。正确的用法是从中提取 **4 条具体改动**接进我们已有的管线：

```
P0-1  story_bible_export.py        → 加 mermaid 四图（人物关系/势力/等级/时间线）
P0-2  chapter_acceptance_contract  → 加自述回执 + 确定性核对器（warn only）
P0-3  foreshadowing.py             → 加在飞存量 + 最大龄期（audit_only，待语料标定）
P1-4  chapter_generation_input     → 教训前馈通道（≤3 条证据引文 + 退休机制 + A/B）
```

其余全部**明确拒绝**，理由都是我们已经用真机数据付过学费的：固定节奏公式制造同质化、范文示例复印句法骨架、自检清单稀释注意力、全局字数常量与章合同冲突。

它对我们最大的贡献其实是**第 1 节 A 条揭示的真空**——长篇正文路径上，没有任何机制让这本书记住自己犯过的错。这个洞是它照出来的，不是它填上的。
