## 一、爽文的定义（一句话 + 一条通用律）

### 1.1 定义

> **爽文不是题材，是一根正交轴：`爽文 = 题材 × 爽度档位`。**

问「这本书是不是爽文」是问错了问题——正确的问法是
**「这本书在爽度轴上处于哪一档，以及它有没有达到那一档的标准」**。

同一玄幻可写成爽文或正剧；同一喜剧可以是爽文喜剧（打脸解气）或治愈喜剧。
所以判断分两步：**先定档，再按档核对**（见第四节）。

### 1.2 通用律（三档读者独立盲评后的唯一共识）

三档读者在几乎所有问题上意见相反，只有这一条一致：

> **「赢」必须 ①落到一个具体的人脸上 ②被具体的人看见
> ③在主角账上留下一笔能带走的东西。**

三件缺任何一件，文笔再好都会被判"这章不爽"。

| 通用律 | 可判定检查 | 反例（读者原话） |
|---|---|---|
| 落到具体的人 | 有名字的对手，且**本章之前**具体得罪/轻视/阻挠过主角 | 「'某个势力'不算」 |
| 被具体的人看见 | 至少一个证人的**称呼/动作/待遇**发生具体变化 | 「『众人震惊』四个字不算变化」 |
| 账上留一笔 | 章末主角多了一样**能说出名字、下一章还能用**的东西 | 「爽了三秒，账上是零」 |

### 1.3 代价与爽感（澄清常见误解）

三档一致：**代价在满足两个条件时增强爽感**——①主角**知情下主动选择**
②**具体可量化**且**后续被记住**。凭空倒霉、被设定坑、为"显得不无脑"
而安排的失败，三档一致减分。

> B 档原话：「没有代价的爽是塑料的。」　A 档原话：「我不是来看他倒霉的。」

**爽值 ≈ (压抑强度 × 反转速度) ÷ 逻辑漏洞。**
压抑是**分子**不是分母——读者受不了的不是「有憋屈」，
而是**主角被低层级龙套长期压制**。

## 二、平台实证（v1 此处为「待补」，现补齐）

### 2.1 四条元结论

**① 「爽文」不是平台标签。**
起点 / QQ阅读 / 掌阅 / 番茄的官方标签体系里**都没有这个 token**：

| 平台 | 实际用词 |
|---|---|
| 番茄 | 「无脑爽」 |
| 起点 | 拆成流派词：升级流 / 扮猪吃虎 / 杀伐果断 |
| 掌阅·QQ | 按题材分类，爽感不单列 |

只认「爽文」二字去匹配必然 0 命中——与本项目「『升级』token 错配仙侠 pack」同病。
**任何按标签识别爽文的方案，起点就是错的。**

**② 越精确的数字，来源越不可靠。**
官方只给指标定义（追更人数 / 万字读完率 / 千字留存率），**不给阈值**。
所有流传的「每 500–800 字一个爽点」溯源到疑似 AI 生成的 SEO 站。
本项目 config 里番茄那条正来自此链，已标注为待验证假设并禁止据此建门禁。

**唯一多源一致的是章级口径**（中国作家网番茄扫文报告等）：

> **每章 ≥1 个小爽点；每 2–5 章 1 个中爽点。**

已知平台口径（在库）：`platform_profiles.yaml:231` 番茄「每章必须 ≥1 个明确爽点」；
`:189` 纵横「每 1–2 章一次可感爽点」。

**③ 头部与腰部生态位相反。**
番茄 Top4 里两本把「不爽文」写进标签——《十日终焉》逐字写着
「不后宫、不套路、不无敌、不系统、不无脑、不爽文」。
**爽文标准适用于腰部走量，不适用于头部突围。** 判断前必须先问「这本书要打哪个位」。

**④ 起点「本章说」是唯一公开可得的段落级爽点 ground truth**
（日均 15 万条段评）。要把判据校准到真读者，这是唯一现成的标注源。

## 三、被真机数据证伪的假设（不许再用）

语料量化（2114 本，含长度配平与逐句精度核验）推翻四条直觉：

| 假设 | 实测 | 结论 |
|---|---|---|
| 爽文对话更多 | **AUC 0.501**，两组中位都 0.22–0.25 | **零区分力**。对话饥饿是可读性问题，与爽文无关 |
| 「结算词密度」能测爽 | A vs C AUC 0.52；A vs B **反向** | 测的是"有没有冲突和道歉"，**文学小说反而更多** |
| 敬称密度能测地位翻转 | AUC 0.538 | 测的是**译制腔**（Mr.→先生） |
| 前蔑称→后敬称位置代理 | **反向**（A 0.05 < B 0.125） | 无效 |

**另一条硬警告**：人工挑选的高分网文，碾压密度**低于**普通爽文
（0.017 vs 0.036）。**碾压密度是「爽文属性」的标记，不是「质量」的标记**——
不可当越高越好的优化目标。

## 四、判断流程（拿到一本书按这个走）

### 第 0 步：先问它要打哪个位

头部突围（反爽文也能赢）→ **本标准不适用**，走另一套。
腰部走量 → 继续。

### 第 1 步：定档（爽度档位 A / B / C）

看**目标读者与付费模式**，不看题材：

| | **A 即时碾压**<br>番茄免费男频 | **B 规则智斗**<br>起点付费 | **C 关系认可**<br>女频 |
|---|---|---|---|
| 爽的形态 | 物理碾压 + 当众羞辱 | 规则自洽 + 格局位移 | 被认可 + 掌控场面 |
| **憋屈耐受** | **1–1.5 章** | **3–5 章** | **2 章**（且须已在还手） |
| **铺垫:爽** | **3:7** | 5:5 ~ 4:6 | 4:6，且要分散给 |
| 反派智商 | 可以低 | **必须高**，输在合理误判 | 坏得聪明且长记性 |
| **整章不爽** | 需钩子/小爽替代 | **接受布局章**（须有信息增量） | 需日常温情替代 |
| 金手指规则 | 几乎不在意 | **最严**，新增设定即退订 | 在意"能力是否真属于她" |
| 对手下场 | 挨打、出丑 | 可放走，格局赢即可 | **必须实际损失，原谅=不爽** |
| 观众 | 越公开越好 | 不在意人数，在意势力判断 | 熟人在场，须含利益相关者 |
| 主角失败 | 减分（除非换到东西） | **加分**（暴露误判并改进） | 中性偏加 |
| 「安静地赢」 | 不喜欢 | 喜欢 | **最喜欢** |

> 典型冲突：主角一句话不说赢了 → C 打高分、A 打低分。
> **因此任何单一尺子都是错的**，不定档就判等于掷骰子。

### 第 2 步：章级判定（通用律三问）

对每一章问 1.2 的三问。**三问全「是」= 该章有爽点结算。**
每一问都要能指出**具体的字**，指不出就是「否」：

- ①对手叫什么名字？他此前在第几章做过什么？
- ②谁看见了？他的哪个动作/哪句原话/什么待遇变了？（「众人震惊」不算）
- ③主角多了什么？这东西叫什么名字？下一章还能用吗？

### 第 3 步：书级判定（按档核对硬线）

| 检查 | A | B | C |
|---|---|---|---|
| 连续无爽点章数上限 | ≤1 | ≤3 | ≤2 |
| 每章 ≥1 小爽点 | 必须 | 布局章可免（须有信息增量） | 可用温情替代 |
| 每 2–5 章 1 中爽点 | 必须 | 必须 | 必须 |
| 铺垫:爽 偏离档位基准 | >±15% 记问题 | 同左 | 同左 |

### 第 4 步：仪器辅助（只作告警，不作判定）

跑 `scripts/validate_shuangwen_chain.py <slug>`，看爽点覆盖率是否低于
**同题材层**人类 p10。**注意第五节的三条限制**，尤其市井/现实类书。

## 五、仪器的三条限制（不写清楚，判据就是假的）

2026-08-16/17 真机实测。**两把尺子各有一个已定量的局限，刚好互补：**

| 尺子 | 跨来源可比（vs 人类） | 题材公平 | 噪声 |
|---|---|---|---|
| 确定性词表分类器 | ✅ 无模型偏好 | ❌ 玄幻 73.2% / 市井 24.1% | 无 |
| 语义判官（三段律 v1.2） | ❌ **同源高估** | ✅ | 章内极差 **0.25–0.30** |

**用法由此确定，不可互换：**
- **跟人类比** → 只能用确定性分类器 + 题材分层
- **自家书前后比** → 只能用语义判官，且 **k≥3、n≥20**

### 5.1 题材偏向（词表尺子）

现成分类器 94 个中文词重度玄幻偏向（突破/晋阶/真身/金光/神识/机缘/认主/碾压/镇压）。
人类语料分层实测：**玄幻章命中 73.2%（n=425）、市井/现实章仅 24.1%（n=79）**。
两个方向的误差都有真机实例：

- **漏报**：某市井章写了教科书式三段律结算（有名字的对手被当众「手滑」少打了肉、
  第三方在场、主角全程没出手），分类器判 `None`
- **误报**：某章分类器判 `face_slap`，语义判官只给 0.30（命中关键词但无真结算）

**结论：词表尺子不能当判据，只能当告警。**

### 5.2 同源高估（语义判官）

人类出版章 payoff 中位：玄幻 0.16 / 市井 0.12 / 混合 0.19（每层 14 章 ×2 采样）。
我们三本书 0.325–0.45，**高 2–4 倍**——而读者盲评判它们「50 章零爽点」。

查因：`llm_runs.model_name` 显示**写手与判官同为 MiniMax-M3**。判官在给自家家族打分。
**要让判官能跟人类比，必须换不同家族的模型。**

### 5.3 噪声（语义判官）

同一段文字（md5 未变）重复评分，章内极差 **0.25–0.30**，覆盖大半个量程。

> **章级 payoff 读数一律不可单独引用**；只有 n≥20 的书级聚合有判别力
> （sd≈0.12，n=20 时标准误≈0.03）。

两次差点据此报假缺陷，都是靠「先 k=3 再下结论」拦住的：
ch1（0.88→0.78，查证内容根本没变）、ch14（0.72→0.18，内容确实变了，
但 k=3 对测 0.35 vs 0.33 实质相同）。

### 5.4 尚未解决的矛盾（必须写明）

**读者盲评说我们的书「50 章零爽点」，仪器读出 0.16–0.45。这个矛盾至今没有解决。**

可能是仪器把「写了一个转折」当成爽点，而读者要的是「赢得爽」；
也可能读者对该题材的期待与仪器的定义不是一回事。

> **在这个矛盾解开之前，仪器给出的数只能用于「同条件前后比」，
> 不能用于回答「这本书爽不爽」。** 那个问题目前只能靠第四节的人工流程。

## 六、铁律（都付过学费）

1. **无杀权**——最强爽文单指标 AUC 仅 0.716，词表误报 40–45%，一律 `audit_only`
2. **prompt 不种词**——只给类别与正向方向，token 只留检测器层。
   把「打脸/跪下/求饶」写进 prompt，所有书会长成同一副样子
3. **词表必须跨题材**——见 5.1
4. **先证伪现有机制再动手**——本项目反复出现「同一事实住两个地方」
5. **验收看真机 DB**，不是单测绿；且**不要测一个还在变的对象**
   （本轮曾在修订轮进行中测出「两条判据未过」，收尾后实为全过）
