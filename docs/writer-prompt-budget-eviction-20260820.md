# 写手 prompt 预算淘汰：后半段劣化的结构性来源

日期：2026-08-20 · 定罪样本：《罚我守坟，坟里换的全是活人》(custom-xianxia-1787176467)

## 现象

同一本书里初稿 AI 味命中数 ch1-8 中位 5.5 → ch9-16 **8.0**，而 deslop 在后批
调用更多、写作纪律块完整在场。源头在写手侧。

## 取证

18 章的 `chapter-first-prompt-*.json` 全部落在 **user_chars 9824–10001**，
system_chars 恒定 2523。压缩器上限 `_DEFAULT_MAX_CHARS = 10_000`
（对应 `context_budget_tokens: 8000`）。**18/18 章每章都触发淘汰**，
而 `【写作提示已压缩】` 这个 marker 是唯一痕迹——没有任何一行日志说明丢了什么。

按块自身上限求和：

| 段 | 上限 |
|---|---|
| 【章节契约】 | 3500 |
| 【故事圣经上下文】 | 3200 |
| 【活动主线/伏笔/回收】 | 3000 |
| 【时间线与硬事实快照】 | 2800 |
| 【近期章节/场景摘要】 | 1800 |
| 合计 | **14 300** |

仅 PLAN 层就是预算的 **1.43 倍**，还没算任务/章节目标/硬约束/爽点约束/
输出规则。**淘汰是结构性必然，不是偶发。**

## 真正的病：淘汰顺序由"位置 + 大小的意外"决定

原 `_cap_prompt` 的填充逻辑是：

```python
for section in middle:            # 按出现顺序
    if used + len(section) > max_chars:
        continue                  # 装不下就跳过，继续看下一段
    keep_ids.add(id(section))
```

`continue`（而非 `break`）意味着**大块被跳过、后面的小块反而活下来**。
于是最大的那几块——前情摘要、伏笔账本——永远第一批出局，而靠后的小段存活。

真机 ch18 存活清单：任务 / 上一章硬承接 / 章节目标 / 硬约束与门禁 / 本章爽点约束 /
章节契约 / 故事圣经上下文 / **[压缩]** / 时间线 / 弱场景逻辑地图 / 隐藏节点执行规则 /
内容安全规则 / 删减策略。

**丢掉的**：`【近期章节/场景摘要】`、`【活动主线/伏笔/回收】`、`【检索补充】`、
`【角色认知边界】`、`【角色生死与登场安全】`、`【写前验收契约】`、`【方法论证据】`。

前两项是写手"接得住上一章"和"记得欠了哪些伏笔"的**唯一来源**——
故事圣经在 pack 和 system prompt 里另有一份，前情摘要没有第二份。
章数越大这两块越满，越先被扔。这就是后半段劣化的机械解释。

## 修复（不抬预算）

10k 上限对应刻意设定的 8000 token 写手上下文预算，且 `prompt回胖` 有过回归
前科（见 memory `prose-prompt-diet`），因此**不动预算**，只改淘汰顺序：

1. 新增 `_CONTINUITY_SECTION_MARKERS`，按价值排序：
   先"这一章要写什么"（上一章硬承接 → 本章爽点约束 → 章节契约 → 弱场景逻辑地图），
   再"接得住前文"（近期章节摘要 → 活动主线/伏笔 → 时间线快照 → 读者期望画面），
   故事圣经排最后一档（静态信息，别处有副本，但仍应赢过检索补充/方法论证据）。
2. 连贯性层在通用层之前入选，但**仍受预算约束**——不像 `protected` 那样
   可以撑破上限。消融证据 PLAN > CONST > CRAFT，所以让位的应该是参考层。
3. `CompactionReport.evicted_sections` 记录被扔掉的段标题，写进 prompt trace
   的 `prompt_compaction.evicted_sections`，并 `logger.info` 一行。
   **留痕不夺权**：淘汰行为本身没变严也没变松，只是不再静默。

no-op 归因验证：把 `_continuity_rank` 打成恒 None，`【时间线与硬事实快照】`
当场被淘汰、`【故事圣经上下文】` 反而存活——正是修复前的价值盲行为。

## 仍未解决（记账）

**每块的独立上限之和 = 预算的 1.43 倍**，所以即使按价值排序，每章仍必然
丢掉最低优先级的几段。根治要么是给 PLAN 层一个共享预算（各块按剩余额度
动态收缩），要么重新标定 8000 token 这个数。两者都需要 A/B，不在本次范围。
下一本书的 trace 里 `evicted_sections` 会直接给出每章实际丢了什么——
先有量具再改预算。
