综合后，7 本书反复指向同一个故事质量链条：

```text
承诺/问题 → 压力/阻力 → 人物选择 → 代价 → 状态改变 → 兑现/新问题
```

这条链条是后续融合框架时最重要的主轴。

## 2. 《雪花写作法》方法论

### 核心定位

这本书的主轴是“递进式规划”。它把小说从一句话前提逐层扩展到人物、情节、场景列表和可写的大纲，核心价值不是让作者机械套模板，而是降低长篇写作的不确定性。

### 主要方法论

1. **一句话前提**  
   先用一句话说明故事的核心矛盾、主角、目标和卖点。它要求故事在扩展前先有可验证的核心承诺。

2. **段落式扩展**  
   把一句话扩成一段，再扩成多段。每一次扩展都要检查冲突、灾难、转折和结尾是否成立。

3. **人物优先补全**  
   主角、反派和主要角色需要有目标、价值观、动机、冲突和变化线。人物不是填入情节的名字，而是情节发展的原因。

4. **反派深层塑造**  
   反派不能只是阻碍物。反派也应有自己的目标、逻辑、过去和合理动机，这样主线冲突才有厚度。

5. **目标与野心区分**  
   抽象野心要转成可行动的具体目标。例如“变强”不够，必须落成“夺回某物、救某人、赢下某场对抗”。

6. **场景清单和 spreadsheet 思维**  
   场景应被列成可管理清单，每场记录 POV、目标、冲突、结果和后续影响。

7. **主动场景与反应场景**  
   主动场景偏“目标-冲突-挫败”，反应场景偏“情绪-分析-决定”。两者交替，形成行动和情绪的连续推进。

8. **灾难点放在结构节点**  
   关键结构节点需要足够强的灾难、挫败或选择压力，避免长篇中段失去张力。

9. **先修大纲，减少正文返工**  
   这本书强调早期发现结构问题，因为正文阶段再修主线、人物和结局，成本更高。

10. **方法适配而非方法崇拜**  
    规划派和发现派都可以写作，关键是找到适合项目和作者的流程，并用反馈修正。

### 对框架的直接启发

| 方法论 | 框架落点 |
| --- | --- |
| 一句话前提、段落扩展 | `BookSpec.logline`、`dramatic_question`、`series_engine` |
| 人物目标/价值观/动机 | `CastSpec`、`CharacterModel`、`character_arc` |
| 场景清单 | `ChapterOutlineBatch.scenes`、`SceneCardModel` |
| 主动/反应场景 | `chapter_event_role`、`event_cycle_contract` |
| 灾难点/结构节点 | `VolumePlan`、`is_climax`、`conflict_buffs` |

### 融合注意

它适合 planner 和 outline 阶段，不适合在 prose 阶段临时注入。否则模型只会写出“看起来结构化”的正文，无法真正改善全书因果。

## 3. 《哈佛短篇小说写作指南》方法论

### 核心定位

这本书把“场景”视为最小故事单元。它强调短篇或场景都必须有自己的叙事问题、危机、行动和结尾，而不是一串描写或说明。

### 主要方法论

1. **场景是 mini story**  
   每个场景都应有开端、推进、危机和结尾。一个场景如果没有局面变化，就不是有效故事单位。

2. **叙事问题驱动兴趣**  
   读者被“问题”牵引：主角能否做到？他会如何选择？真相是什么？问题必须清晰，答案必须延迟。

3. **危机分为行动危机和选择危机**  
   行动危机关注“能不能完成某事”，选择危机关注“该不该做某事”。两种危机决定故事结构和场景写法。

4. **事件 → 插曲 → 遭遇 → 场景**  
   单个事件可以扩展为互动，互动可以升级为遭遇，遭遇在冲突中形成完整场景。

5. **五步场景结构**  
   场景可按“遭遇/进入情境 → 场景目标 → 互动冲突 → 结尾行动 → 余波/连接主问题”组织。

6. **第五步必须连接主线**  
   场景结尾不能只停在局部效果，必须把本场变化连接到主故事问题上。

7. **悬念来自延迟回答**  
   不要过早回答叙事问题。可以通过刺激-反应、阻碍、误导、代价来延迟。

8. **希望/恐惧交替**  
   场景推进应让读者在“可能成功”和“可能失败”之间摆动。

9. **POV 由危机焦点决定**  
   视角应选最能承受危机压力、最能暴露故事问题的人。

10. **清晰优先于炫技**  
    文体、比喻、描写和句式都要服务场景呈现，不能压过叙事问题。

### 对框架的直接启发

| 方法论 | 框架落点 |
| --- | --- |
| 叙事问题 | `hook_description`、`next_reader_desire` |
| 行动/选择危机 | `main_conflict`、`protagonist_choice` |
| 五步场景 | `SceneCardModel.purpose`、`scene.methodology_contract` |
| 第五步连接主线 | `state_change`、`gain_or_reveal` |
| 希望/恐惧交替 | `pressure`、`conflict_buffs`、review pacing |

### 融合注意

这本书对 `scene_causality` 非常强，适合成为场景生成和场景 review 的核心方法论。但它更偏短篇/场景，需要和长篇 ledger、卷目标、角色长期弧线结合。

## 4. 《小说写作：叙事技巧指南》方法论

### 核心定位

这本书偏“叙事技巧”和“文字执行”。它关心人物如何被动作、对白、细节和视角呈现出来，也关心修订时如何发现具体问题。

### 主要方法论

1. **人物通过行动显现**  
   角色性格最好通过他做什么、怎么做、在压力下如何反应来呈现。

2. **对白显示性格和关系**  
   说话方式、词汇、回避、打断、沉默都能塑造人物，不应让所有角色说同一种话。

3. **间接塑造优于说明**  
   让读者从行动、场景细节、他人反应中推断人物，而不是由作者直接下判断。

4. **细节必须有意义**  
   细节应服务情绪、主题、人物或情节，不应成为无功能装饰。

5. **主动语态和具体动词**  
   句子要有行动力。动作、物件和感官证据比抽象形容更可靠。

6. **句式节奏匹配内容**  
   紧张场景用更短、更直接的句子；反思或舒缓场景可拉长节奏。

7. **控制叙述距离**  
   叙事不能随意在作者讲解、外部观察和角色内部体验之间跳动。

8. **减少过滤词**  
   “他看见、他感觉、他意识到”这类过滤词会拉远距离，很多时候应直接呈现感官对象。

9. **主题在修订中浮现**  
   主题不一定先被宣言式确定，常常在草稿中显形，再通过修订强化。

10. **多轮定向修订**  
    修订时每一轮只盯一种问题，例如 POV、细节、对白、节奏、主题，而不是一次性泛改。

### 对框架的直接启发

| 方法论 | 框架落点 |
| --- | --- |
| 行动显现人物 | `visible_action_or_reaction`、scene review |
| 对白差异 | `character_voice_distinction`、dialogue repair |
| 叙述距离 | `pov_consistency`、`pov_prose` |
| 有意义细节 | `signature_image`、`world_rule_landing` |
| 多轮修订 | `RewriteTaskModel`、review finding categories |

### 融合注意

这本书更适合 draft、review、repair 阶段。它不应该只作为“文风提示”，而应拆成 POV gate、show-don't-tell gate、dialogue gate、detail-purpose gate。

## 5. 《怎样写故事：小说与剧本创作的6W原则》方法论

### 核心定位

这本书的核心是“故事的意义来自人物内在变化”。外部事件只有作用到主角的信念、恐惧、欲望和选择上，才构成真正的故事。

### 主要方法论

1. **主角内在冲突是故事电轨**  
   主线不是事件堆叠，而是外部压力不断触碰主角的内在矛盾。

2. **先设计内部故事，再设计外部情节**  
   如果不知道主角为什么在乎、害怕什么、误信什么，外部事件就会失去意义。

3. **具体主角，而非任意人**  
   同一个事件落在不同人身上会变成不同故事。主角必须有独特过去、欲望和误判。

4. **欲望与恐惧组成发动机**  
   主角想得到什么、害怕失去什么、错误相信什么，决定他如何行动。

5. **每个元素都要连接内在冲突**  
   动作、对白、描写、支线、世界观都应回到主角当前的内在压力。

6. **因果链优先于事件顺序**  
   不是“然后发生”，而是“因为这个选择，所以产生那个后果”。

7. **场景要有 alpha point**  
   每场应明确起点处主角的预期/信念，以及结尾时这个预期如何被改变。

8. **转折场景要细化**  
   人物改变不是一句顿悟，而是由压力、证据、失败和选择逼出来。

9. **顿悟是结尾核心**  
   结尾的高潮不仅是事件解决，还要体现主角世界观或自我认知的变化。

10. **主题通过视角和代价呈现**  
    主题不是说教，而是人物在代价面前选择了什么。

### 对框架的直接启发

| 方法论 | 框架落点 |
| --- | --- |
| 内在冲突 | `CastSpec.character_arc`、`protagonist_desire` |
| 欲望/恐惧/误信 | character profile、scene emotional task |
| 因果链 | `causal_contract` |
| alpha point | `entry_state` / `exit_state` |
| 顿悟 | climax chapter、`state_change`、snapshot |

### 融合注意

这本书能补当前框架中“事件很满，但人物变化不够锋利”的问题。它应前移到 BookSpec/CastSpec/ChapterOutline，而不是只在正文阶段要求“写出内心”。

## 6. 《布洛克小说写作手册》方法论

### 核心定位

这本书更像职业写作者的实践手册。它覆盖创作习惯、题材阅读、市场感、开篇策略、修订、反馈和长期产能。它不是单一结构理论，而是“如何持续写下去并交付作品”的经验系统。

### 主要方法论

1. **长期稳定输出比灵感更重要**  
   每日目标、持续写作、减少中断，是长项目完成的前提。

2. **通过大量阅读内化类型**  
   要理解题材期待、读者习惯和惯例边界，不能只凭抽象想象写类型小说。

3. **分析其他作者的技巧**  
   阅读不是消费，而是观察开篇、冲突、转折、对白、章节断点等技巧。

4. **开篇要立刻制造注意力**  
   可以从行动中开始，用不完整信息、异常局面或冲突吸引读者。

5. **市场与个人声音要平衡**  
   类型承诺和读者期待重要，但作品也需要作者自己的兴趣和声音。

6. **修订目标要明确**  
   修改标题、开篇、结构、人物、语气、节奏时要知道自己在解决什么问题。

7. **反馈要选择性使用**  
   反馈有价值，但过早、过杂的反馈会打断草稿完成。

8. **研究和写作要分清阶段**  
   研究不能变成拖延。缺材料时补材料，能写时先把草稿推进。

9. **把写作当作技能投资**  
   写作能力来自反复练习、投稿/反馈/修订循环，而不是一次性顿悟。

10. **接受建议的上下文差异**  
    写作建议常常互相矛盾，因为它们适用的项目和作者不同。需要判断而不是盲从。

### 对框架的直接启发

| 方法论 | 框架落点 |
| --- | --- |
| 类型阅读/市场意识 | prompt packs、platform profiles、material forge |
| 开篇注意力 | opening gates、first chapter contract |
| 长期产能 | project health、workflow progress、resume |
| 反馈/修订循环 | `ReviewReportModel`、`RewriteTaskModel` |
| 方法上下文差异 | selector、project profile overlay |

### 融合注意

这本书产出的卡最多，覆盖广，但重复母题也最多。它适合作为 advisory/heuristic pool，不应因数量优势压过更结构化的书籍或平台强约束。

## 7. 《情节与人物：找到伟大小说的平衡点》方法论

### 核心定位

这本书重点解决“情节强但人物薄”或“人物细但情节散”的问题。它强调人物和情节必须互相生成：人物的欲望与缺陷制造行动，行动的后果逼迫人物改变。

### 主要方法论

1. **人物有核心人格**  
   可以借助心理模型区分人物，让主要角色避免同质化。

2. **从核心人格向外扩展**  
   外貌、职业、说话方式、习惯和背景应服务核心人格，而不是随意装饰。

3. **人物需要 passion**  
   角色必须有愿意为之付出代价的东西，行动才有能量。

4. **记录人物起始生活状态**  
   角色在故事开始时的关系、职业、经济、心理满足度，会决定他为什么被事件改变。

5. **人物弧线五阶段**  
   人物从旧状态、触发、抗拒、被迫选择到改变，应有可追踪阶段。

6. **情节由人物驱动**  
   情节不是外部事件拖着人物走，而是人物选择让事件升级。

7. **三幕结构服务人物变化**  
   第一幕让人物进入问题，第二幕用升级冲突逼迫改变，第三幕用高潮测试改变是否真实。

8. **高潮是决策点**  
   最终高潮不只是打赢，而是人物在最大压力下做出能证明变化的选择。

9. **外部冲突映射内部冲突**  
   外部敌人、环境、时限、损失，要能逼出人物内部矛盾。

10. **结局要合并外部解决和内部变化**  
    情节问题和人物问题都应在终局得到回应，不能只解决一边。

### 对框架的直接启发

| 方法论 | 框架落点 |
| --- | --- |
| 核心人格 | character idiolect、cast strategy |
| passion / want | `protagonist_desire`、relationship debts |
| 起始状态 | `opening_state`、character snapshots |
| 五阶段弧线 | `ArcBeatModel`、volume plan |
| 高潮决策点 | climax contracts、`is_climax`、review |

### 融合注意

它适合与现有 `character_idiolect_tracker`、cast strategy、chapter snapshots 深度融合。它不能只变成“人物设定更丰富”，重点是人物设定必须改变情节走向。

## 8. 《故事写作 小说写作实用指南》方法论

### 核心定位

这本书更偏本土创作经验和类型表达，强调从真实经验、社会/历史材料、梦境/想象、悬念节奏和人物层次中生成故事。

### 主要方法论

1. **主角自我认知弧线**  
   主角应经历从弱点、无知、逃避到理解、行动和成长的变化。

2. **反派类型和均衡设计**  
   反派需要功能、动机、复杂性和与主角相称的力量，冲突才有可看性。

3. **熟悉环境深挖**  
   熟悉地点、职业、社会关系可以提供真实细节和情绪底色。

4. **陌生化环境描写**  
   环境不只是背景，应通过视角、象征和情绪变化变得有意义。

5. **梦境/片段作为故事种子**  
   梦境或强烈画面可以扩展成情节，但必须经逻辑补全。

6. **假设变形法**  
   对现实元素提出“如果……”的问题，把熟悉材料变成新故事。

7. **波浪式冲突推进**  
   冲突不能一直同强度推进，应有加压、释放、再加压的波形。

8. **线索必须对读者可见**  
   悬疑或推理中的线索要提前给读者看见，否则 payoff 会显得作弊。

9. **社会/历史材料进入主题**  
   历史事实、地域语言、社会事件可以增强真实感，但必须服务人物和主题。

10. **外部氛围和内部心理共振**  
    恐怖、悬疑、历史等题材需要环境、心理和事件互相强化。

### 对框架的直接启发

| 方法论 | 框架落点 |
| --- | --- |
| 社会/历史材料 | material forge、world bible、WorldviewKernel |
| 陌生化环境 | `signature_image`、location refs |
| 线索可见 | `ClueModel`、hook/payoff ledger |
| 波浪式冲突 | pacing mode、emotion phase |
| 反派均衡 | antagonist plan、threat escalation |

### 融合注意

它对本土类型和悬疑氛围有价值，但很多方法偏启发式。适合与 `worldview_theme`、`opening_retention`、`setup_payoff` 做补充，不适合直接变成硬 gate。

## 10. 当前判断：哪些内容适合怎么融合

### 应该进入 planner 的方法论

- 一句话前提、读者承诺、dramatic question。
- 主角内在冲突、欲望、恐惧、误信。
- 全书/卷/章的因果链。
- setup/payoff 队列。
- 章节在更大事件单元中的角色。

### 应该进入 scene contract 的方法论

- 场景目标、阻碍、行动、代价、结果。
- entry_state / exit_state。
- POV 角色和视角距离。
- signature image。
- hook type、cut point、information control mode。

### 应该进入 draft prompt 的方法论

- show-don't-tell。
- 具体动作和感官证据。
- 对白潜台词。
- 场景压力和节奏。
- 禁止方法论术语泄漏到正文。

### 应该进入 review/gate 的方法论

- 场景因果完整度。
- POV 稳定性。
- 对白承载。
- hook/payoff 是否有账本证据。
- 线索是否提前可见。
- 人物行动是否有动机、选择和代价。

### 应该进入 repair 的方法论

- 低分指标到方法论域的映射。
- 按失败模式生成 RewriteTask。
- setup/payoff 缺口走 ledger repair，不走泛泛润色。
- POV/对白/场景因果分别定向修复。

## 11. 后续对标时应重点检查的问题

1. 某个方法论是否已经有框架字段承载？
2. 它是 `strict`、`heuristic` 还是 `advisory_only`？
3. 它应该在 planner、draft、review 还是 repair 阶段生效？
4. 它是否和平台强规则、`writing_methodology.yaml`、prompt pack 冲突？
5. 如果它低分，系统能否自动选择对应 repair 策略？
6. 它的效果能否通过 A/B 指标验证，而不是靠主观感觉？
