## 1. 背景（为什么书名变成垃圾）

最近一次提交 `6e59af7 "Refine hook formulas and Concept Lab generation"` 引入了全新的 Concept Lab 子系统（`concept_lab.py` 623 行）与 `concept_title_formulas.yaml`，并把 `platform_title_workflow` 接到了生产链路（conception 终段）上，**赋予它覆盖模型/人工标题的最终决定权**。

问题是：`platform_title_workflow` 是一个**为单一"驱魔探案" demo 调好的纯模板拼接器**（`output/exorcist-detective-*` 是它的设计样本），没有任何一次 LLM 调用，却套着 `methodology_source` / `generation_steps` 这类"方法论"装饰元数据。一旦接到全题材生产链路，它就把所有题材的书名都按探案模板重拼，并把模型写好的正经书名丢弃。

### 1.1 复现证据（生产路径 `select_primary_platform_title`）

输入一个完全正常的标题 **「烬骨登天录」**（玄幻·修真复仇），实际输出：

| 目标平台 | 框架最终采用书名 | 病灶 |
|---|---|---|
| 七猫 | **复仇神探** | "神探"硬编码后缀，玄幻书被套探案模板 |
| 起点 | **宗门案卷** | "案卷"硬编码，同样探案模板 |
| 番茄 | **我在修真·复仇·宗门靠复仇翻盘** | 带「·」的原始 sub_genre 直灌句中，语法破碎 |
| 晋江 | **复仇倒计时** | tag「复仇」被当 hook，全平台复读"复仇" |
| 通用 | **复仇之书** | 纯兜底废话 |

> 复现脚本（手测）：`PYTHONPATH=src python3 -c "from bestseller.services.platform_title_workflow import select_primary_platform_title; ..."`
> 原始好标题「烬骨登天录」**一个都没活下来**。

## 2. 根因（代码级，按对结果的影响力排序）

| 代号 | 根因 | 证据（file:line） | 主要损害 |
|------|------|------------------|---------|
| **T-0** | **输入契约错误：题材分类被当成书名内容**。书名本应基于故事 DNA（大纲/一句话钩子/吸引力方向）构建，但链路把 `primary_category`/`secondary_category`（修仙/悬疑等题材标签）直接喂进了书名工程，且所有内容槽（hook/object/threat/setting/identity）的 fallback 链最终都落到题材标签 | `conception.py:1752` 装入 category；`_signal_tokens:423` 内容槽回退到 `secondary`/`primary` | **结构性根因**：题材标签直接变书名 |
| **T-A** | **好标题被无条件丢弃**：原始主标题只有 `title_evaluation.decision == "pass"` 时才进候选池；但实测所有标题都判 `revise`，永远拿不到 `pass` | `platform_title_workflow.py:951` + `_select_primary_candidate:1146` | **决定性**：模型标题永远出局 |
| **T-B** | **评估器只认"短视频口播体"**：吸引力打分要 ≥70，加分项全是 `我/你/越/开局/让你/倒计时/？`；文学 IP 名一个钩子词都没有 → 42 分 → fail | `_evaluate_reader_attraction:1585` | 凝练书名被系统性误判为废 |
| **T-C** | **模板硬编码单一题材**：七猫 `{object}神探`、起点 `{threat}案卷`、`{setting}诡案录`——探案专用，对玄幻/言情/科幻全部错配 | `_platform_template_specs:1878` | 题材错配的怪标题 |
| **T-D** | **token 抽取退化、脏数据直灌**：原始 `secondary_category`「修真·复仇·宗门权谋」（含「·」）当 setting；tag「复仇」同时当 hook/object/threat | `_signal_tokens:374` | 语法破碎 + 复读 |
| **T-E** | **（旁支）Concept Lab 把标语当书名**：`mechanism_title_cores` 填的是带逗号标语（"死线越近，底牌越真"），`contrarian_truth` 公式 `{title_core}` 原样输出；docstring 却写"4-10 字精炼 title_core" | `config/concept_title_formulas.yaml` + `concept_title_formulas.py:5` | 目前仅污染 `title_seed`（提示位），隐患 |

> **关键判断**：
> - **T-0 是结构性根因**——书名构建的输入就喂错了。题材分类（修仙/悬疑）是**标签**，逻辑上不能当书名内容，只能用于①选平台风格②个别频道前缀（受控短词）。内容槽必须只从故事 DNA 派生，且**派生不出来时不得用题材标签兜底**，应让位给模型原标题/LLM 改写。
> - **T-A 是即时致命点**——让模型标题"默认保留、只在 reject 时才让位"，垃圾书名立刻消失大半。
> - T-B/T-C/T-D 决定"备选候选"的质量；T-E 是独立小修。

### 2.1 T-0 复现证据（薄故事 DNA 时题材标签直接成书名）

输入一个只有题材标签、logline 空泛的 profile（`primary_category=仙侠, secondary_category=修仙, tags=[仙侠,修真,升级流]`）：

```
内容槽全部回退到题材标签：hook=修真 setting=修仙 object=修真 threat=修真
=> qimao: 修真神探 | qidian: 修真案卷 | fanqie: 我在修仙靠修真翻盘 | general: 修真之书
```

题材词「修仙/修真」**就是**最终书名——这在逻辑上根本不成立。

## 3. 目标与非目标

**目标（本次交付）**
1. **输入契约纠正（T-0）**：书名内容只从**故事 DNA**（logline/一句话钩子/reader_promise/非题材 tags/角色身份）派生；题材分类（genre/sub_genre）**退出书名内容**，仅保留两个合法用途——①选平台 `style`，②受控频道前缀短词（如飞卢「仙侠：」，取自精选映射，绝非原始 sub_genre 串）。派生不出内容时不得用题材标签兜底。
2. 模型/人工写的主标题默认保留，不再被模板无条件覆盖（黑名单制取代白名单制）。
3. 评估器能正确识别"凝练 IP 名"，不再把无标点书名一律判废。
4. 平台模板按 genre **族系**路由（玄幻/言情/探案各走各的），消除探案题材错配。
5. token 抽取清洗分隔符、去重。
6. **P2 根治**：接通 LLM 真改写——当主标题被判需要优化时，用 `_title_revision_prompt` 调一次 LLM 产出平台口播优化标题，替代纯模板拼接。
7. Concept Lab 标题核：标语与书名核分离。

> **核心原则**：题材分类是"放在哪个货架"的标签，不是"这本书叫什么"。书名 = f(故事 DNA, 平台风格)，题材只进 `style` 选择，不进标题字面。

**非目标（本次不动）**
- 不换模型、不改 LLM 角色分级。
- 不删 `platform_title_workflow` 的候选矩阵能力（它做"多平台 A/B 候选建议"仍有价值）；只收回它对主标题的**强制覆盖权**。
- 不重构 Concept Lab 整体。

## 4. 架构修正

### 4.1 当前链路（问题）

```
conception 终段 final_result.title（模型产出，质量OK）
        │
        ▼
select_primary_platform_title(title_profile)   ← 纯模板拼接，无 LLM
        │  T-A: 原标题非 pass → 丢弃
        │  T-C: 套探案模板  T-D: 脏 token
        ▼
workflow_title 覆盖 title  ← 垃圾书名最终落库
```

### 4.2 目标链路

```
conception 终段 final_result.title（模型产出）
        │
        ▼
build_platform_title_workflow()  ← 仍是纯同步，产出：
        │   · 原标题候选（默认 keep）
        │   · 多平台 A/B 候选（按 genre 路由的模板，仅作建议）
        │   · 每个候选的 evaluation + revision_prompt
        ▼
_select_primary_candidate()  ← 黑名单制：
        │   原标题 reject 才让位；否则保留
        ▼
[新增] 若主标题 decision==revise 且开启 LLM 改写：
        conception 层用 _title_revision_prompt 调 complete_text(role=...)
        → 校验长度/题材/无脏字符 → 通过则采用，失败回退原标题
        ▼
最终 title
```

> **设计约束**：`platform_title_workflow.py` 保持**纯同步、无副作用**。LLM 调用放在 conception 层（那里已有 `session` / `settings` / `complete_text`）。workflow 只负责"产候选 + 产 revision_prompt"，不自己调模型。

## 5. 实施步骤（TDD，先补现测再改）

### P0 止血（决定性，先恢复正常书名）

- **F0 · 切断题材标签 → 书名内容的泄漏（T-0，头号修复）**
  `_signal_tokens:374`：内容槽（hook/object/threat/setting/identity/twist/action）的 fallback 链**移除 `secondary`/`primary`（题材标签）**；改为从 logline/一句话钩子/reader_promise/非题材 tags/角色身份派生。
  - 新增 `_is_genre_like_token` 拦截：任何落到内容槽的值若是题材词（修仙/悬疑/玄幻…）一律丢弃。
  - 派生不出有效内容槽时，该模板候选**不生成**（而非用题材词凑），把主标题决定权交还原标题/LLM 改写。
  - 题材分类仅保留：`style` 选择（已有）+ 受控频道前缀（飞卢/番茄等，取自精选 `genre→频道短词` 映射）。
- **F1 · 反转保留逻辑**
  `platform_title_workflow.py:951`：原始主标题候选默认加入 pool，仅当 `decision == "reject"` 时排除。
  `_select_primary_candidate:1146`：调整优先级——目标平台候选中，**原标题（pattern=="当前主书名校准"）若非 reject 则最优先**，模板候选退为次选。
- **F2 · 评估器加"凝练 IP 名"通道**
  `_evaluate_reader_attraction:1585`：新增判定——长度 3–8、无逗号/问号、含题材意象字（登天/问道/诡案/重生/replace 等族库）的标题，吸引力直接达标，不再强制口播钩子词。
- **测试**：`tests/unit/test_platform_title_workflow.py`（新建）——断言「烬骨登天录」在 qimao/qidian/玄幻 profile 下被保留为主标题。

### P1 题材解耦 + token 清洗

- **F3 · 模板按 genre 路由**
  `_platform_template_specs:1878`：把探案硬编码（神探/案卷/诡案录）拆成 genre 族库（玄幻/仙侠→登天录·问道·天骄；言情→宠·替嫁·重生；探案→案卷·诡案）。`_signal_tokens` 增加 `genre_family` 字段供模板选择。
- **F4 · token 分隔符清洗**
  `_signal_tokens:374` / `_reader_title_token:500`：对 `·／,、；:` 切分取最具体段，禁止整串 sub_genre 进模板；hook/object/threat 去重，避免同一 tag 多槽复读。
- **测试**：断言番茄不再产出含「·」的标题；断言三槽不复读同一词。

### P2 根治 · LLM 真改写（本次重点）

- **F5 · 接通 `_title_revision_prompt`**
  在 `conception.py`（`select_primary_platform_title` 调用处，约 `:1782`）后新增：当返回的主候选 `decision == "revise"` 且配置开启时，取该候选的 `feedback.revision_prompt`，用 `_llm_call`（已存在，`logical_role` 复用 conception finalize 角色）调一次 LLM，要求按目标平台口播规则改写出**单个**优化标题。
  - 输入：原标题 + 平台风格规则（`style.design_rules` / `avoid_rules`）+ logline + 题材。
  - 输出校验：长度落 `style.min_chars~max_chars`、无脏字符、题材不漂移；任一不过 → 回退原标题。
- **F6 · 配置开关**
  `config/default.yaml` 增 `title_workflow.llm_revision_enabled`（默认 true），便于离线/降本时关闭回退到 P0/P1 的确定性结果。
- **测试**：mock LLM，断言 revise 路径被触发、校验失败时回退原标题。

### P3 旁支 · Concept Lab 标题核

- **F7 · 标语与书名核分离**
  `config/concept_title_formulas.yaml`：`mechanism_title_cores` 改填 4–8 字**书名核**（如 `death_grows: 死线`、`time_loop: 万次轮回`）；带逗号标语移到独立 `mechanism_hooks` 字段，仅供 logline/卖点使用，不进 `{title_core}`。
- **测试**：`tests/unit/test_concept_title_formulas.py` 增断言——所有 `title_core` 无逗号、CJK 长度 ≤8。

## 6. 验收标准

0. **T-0 硬性**：任意 profile（含薄故事 DNA）下，最终书名与所有模板候选**不得等于或包含纯题材词**（修仙/悬疑/玄幻/修真…）作为标题主体；薄 DNA 时回退模型原标题而非生成「修真之书」。
1. 玄幻/言情/科幻/探案各一个 profile，主标题保持模型产出或合理改写，**无探案错配、无「·」脏字符、无三槽复读**。
2. 「烬骨登天录」类凝练 IP 名在所有平台被保留。
3. LLM 改写路径：revise 命中时产出平台优化标题；校验失败稳定回退原标题，绝不产出空/碎标题。
4. `pytest tests/unit/test_platform_title_workflow.py tests/unit/test_concept_title_formulas.py` 全绿。
5. 全量回归 `pytest -q` 不引入新失败。

## 7. 风险与回退

- **LLM 改写成本/延迟**：每本书多一次 LLM 调用。通过 `llm_revision_enabled` 开关与"仅 revise 才调用"控制；reject/pass 都不调用。
- **改写漂移题材**：靠输出校验（题材关键词 + 长度 + 脏字符）兜底，失败即回退确定性原标题。
- **F1/F3 影响既有快照**：仅影响新生成项目的主标题选择，不回改历史 canon。
