# 同质化与写死约束 · 全链路审计报告（2026-06-24）

> 目标:找出生产链路里**导致跨书同质化、或把设定写死得过僵从而压制大模型输出、损害大纲/正文质量**的硬编码约束。范围:构思→规划/大纲→正文→题材表→评分门禁。方法:4 个并行审计 agent 逐层只读审计。本文 file:line 为审计时实际行号。

## 贯穿性根因(一句话)

**框架把「男频爽文 / 侦探」当成全题材默认,且大量约束做成了「硬强制」(critical 阻断 / schema 必填 / 写死词表)而非「软引导」。** 两个后果:① **同质化**——每本书被压进同一模具(系统/金手指/升级流/信息差炸弹);② **压制输出质量**——对非爽文题材,硬约束让大模型无法发挥,好内容被反复毙 / churn。另有一类特别脏:**单本书(青囊/镜债/砚台系列)的私货专有名词,被烘焙进对所有书生效的通用 prompt 和 block 级闸门**。

治本方向(与本仓 `prose_craft_techniques.yaml` / `concept-autobake-to-methodology` 一致):**方法论引导 + 开放池 > 写死;具体内容(名/桥段/数据/例句)迁出到 per-project metadata 或合成占位;机制骨架按题材族 soft 化、可覆盖、可跳过;critical 硬阻断降为 advisory/audit_only。**

- **2026-06-24 复核结论(本条系审计静态读高估,与 [[improvement-audit-verification]] 同型):四套 kernel 已是 genre-aware,非同质化源,无需改。** 逐条核验:
  - `entry_system_kernel._taxonomy_for_profile` 按题材分流:进阶题材→法宝/功法/修行路径/阵法;关系题材→承诺物/秘密/义务/身份;悬疑→证据/规则/伪装;末世→资源/据点/感染;其它→通用 关键物/资源/证据/身份/母题。**实测**(romance/history/xianxia/mystery 跑 `build_fallback_entry_system_kernel`):各题材 taxonomy 互不相同,且**零** `属性面板/状态栏/叮——/宿主/签到` 等系统面板词。所谓"升级阶梯"实为通用"资产成熟度"语义,非数值面板。
  - `emotion_driven_kernel` 由 LLM 从本书 premise/world/cast 生成;`_fallback_emotion_driven_kernel` 亦全部从本书 protagonist/antagonist/world_rules 派生(中性兜底"解决核心危机/世界规则/每次捷径留下可见代价"),**无写死悬疑骨架**(P1-1 旧断言一并失效)。
  - `public_emotion_kernel` seed 从本书 genre/premise/audience 派生,且自带反模板守卫("公共情绪只能服务本书设定,不能变成跨书固定模板""仅绑定《本书》,不得作为其他项目默认设定")。
  - `compliance_boundary_kernel` 是平台级合规(题材无关,每本书都需要)。
  - 四个 `_*_prompt_block` 均 `if not raw: return ""`——作为**可选上下文**注入,planner 可不依赖,非强制骨架。
- **真正的"走到系统"病根**是 P0-3(`golden_finger` 必填槽)+ P0-1(通用 prompt 私货词),均已修。kernel 层无需改动。
