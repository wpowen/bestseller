# 大纲能力（正文前规划）质量根因诊断 与 增量验证优化计划

> 立项：2026-06-29　|　/goal：分析「为什么简介让人不想读、设定无聊且逻辑不通」，是否「干扰过多」拖低大纲质量；制定**增量验证**计划逐步优化到行业顶尖；先计划→再执行→最后给出最佳大纲方法论与最佳示例。
> 遵循《开发与验证标准-feature-lifecycle-20260618》（L1 单测含 no-op / L2 回归 git-stash 归因 / L3 真机零 token 打桩 + A/B）。

---

## 0. TL;DR（结论先行）

**不是「缺能力」，是「管线错形状」。** 框架已经有：①一份高质量 24 章方法论教材（`docs/novel-writing-methodology-course.md`），②成熟的构思期吸引力评估层（10 维简介门 + 5 维书名门 + 9 维 premise 判官 + 双盲 arena，已合并 main），③题材感知的世界观差分推演引擎。**问题不在数据层和评估层，而在「生成器过载 + 评估只是末端打分、不是先验级联 + 设定靠 enrichment 填壳」三处结构错配。**

一句话：**当前是「一次性把 5 件事塞进一个 800-token 调用生成完，再在末端给简介打个结构分」；方法论要求的却是「先验证一句话卖点/发动机能不能钩人，钩得住才逐层下钻展开世界观与结构」。两者形状相反。** 这正是用户三个症状（简介劝退 / 设定无聊 / 逻辑不通）和「干扰过多」直觉的共同根。

## 2. 五大根因（file:line 证据）

### R1 — 故事核心未「先于细节」被验证（应是闸门，实为末端 advisory）
- 一句话卖点对应 `premise_appeal_judge` 的 `concept_strength` 维，但 `config/story_appeal.yaml:46 premise_min=0`、`:58 block_below_bar=false`、`:47 forbid_gated_to_pass=false` —— **整个 appeal 系统 2026-06-24 已降为 advisory**（因 LLM 绝对分不可信、真实爆款"朴实简介"会被 80 线误杀）。
- 故事发动机 `series_engine` 是 `planning_kernel._infer_series_engine()` **规划之后回填（REACTIVE）**，方法论的核心循环（上瘾四步）只在 prompt 里 advisory，从不对大纲做校验。
- **后果**：用户 #1 诉求「不吸引就不展开细节」未实现——系统照常展开全部细节，只在末端给简介打分。可信的相对 arena（`story_appeal.yaml:82-84` 自承是「故事质量硬门」）却被排除在构思回路外。

### R2 — 生成器过载（「干扰过多」假设：**初步证实，待 A/B 定量**）
- finalize 单次调用要 LLM 同时产出 **5 件竞争产物**（title/premise/synopsis/tags/writing_profile），用户 prompt ~4000–5000 token，叠了 **8 层约束 / 25–30 种独立约束类型**（默认母题守卫、金手指设计原则、商业 brief、品类读者承诺、品类反模式、题材 profile、情绪样例、qimao 合约…），其中 **commercial brief 与 golden finger 原则重复注入**（Round1 已给过），最后压进 **800-token 输出预算**（`conception.py` finalize budget override）。
- 这与 `[[prose-prompt-diet]]` 正文层结论同形：**过载 → 回归安全/通用 → 平庸**。
- **后果**：premise 常只分到 ~50 token、synopsis ~100 token，两者都浅；多约束并发挤压 → 设定平庸、卖点钝。

### R3 — 简介评分是「浅层结构代理」，非「真吸引力」
- `blurb_appeal_gate` 全确定性、零 token，测的是「有没有身份+冲突+代价三要素 / 首句≤30字 / 题材词命中 / 反模板」等**结构特征**。结构齐全但无聊的简介照样 ≥80。
- 真能测吸引力的 `premise_appeal_judge`（LLM）是 advisory；唯一可信的相对 arena 不在回路。
- **后果**：恰好复现 2026-06-21 立项文档 TL;DR——「能产出结构完整但没人想点的书」。

### R4 — 设定「无聊/逻辑不通」= enrichment 填壳 + premise-blind 默认 +（少量）preset 兜底
- `outline_field_enrichment._fill_causal_contract`（`:208-237`）：planner 漏填 causal_contract 时**合成**一份——`protagonist_choice == protagonist_desire`（复制）、`cost_or_tradeoff == pressure`（复制）、`chapter_function` 缺则 `"推进卷X主线"`（通用兜底）。**只要 8 个字段非空即通过，从不校验是否构成因果链**（pressure→choice→action→state→cost）。下游门只查「字段在不在/字数够不够」，不查因果 → **看着完整、实则空壳 = 逻辑不通的直接来源**。
- `_fill_target_emotion`（`:240-264`）+ `_fill_golden_hype`（`:290-297`）：planner 漏填时按**章号位置**兜底——黄金章（1-3）一律「爽」、其余「紧张」，**premise-blind**。恐怖/悬疑/正剧/治愈题材会被套错情绪 DNA。（注：是 planner 漏填时的 fallback，非强制覆写；但结构探查估 planner 漏填率 ~50%，故常态触发。）
- `_ensure_complete_profile`：finalize 的 world 稀疏时用 genre preset 兜底 → 通用世界观。
- **注意**：世界观差分推演本身是对的（`world_model_deriver`）；无聊不来自推演，而来自**这些「漏填即兜底」的旁路**绕过了 premise 接地。

### R5 — 无雪花/递进级联（flat batch，错一处全章继承）
- 规划是**扁平批量**：`volume_plan` → 一次 LLM pass 出 10–50 章。**没有 logline→卷 synopsis→章 beat→场景**的逐层下钻，没有「下层对上层取证」的递进收紧。批 1 误读 premise，后续全章继承。
- setup→payoff **生成期不强约束**，只有 `foreshadowing.py` 事后审计；钩子有 `expected_payoff_by_chapter` 字段但无人校验是否真埋。
- 方法论 ch10/ch11 明写的「五层规划骨架 / 四层递进」在代码里**缺位**。

## 3. 统一洞察：架构是「评估 bolt 在过载生成器上」，而非「先验级联」

```
现状（错形状）：
  [过载 finalize：5合1/800token] → premise+blurb（都浅）
        → [扁平批量 outline] → [漏填即位置/preset 兜底 enrichment]
        → 末端：blurb 结构分(≥80?) + 大纲判官(13维)
  appeal 全 advisory，arena 不在回路，发动机规划后才回填

方法论要求（对形状，ch3/4/10/11）：
  一句话卖点(人+欲+阻+代) →〔闸门：钩不住就重做，不展开〕
        → 故事发动机(want≠need/每胜有代价/可复 30 次的核心循环) →〔闸门〕
        → 世界观/筹码/钩子（从发动机长出，接地）→〔闸门〕
        → 雪花递进：卷 synopsis → 章 beat → 场景（逐层取证）→ 伏笔嵌套
```

**修复方向不是「加门」也不是「加方法论」（都够多了），而是把管线掰回「先验级联」并给生成器减负。** 用户的 4 个关注点恰好就是这条级联的 4 段——本计划据此分相。

## 4. 增量验证路线图（每相：目标 / 改动 / A-B 尺子 / 三层验证 / 风险）

> 原则：先建尺子，再动刀；每步 soft/additive、禁用即字节不变；用 A/B 数据决定保留/回滚（教训 `[[opening-jargon-lever-falsified-ab]]`：似是而非的杠杆要被证伪）。

### Phase 0 — 建「大纲质量测量尺」（先决，无尺不改）
- **目标**：一条可复跑命令，对给定 (题材, 描述) 跑构思，输出三组数：①确定性 blurb/title 分，②premise 判官 9 维，③**相对 arena 胜率（对真实爆款双盲）**——后者是唯一可信绝对质量信号。
- **改动**：`scripts/outline_quality_bench.py`（复用 `story_appeal.evaluate_story_appeal` + `premise_appeal_arena`）。支持零 token 打桩跑通逻辑、真 LLM 跑数。
- **验证**：L1 打桩断言三器可调用、字段齐；L3 真机对 5 题材出基线分表。
- **产出**：基线分表（后续每相的 before）。

### Phase 1 — 验证/处置「干扰过多」（de-overload）
- **目标**：证实或证伪 R2。把 finalize 的「5 合 1/800token」拆成 **(a) 故事核心(卖点+发动机)** 与 **(b) 文案(synopsis+tags)** 两段，各自给足预算；去掉 commercial brief / golden finger 的重复注入。
- **A-B 尺子**：当前管线 vs 拆分管线，跑 Phase 0 bench，比 arena 胜率 + premise 9 维。**赢则留，平/负则回滚并记录**（不预设结论）。
- **验证**：L1（拆分函数 + 禁用 no-op 字节不变）/ L2 回归 / L3 多题材 A/B。

### Phase 2 — 故事核心先验闸门（实现「不吸引就不展开」）★用户 #1
- **目标**：`StoryCore` 升为一等产物 = 四要素 logline（人/欲/阻/代）+ 核心循环（升级/关系/谜团，可复 30 次校验）+ want≠need + 每胜有代价。**在世界观/细节展开前**先验：未达线→有界重生 StoryCore（不重生整书）；达线才下钻。
- **给判官以牙**：把**相对 arena** 接进构思回路作为软门（赢率<阈值→重生），替代不可信的确定性 80 绝对线（保留 80 作重生目标线）。
- **验证**：L1 schema + gating 边界 + 禁用 no-op；L3 真机：弱核心被拦+重生、强核心直通，arena 胜率 ↑。

### Phase 3 — 设定去空壳（premise-aware + 因果链校验）
- **目标**：(a) `target_emotion/hype` 兜底改 **premise-aware**（honor `book_spec.target_tone`/题材情绪曲线，非章号位置）；(b) `causal_contract` 从「8 字段非空」升级为**因果弧校验**（choice≠desire、cost≠pressure、function 非通用兜底，否则标 advisory 缺陷并定向修）。
- **A-B 尺子**：大纲判官的 logic_consistency / motivation_chain_clarity before/after。
- **验证**：L1（校验器红/绿 + 恐怖题材不再被填「爽」）/ L2 / L3。

### Phase 4 — 雪花递进级联（替代 flat batch）
- **目标**：`logline → 卷 synopsis → 章 beat → 场景`逐层下钻，每层对上层取证；setup→payoff 生成期强约束（钩子必须在 `expected_payoff_by_chapter` 兑现，否则定向补）。
- **验证**：L1 级联各层 schema + 取证守卫；L3 出一本端到端、伏笔闭环可查。

### 交付 — 最佳大纲方法论 + 最佳大纲示例
- 代码对齐版「最佳大纲方法论」（把 ch3/4/10/11 收敛成可执行 5 段级联 + 每段验收）。
- 用改进管线产出**一份最佳大纲示例**（题材自选），附 arena/gate 达标证据。
