## 1. 诊断（为什么做这些）

调研 DeterminFlow 引擎后，拿它的机制逐条对照本仓已知痛点，并用一个子代理穷举了本仓**所有会让书自动重新开跑的出口**（自愈扫描、worker 终局续跑链、pipeline 内部循环、closure runner、web 僵尸恢复、API、scheduler）。结论：

| 编号 | 病 | 代码证据 |
|---|---|---|
| D1 | 停止只写 web 内存/`projects.metadata`，被流水线整块重写抹掉 | `web/server.py` cancel 注释自述；`projects.metadata` 由 pipeline ORM 整块赋值（`pipelines.py` 多处 `project.metadata_json = {...}`） |
| D2 | `production_paused` **不是**自愈的停止信号 | `self_heal._project_resume_is_blocked` → `gate_registry.project_resume_is_terminally_blocked` → `_TERMINAL_PROJECT_KEYS` 实际只含 `qimao_opening_gate_exhausted` 一个键 |
| D3 | 门禁自动续跑**零预算** | `worker/tasks._handle_generation_gate_auto_continue` 非 replan 分支无条件入队；self_heal 侧的 3 次预算它不读不写 |
| D4 | ARQ 隐式重试不可见 | `worker/main.WorkerSettings` 未设 `max_tries`，arq 默认 5 次，计数只在 Redis |
| D5 | 跑书中途改配置 → 生成端/校验端漂移 | 全仓仅 `quality_evaluation.py:143` 一处 `config_hash`，无开书级冻结 |
| D6 | 判官"没应答"被当成"正文差" | `chapter_llm_quality_judge` fallback 给 0.0 分 + critical issue；多采样中位数把 0.0 一起平均 |
| D7 | 返工成本无归因 | `llm_runs` 有 `logical_role/workflow_run_id`，无章号/门名/修复轮次 |

## 2. 实现

### P1-1 操作者意图独立成表（治 D1/D2）
- 新表 `book_production_control`（migration `0038`）：`desired_state(run|pause|stop)`、`command_serial`（代际号）、`resume_pending`（持久恢复意图）。**流水线只读不写**，从物理上消除覆盖。
- 新服务 `services/production_control.py`：`request_stop/pause/run`、`mark_resume_pending`、`claim_resume_pending`（一次性 + `command_serial` CAS）、`auto_recovery_is_permitted`（**所有自动恢复路径唯一判据**）、`halted_project_ids`（sweep 用）。
- 接入点：
  - `worker/tasks._skip_halted_project_if_needed` → 加在全部 5 个 worker 任务入口。**守卫入口而非 15 个入队点**，任何未来新增的入队路径自动被覆盖。
  - `worker/self_heal.find_stuck_projects` 循环首行按 `halted_project_ids` 跳过。
  - `pipelines.run_progressive_autowrite_pipeline` 卷边界读取，跑动中的书也能停。
  - `web/server._cancel_project_task_async` → 写 `request_pause`；`POST /api/tasks/autowrite` → `_clear_production_halt_async`（显式启动=要跑的意图，防止书永久启动不了）。
- 质量分保护：未知 `desired_state` **fail closed**（当作 stop）；读不到控制行 **fail open**（当作可跑，避免桩/旧书被困死）。两个方向刻意相反，各自对应更小的伤害。

### P1-2 触发器分类的重试预算（治 D3/D4）
- 新模块 `services/retry_ledger.py`：`RetryTrigger{initial,auto,manual,validator,recovery}`；仅 `auto` 消耗预算，`manual/validator` 开新失败链（人/校验介入=重新授信），`recovery` 免费（进程崩溃不该算书的账）。绝对上限 `ABSOLUTE_MAX_AUTO_ATTEMPTS=20`，配置无法调高。
- **计数器与被守卫状态同一 mapping 落盘**（`load_chain`/`store_chain`），2026-07-25 那次计数器被相邻 key purge 抹掉的形状不可能重现（有专门回归用例复现该 purge）。
- 接入 `_handle_generation_gate_auto_continue`：先扣预算再入队；耗尽 → `_mark_generation_gate_budget_exhausted` 落显式终态（清 `generation_gate_auto_retry_needed` 让自愈也不再捞），**没有"再试一次"分支**。
- `generation_gate_budget()` 与 self_heal 共用同一环境变量，两条路不可能被调开。
- `WorkerSettings.max_tries=1`：关掉 ARQ 隐式重试，恢复交给应用层（可观测、有预算）。

### P1-3 配置冻结—核验对（治 D5）
- `services/book_runtime_guard.py`：按部件分别取语义哈希（不是整块）——drift 报告能点名**哪个字段动了**，"有东西变了"不可行动。
- `services/book_contract_snapshot.py`：定义哪些配置算合约（字数带/语言、prompt profile、修复预算、每书 override）。
- 接入 pipeline 卷边界：首卷冻结，此后每卷核验。默认 `audit_only`（本仓每个先硬阻断的门都出过误杀），`enforce` 需显式开。
- **实测修正**：初版把 `writer_prompt_mode` 挂在 `pipeline`（实际在 `generation`）、`autonomous_quality_retrofit_max_attempts` 挂在 `settings`（实际在 `pipeline`），两者都静默返回 `None` 且哈希稳定——**门看着在跑，实际零监控**。已加 `test_every_contract_field_resolves_against_real_settings` 锁死。

### P1-4 成本归因（治 D7）
- `services/cost_attribution.py`：contextvar 环境归因 + `rework_scope()` 给每轮返工一个稳定 id。`llm.py` 落库前一处合并即可覆盖全部调用——避免"漏改一个调用点=静默失去归因"。
- 已接 `deslop_revise`（返工大户）。

### P1-5 判官第三态（治 D6）
- `domain/llm_quality_judge.py`：`JUDGE_INFRASTRUCTURE_FAILURE_CODES` + `infrastructure_failure` / `quality_rejected` 属性。判官有三种结局，不是两种。
- `chapter_llm_quality_judge.judge_chapter_commercial_quality_stable`：中位数**只在真正给出判决的样本上聚合**；全挂则如实上报基础设施失败，不编造 0.0 质量分。

### P2-1A 后验裁决观察员（shadow，默认关）
- `services/posthoc_arbiter.py`：确定性 observer（契约 beat vs 正文 n-gram 证据，`landed/weak/missed` 三档，**weak 表达不确定而非猜**），每条判定附可核验原文片段。
- `arbiter_mode()` 默认 `off`，未知值也回落 `off`——合并本模块不会让任何跑书悄悄多干活。

### P2-2 步骤 0 契约回声诊断
- `scripts/diagnose_contract_echo.py`：只读、固定随机种子、**带同书异章对照组**。

## 4. 实测结论：契约回声假说**成立**

`scripts/diagnose_contract_echo.py` 跑真实成书（92 章 / 2 书）：

| 指标 | 值 |
|---|---|
| 自身重合率（契约 vs 本章正文） | 0.108 – 0.120 |
| **对照重合率**（别章契约 vs 本章正文） | **0.006 – 0.008** |
| mean echo lift | **+0.107** |
| median echo lift | +0.100 |

对照组接近零 ⇒ 排除"只是常用词"的测量假象。**约 17 倍差距，正文确实在复述契约原话**。这为 P2-2「契约→意图」改造提供了实证依据，可进 A/B。

方法学：任何重合率指标必须带同书异章对照，否则数字无意义。

## 5. 默认行为变化（新建书会受影响的）

| 项 | 变化 | 风险 |
|---|---|---|
| 停止书 | 写独立表，自愈/worker/pipeline 三处都认 | 停止真的生效（预期内的行为变化） |
| 门禁自动续跑 | 同一门连续失败 3 次后进显式终态 | 从"无限重试"变为"停下等人"，需观察是否有书过早停下 |
| ARQ 重试 | 5 → 1 | worker 崩溃后不再自动重跑整本；恢复由自愈负责（有预算、可观测） |
| 判官多采样 | 挂掉的样本不计入中位数 | 通过率可能小幅上升（本就该如此） |
| 配置冻结 | audit_only，只记录不阻断 | 无 |
| 后验裁决 | 默认 off | 无 |
