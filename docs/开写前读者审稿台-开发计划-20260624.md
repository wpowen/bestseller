# 开写前读者审稿台 · 开发计划

> 立项：2026-06-24　|　分支：待建 `feat/reader-review-stage`　|　遵循《开发与验证标准-feature-lifecycle-20260618》
> 目标：在**正文生成之前**，把已存在的中间物料（构思 / 大纲 / 场景卡 / 判官分 / 对标）从「工程 JSON」翻译成「读者能读的故事」，让人以读者视角 10 分钟判一本书该不该开写。

---

## 0. 根因（为什么要做）

四条质量根因，详见会话诊断：
1. **唯一可信的对标只评了 200 字简介**（`premise_appeal_arena` 仅跑 blurb），大纲 / 场景卡 / 正文从未进盲评。
2. **自动判官绝对分自标"仅参考"**（`premise_min: 0`、advisory），大纲层无硬信号。
3. **结构闸门被 enrichment 填满字段骗过**（`outline_field_enrichment` 确定性补全 → 空壳也绿灯）。
4. **同质化没有被测量**：去重全是表层（书名 / 人名黑名单 / 单本内 Jaccard / 词频），跨书结构性雷同（系统/金手指→打脸→升级）无人量。

→ 缺的是"正文之前，一个人用读者视角读一遍"的反馈闭环。本特性补这个闭环，并把对标从简介扩到大纲 / 抽样章节（根治 #1）。

---

## 1. 设计原则（soft / additive / 未启用零变化）

- **零 token、确定性优先**：场景卡→人话分镜用确定性模板拼装（从既有字段组合），不引入新 LLM 调用；唯一 LLM 是 arena 盲评（已有注入式 judge，可打桩）。
- **纯读层、不改生成**：本特性只读既有 DB / 物料并渲染，不动 planner / writer / gate 的任何生成逻辑。未访问审稿台时，全栈字节级不变。
- **单一真源**：复用 `build_project_structure` / `build_story_bible_overview` / `build_narrative_overview` / `load_benchmark_report`，不另起数据通道。
- **输入封顶**：分镜只渲染黄金三章（ch1–3）+ 卷纲里程碑；跨书对照只取最近 N=8 本；arena 候选截断。

## 2. 五屏数据契约

| 屏 | 名称 | 数据来源 | 渲染产物 | 读者该问 |
|:--|:--|:--|:--|:--|
| ① | logline 对照台 | `metadata.premise` / `synopsis` + `appeal_reference_blurbs.yaml` 同题材 3 条 + arena win-rate | 本书一句话 vs 3 本真爆款并排 | 放一起像不像会火的书 |
| ② | 引擎体检 | `cast_spec.golden_finger` / `world_spec.power_system` | 金手指/力量体系人话复述 + 套路红标（=系统？=境界流水账？） | 又是个套路吗 |
| ③ | 黄金三章分镜 | ch1–3 `ChapterModel` + `SceneCardModel` | 每场 2–3 句"发生什么+钩子" + 判官分人话化 | 读到这想翻下一章吗 |
| ④ | 节奏曲线 | `volume_plan` 里程碑 + 各章 `hype_type/hype_intensity/primary_emotion` | 爽点分布/输赢节奏/信息揭示时间线 | 节奏有没有塌 |
| ⑤ | 跨书同质化表 | 最近 N 本书的骨架（archetype/金手指型/开篇原型/力量体系签名/ch1钩子型） | 并排表 + 雷同列高亮 | 这本跟别本是不是一个壳 |

| 切片 | 文件 | 内容 | 验证 |

切片 A 无 DB 依赖，先做、先单测。B/C/D 依赖 A。

### 3.1 切片 D 的难点：参照物粒度

arena 现只有 `appeal_reference_blurbs.yaml`（参照"简介"）。扩到大纲/章节需要**同粒度的真实爆款参照**：
- **大纲梗概盲评**：需要"真爆款前3章梗概"参照集 → 新增 `config/appeal_reference_outlines.yaml`（人工填 3–6 本/题材的前三章梗概，120–200 字）。
- **章节开篇盲评**：需要"真爆款第1章开头"参照集 → 新增 `config/appeal_reference_openings.yaml`（首 ~600 字）。
- 复用 `run_appeal_match` 的位置交换 + swap-consistent + 跨家族 judge 骨架，仅替换 system/user prompt 的判断对象（"哪个大纲更想追"/"哪个开篇更抓人"）。
- 候选侧用本书 ch1–3 梗概 / ch1 开篇草稿（若已物化）。未物化时该屏标"待章节生成后可评"，不阻断。

## 4. 三层验证计划

- **L1**：`tests/unit/test_reader_review.py` — 分镜渲染（正常/字段缺失/空场景）、同质化表（无雷同/全雷同/部分高亮）、套路体检（系统型金手指命中/原创金手指不误伤）、assembler no-op（空 project→稳定空结构、字节级可复现）。
- **L2**：跑 `tests/unit/test_web_server*.py` + reader_review 全套；失败 `git stash` 归因。
- **L3**：`scripts/verify_reader_review_e2e.py` — live docker 栈，对一本真实已规划的书调 `_load_reader_review_payload`，零 token（arena judge 打桩返回 fallback），用 `BaseException` 哨兵截获 payload 不 commit，核验 DB 未污染；产出五屏 before/after 能力对比表（每屏渲染出了什么 / 缺什么）。
