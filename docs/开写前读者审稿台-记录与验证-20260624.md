# 开写前读者审稿台 · 功能特性记录与验证报告

> 日期：2026-06-24 ｜ 分支：`feat/reader-review-stage`（待建）｜ 关联：[开发计划](开写前读者审稿台-开发计划-20260624.md) ｜ 遵循《开发与验证标准-feature-lifecycle-20260618》

## 0. TL;DR
把正文之前已存在的中间物料（构思/大纲/场景卡/对标）从工程 JSON 翻译成**读者能读的故事**，新增 `/review/{slug}` 五屏审稿台 + `outline_arena` 把盲评从「只评简介」扩到「大纲梗概/章节开篇」。纯读层、零 token、未启用字节级不变。L3 真机在三本真书上跑通，**抓出并修复一个真 bug**（金手指识别失明），并真实暴露跨书同质化。

## 1. 背景与根因
深度优化后质量/同质化仍差，四根因（共性=只修结构层、没在正文前拦内容层）：
1. 唯一可信对标（`premise_appeal_arena`）只评 200 字简介，大纲/场景卡/正文从未进盲评。
2. 自动判官绝对分自标 advisory（`premise_min:0`），大纲层无硬信号。
3. 结构闸门被 `outline_field_enrichment` 填满字段骗过 → 空壳也绿灯。
4. 同质化无人测量（去重仅表层：书名/人名/单本内 Jaccard/词频）。

→ 缺「正文前一个人用读者视角读一遍」的闭环。

## 2. 设计与落地

| 切片 | 文件 | 内容 |
|:--|:--|:--|
| A 核心纯逻辑 | `services/reader_review.py`（新） | `classify_golden_finger_type`/`detect_genericness`(+`concept_text`兜底)/`render_chapter_storyboard`/`build_sameness_table`/`build_rhythm_curve`/`build_logline_compare`/`build_reader_review`。确定性零 token |
| B Web 装配+端点 | `web/server.py`（改） | `_load_reader_review_payload` + helpers；`GET /api/projects/{slug}/reader-review`；页面路由 `/review/{slug}` |
| C 前端 | `web/novel_reader_review.html`（新） | 五屏 SPA：①logline对照②引擎体检③黄金三章分镜④节奏曲线⑤跨书同质化表 |
| D arena 扩展 | `services/outline_arena.py`（新）+ `config/appeal_reference_{outlines,openings}.yaml`（新脚手架） | 复用 premise_appeal_arena 的 swap-consistent/parse/summary，新增「哪个大纲/开篇更想追」prompt。真实参照语料待手工策展，空语料→pairs==0→「暂无对标」 |

**运行时数据流**：DB（chapters/scene_cards/planning_artifact_versions/project.metadata）→ `_load_reader_review_payload` 装配 → `reader_review.build_reader_review` 渲染 → JSON → 前端五屏。金手指源优先级：cast.protagonist.golden_finger → metadata.golden_finger → premise/logline（兜底 concept_text）。

**设计原则**：纯读不改生成；soft/advisory（红标只提示不阻断）；未启用/空数据字节级不变；输入封顶（只渲染 ch1-3 + 卷纲 + 最近 8 本）。

## 3. 验证

**L1 单测**：`tests/unit/test_reader_review.py`(24) + `tests/unit/test_outline_arena.py`(5) = **29 绿**。含 no-op 字节级不变断言、系统型金手指命中/原创不误伤、concept_text 兜底、空壳场景可见、雷同高亮、空语料 no-op、swap-consistent。

**L2 回归**：`test_web_server.py`+arena+新模块 **178 passed / 1 failed**。失败 `test_design_dossier_html_contains_expected_mount_points` 经 `git stash -u` 干净树复跑**依然失败 → 既有失败、非本次引入**（design_dossier.html 早已改过、断言串过时）。

**L3 真机端到端**：live docker 栈，宿主 Python（含新码）直连 docker DB（`BESTSELLER__DATABASE__URL=…@localhost:5432`），对三本真书调 `_load_reader_review_payload`。零 token（loader 不调 LLM，arena 分读自 benchmark 报告）。零污染（读前读后章节数 100→100/100→100/50→50 不变）。

抓 bug + 修复（L3 价值）：首跑三本金手指全 `未知`——根因 cast.protagonist.golden_finger 实际为 None、金手指藏在 metadata/logline。修 = `detect_genericness` 加 `concept_text` 兜底 + loader 用 metadata 兜底。复跑：

| 书 | gf_type | generic | flags | ⑤雷同度 |
|:--|:--|:--|:--|:--|
| 蚀漏砚(仙侠) | 原创 | False | — | 0.6 |
| 青崖诡事(灵异) | 原创 | False | — | 0.4 |
| 福星甩不掉(都市脑洞) | **系统流** | **True** | **GOLDEN_FINGER_IS_SYSTEM** | 0.4 |

⑤跨书表真实暴露同质化：6 本中 opening_archetype 普遍 `humiliation`、ch1_hook_type 普遍 `sudden_reveal`、golden_finger_type 多本 `系统流/模拟器流`。③分镜从真实场景卡产出可读剧情（如「第1章『断称』场景1，谢迟、谢萤。建立灭镇夜火的现场压力…钩子：谢迟翻出砚台，缺口朝上」）。

复跑命令：见本仓 `BESTSELLER__DATABASE__URL` 指向 docker DB 后 `python3 -m pytest tests/unit/test_reader_review.py tests/unit/test_outline_arena.py`。

## 4. 结果与结论
五屏审稿台端到端可用，正文前可被人以读者视角审。金手指套路检测、跨书同质化、空壳场景在真书上均有效。arena 扩展机制就绪，激活仅需手工填 `config/appeal_reference_{outlines,openings}.yaml` 真实爆款语料（同 blurb 库策展标准）。
