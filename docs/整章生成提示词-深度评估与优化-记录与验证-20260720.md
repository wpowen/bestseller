# 整章生成提示词——深度评估与优化（记录与验证）

日期：2026-07-20
范围：`build_chapter_first_draft_prompts` 的 system prompt（chapter_hybrid 模式下的正文主生产口）
前置：`docs/混合生成模式-整章生成与场景定点修复-设计与开发计划-20260720.md`（本次落地其 M1 的 prompt 部分 + T1.4）

---

## 0. 一页结论

评估发现整章 prompt 的问题**不是"缺规则"，而是"规则来源错了"**：它带着一份手抄的反AI腔副本，其中一条正是 50 轮实验已证伪的黑名单反向激活写法；同时它与自身的项目档案存在直接指令冲突。

四项改造已落地并测试锁定：单一真源替换手抄副本、删除反向激活枚举、补入两个已验证能力块、消除章级/场级指令冲突。另修掉压缩器的一个静默失效面。

**质量结论要诚实**：确定性指标上，修补后的新版优于旧版（AI 味均值 14.7 vs 16.0，内心声音代理 +40%）；但配对盲评按仓库自己的决策协议判为 **inconclusive**（换位一致率仅 33%，判官位置偏置严重）。结构性收益（单一真源、无反向激活、无自相矛盾、压缩器保护）是确定的；**质量提升尚未被证明**，需真机 + 跨题材复验。

---

## 1. 评估：改造前整章 prompt 的五个问题

| # | 问题 | 证据 |
|---|---|---|
| 1 | **反AI腔纪律是手抄劣化副本，不是单一真源** | `anti_ai_voice_discipline.py` 的模块文档明写"Do not re-inline these rules into a prompt; import and render instead"，且记载 rewrite 路径因缺此块产出 76% 正文却带 1.75x 动词 tic / 2.07x 结论先行。整章路径恰恰是 re-inline 的那个反例，只有 3 行手写近似句 |
| 2 | **其中一条正是已证伪的反向激活写法** | 旧约束原文"不要用**手腕发烫、指尖发冷、呼吸一滞、心口一紧**代替…"。`docs/正文AI味-50轮短文对比与修复-20260718.md` 证明黑名单式列举会 prime 它想禁的措辞；该 prompt 产出的书稿实测 手腕×49 / 烫×58 / 喉结×26 / 指节发白×15 |
| 3 | **内心声音授权完全缺失** | `cinematic_pov` 只在 `PROSE_SCENE` 编译里，而整章路径不调用 `compile_methodology`。对标诡秘之主 E1/E2/E3 已确诊：内心标记 3 章全 0（对标 6 处/15 问号）是可读性差距根因，不是文笔差距 |
| 4 | **位置感知块缺失** | `prose_prompt_fusion` 的开篇炸点律（盲评 100%）与中段持续追读律（第50章老读者判官 100%）整章路径零调用 |
| 5 | **prompt 自相矛盾** | system 要求"把所有场景揉进一段连续叙事"，同一 prompt 的项目档案与连载护栏却要求"**每场**必须包含明确目标、阻碍、升级、信息变化和**尾钩**"——照做就是三个迷你弧各带一个小尾钩，正是整章单元要消除的拼接感 |

额外发现（压缩器）：`_PROTECTED_SECTION_MARKERS` 不含反AI腔块。它此前仅靠 "内心" 这个 marker 的**子串巧合**存活；改造后若 header 变化即静默失效——prompt 看着完整，正文悄悄退回 AI 腔。

## 2. 改造清单

| 改动 | 落点 | 依据 |
|---|---|---|
| 手抄副本 → `render_anti_ai_voice_discipline(scope="chapter")` | `drafts.py` chapter-first system prompt | 单一真源设计意图；chapter scope 把配额按模型实际持有的文本量陈述（动词≤4/明喻≤3/度量≤5） |
| 删除身体信号词枚举 | 同上 | 50 轮实验：黑名单反向激活 |
| 新建 `pov_experience_discipline.py`（内心导航 全章≥8 处 / 单一视角 / 机制落地律） | 新模块 + 整章 system prompt | 内心导航=E1/E2/E3 真机；机制落地律=B2 单加胜率 100%（2026-06-29 增量验证） |
| 新增 `render_chapter_position_prose_block()`（只出位置块，不出基础块） | `prose_prompt_fusion.py` | 基础块与反AI真源逐条重复；重复注入=花预算把同一条规则教两遍，且把 system prompt 推向清单感（拐点在第 4 块） |
| 连载护栏 `scope="chapter"`、写作档案 `mode="chapter"` | `writing_profile.py` + 调用点 | 消除第 5 项自相矛盾；义务不删，只从"每场"改为"整章"陈述 |
| 补 5 个受保护 marker | `prompt_compactor.py` | 承重规则的存活不能寄托在别的 marker 的子串巧合上 |
| **补回"对举式定义"禁令（配对改写形式）** | `anti_ai_voice_discipline.py` | **A/B 实测回归**（见 §3）；写成"配对改写"而非裸禁令，遵循 `writer.md` 的 positive_replacements 既有理由 |

体量：system prompt 1729 → 2896 字符。

## 3. 验证

### L1 单测

新增 3 个测试文件、53 项，全绿；prompt 相关回归 1125 项全绿；全量单测 8166 passed（唯一失败 `test_every_auto_repair_code_has_quality_contract` 经 `git diff HEAD` 核实由**他人未提交改动**引入 `SCENE_CARD_PROSE_COPIED` 未注册契约所致，与本次无关，已单独开任务）。

关键守卫：
- 整章路径带反AI腔各条规则 + 章级配额（补上了守卫文件原本漏掉的生成路径）
- 整章 prompt 不得出现身体信号词枚举（防反向激活复发）
- scope/mode 的 no-op 对照：场景路径行为零变化
- 压缩器保护：5 个 marker 已注册 + 各块 header 真能被 `_section_is_protected` 命中

### A/B 实测（3 案例 × 双臂，唯一变量=system prompt）

**确定性指标**（仓库自有检测器）：

| 臂 | AI味均值(低好) | 问号均值(内心声音代理) | 不是X而是Y 合计 |
|---|---:|---:|---:|
| 旧版 | 16.0 | 4.7 | 2 |
| 新版（未修补） | 18.7 | 9.0 | **4** |
| 新版（已修补） | **14.7** | 6.7 | **0** |

**中途发现的真回归**：新版首版 AI 味反而更差，根因是我删手抄行时连"不是……而是……"的显式禁令一起删了，而反AI真源与 slop 黑名单都没有等价条款（`render_slop_blacklist_block` 实测不含该条）。补进真源后 4→0，AI 味均值反超旧版。**这条回归是 A/B 测出来的，不是看代码看出来的。**

**配对盲评**（3 案例 × 换位 × 编辑/读者双视角 = 12 次）：

| 案例 | 旧版加权 | 新版加权 | 换位一致 |
|---|---:|---:|---|
| 血枭 | 6.93 | 8.15 | ✅ |
| 分账 | 8.00 | 7.53 | ❌ |
| 借炉 | 7.60 | 7.80 | ❌ |
| **总体** | 7.51 | **7.83** | **33%** |

按 `docs/experiments/generation-mode-ab-test.md` 的决策门槛：案例胜场 2:1 ✅、加权分差 +0.32 ≥ 0.30 ✅、覆盖保护 ✅、**换位一致率 33% < 75% ❌** → 判定 **inconclusive**。

失败原因是判官位置偏置：3 个案例里有 2 个是"两位判官都选了位置 A"，与实际臂别无关。这与首轮生成模式 A/B 的判官噪声（33%）同型，是判官体系问题而非本次改动问题。

## 4. 诚实的边界

- 质量提升**未被证明**。可宣称的只有：结构性缺陷已修（单一真源、无反向激活、无自相矛盾、压缩器保护），确定性指标方向为正（N=3，边际小）。
- 样本为仙侠 3 章、写手为 Fable、光板任务（无完整物料/台账）。生产 prompt 的 user 段还有约 25 个分节，本次未动。
- 判官位置偏置未解决，任何依赖盲评的结论都会被它稀释。这正好对应横向调研点名的缺口：**多人格读者小组共识过滤**（autonovel 4 人格 3/4 共识）与章节版本 Elo 锦标赛。

## 5. 下一步

1. 用生产管线真机复验（带 entry_state 台账与完整物料），而非光板 prompt。
2. 跨题材回归（都市情感/职场/悬疑），确认不是仙侠单题材效应。
3. 修判官位置偏置（多人格共识过滤），否则质量结论永远停在 inconclusive。
4. 已发现但未处理：`_BASE_FUSION_BLOCK` 仍含"爽点必须写完整四拍"，而 B8 爽点四拍在 2026-06-29 增量验证中是 **0% 胜率（5:0 全败）**。这条在**场景路径**上活着，需单独 A/B 后再决定是否摘除——本次未动，因为改它会影响场景路径行为。
