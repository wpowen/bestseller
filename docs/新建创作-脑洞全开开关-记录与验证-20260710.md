## 1. 诊断（代码证据）

"脑洞中规中矩"的根因不是缺创意机制——概念淘汰赛判官本身奖励新颖（`concept_tournament.py:475` composite 用 `(10-predictable)` 反向 + freshness/unpredictability 权重）。真正把创意往回收的是三道**确定性闸门**：

1. **俗套 KO 误杀**：`concept_tournament.py:427-432` 命中俗套即 `continue` 出局；`_cliche_hits`（:152-171）双词元宽松匹配，真机曾把"修真账房做假功德账"以【老祖+飞升】散词误毙（:157 注释）。
2. **引擎审计偏保守**：`:433-436` 答不出进度条/问题梯即出局，系统性偏向"能讲清的安全概念"。
3. **winner_min 回落均值**：`:503-509` 冠军 composite < 5.5 → 不注入 → 回落 preset 题材众数（显式均值回归）。

## 2. 计划（soft/additive、单一真源、no-op 字节级不变）

新增建书勾选项 `wild_concept`：勾选时松开三道闸门（俗套/审计 **eliminate→penalize** 改罚分、`winner_min` 5.5→4.0、多候选、判官偏新颖）；不勾 = 现状逐字节不变。与 `brainhole`（每章名场面兑现契约）严格区分。

**关键设计**：淘汰赛本就接受 `config=` 参数，但 KO/审计是硬 `continue`（config 无法把淘汰变罚分）→ 在筛选循环加 `cliche_mode/audit_mode` 分支（默认 `eliminate`）。wild 覆盖经 `config/concept_tournament.yaml` 的 `wild_mode` 块深合并，勾选才合并 → 默认零影响。

## 3. 实现（贯通单一真源）

| 层 | 文件 | 改动 |
|---|---|---|
| 模型 | `services/story_enhancers.py` | `StoryEnhancerSelection` 加 `wild_concept: bool = False`（**不进 `is_empty()`**——无每章合同，不渲染空合同头）；加单一真源读取口 `wants_wild_concept(metadata)` |
| 配置 | `config/concept_tournament.yaml` | 基线加 `cliche_mode: eliminate`/`audit_mode: eliminate`/penalty（显式=现状）；加 `wild_mode` 覆盖块（n_candidates 8/winner_min 4.0/penalize/judge_weights 偏 freshness） |
| 淘汰赛 | `services/concept_tournament.py` | 加 `resolve_tournament_config(wild, base)` 深合并（**永不改 lru_cache 基线**）；筛选循环 eliminate→penalize 分支（罚分记 `penalty_by_concept`）；composite 阶段扣罚分 `max(0, composite - penalty)`；export helper |
| 构思 | `services/conception.py` | `ctx["wild_concept"] = bool(user_hints.get("wild_concept"))`；淘汰赛调用点 wild 时传 `config=resolve_tournament_config(wild=True)`，否则 `None`（读基线=现状） |
| 管线 | `services/pipelines.py` | `run_conception_pipeline` 单一调用点：从 `project_payload.metadata` 经 `wants_wild_concept` 线程化进 `user_hints["wild_concept"]`（未勾则 hints 不含该键=现状） |
| 持久化 | `web/server.py:3473`、`cli/main.py:1285,1322` | `is_empty()` 门控补 `or _enhancers.wild_concept`——wild-only 选择不被丢弃 |
| UI | `web/novel_quickstart.html` | Step1 加 `#seWildConcept`「脑洞全开」勾选框（与脑洞引擎同组，默认不勾）；4 处 JS 一致（input/计数/change 监听/`collectStoryEnhancers` payload），字段名 `wild_concept` 对齐后端 |
| CLI | `cli/main.py` | 加 `--wild-concept` 旗标 → `_enhancer_payload["wild_concept"]` |

链路验证：`run_conception_pipeline` 全仓**唯一调用点**在 `pipelines.py`；web 直连（`server.py` `ProjectCreate(metadata=project_metadata)` 含 story_enhancers）与 worker（`tasks.py` `metadata=dict(project.metadata_json)`）两路都让 `project_payload.metadata` 携带 story_enhancers。

## 4. 三层验证

**L1 单测（44 绿，含 no-op 守卫）**：`tests/unit/test_concept_tournament.py`——
- `resolve_tournament_config`：非 wild 返回基线原对象；wild 深合并 judge_weights（freshness 覆盖、click 保留）；**基线 lru_cache 绝不污染**。
- `penalize` 保留俗套候选并打分（composite=raw−1.5）；罚分翻转排名（俗套 raw 8.2−1.5=6.7 输给干净 7.2）；降 winner_min 收留 composite 4.4 大胆概念（基线 5.5 毙之回落）。
- **no-op**：不给 penalize 键（基线）→ CLICHE 仍被 eliminate（`test_default_mode_still_eliminates_cliche`）。
- 接线钉：源码断言 `ctx["wild_concept"]` 读取 + `resolve_tournament_config(wild=True)` + `config=_ct_config` + pipeline `wants_wild_concept` 线程化。
- 背景 sanity：`wild_concept` 字段/`is_empty` 不计 wild/`wants_wild_concept` 读取/wild-only 空合同块。

**L2 回归（352 绿）**：conception_services / conception_mechanism_dedup / conception_session_isolation / pipeline_services / pipelines_session_isolation / cli / project_services / concept_tournament，零回归。

**L3-lite 端到端标志传播（零 token）**：模拟真实链路 metadata → `wants_wild_concept` → `user_hints` → `ctx["wild_concept"]` → `resolve_tournament_config` → 真实 `run_concept_tournament`，同一俗套候选——
- **wild**：`wants_wild=True → cfg=wild → 俗套被毙=False → 注入冠军`。
- **plain**：`wants_wild=False → cfg=base(None) → 俗套被毙=True → winner=None（回落均值）`。
全链标志真的翻转了行为。

**Lint**：无新增真实错误（F/B/E9）——`story_enhancers.py` 的 `Field` F401 为 HEAD 基线既存；RUF001/002（全角标点）是全仓既存容忍噪声（repo 基线 16450 错，`ruff check` 非通过门），我的中文注释与各文件既有全角风格一致。

## 5. 语义澄清

- `wild_concept` ≠ `brainhole`：前者=概念淘汰赛激进度（选择门槛/生成多样性），后者=每章高概念名场面兑现契约。UI 文案已区分。
- 二期（本次不做）：构思期 per-call 温度覆盖（`LLMCompletionRequest` 无 temperature 字段，需动 schema，改动面横跨全角色），待 wild 真机验收后评估。
