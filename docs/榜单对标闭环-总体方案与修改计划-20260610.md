# 榜单对标闭环 — 总体方案与修改计划（2026-06-10）

## 0. 背景与目标

**目标**：让框架产出的小说可以与市场榜单级小说正面对比，并且这个"达到榜单级"是**可测量、可验收、可持续回归**的，而不是内部判官的自我评分。

**核心论断**（来自 2026-06-10 框架审计）：

> 当前框架局部质量控制非常密（15/17 闸门活跃、每章多层判官），但所有质量分都是
> 内部刻度，从未与真实榜单书直接对比过。"确保榜单级"首先是测量问题：
> 没有对标测量，就只能希望达标，无法确保达标。

**新增资产**：`/Volumes/书籍` 书库（1261 本 UTF-8 网文全本，其中 `高评分小说/` 23 本头部榜单校对版全本：《大奉打更人》《将夜》《雪中悍刀行》《大王饶命》《第一序列》《魔临》《亵渎》《永夜君王》等）。

**已有存量（方案直接复用，不重复建设）**：

| 资产 | 位置 | 状态 |
|---|---|---|
| 语料注册表（2246 本，hash+标题） | `.distillation_private/source_registry.private.json` | ✅ 现成 |
| 全库按章切分 | `.distillation_private/source-NNNN/chunks/chapter-NNNN.txt` | ✅ 现成 |
| 方法论蒸馏产物（2026-05 多轮） | `data/methodology_*`、`data/quality_lexicons` | ✅ 现成 |
| 对标样本集（40 本元数据） | `.distillation_private/benchmark_sample_set.private.json` | ✅ 现成但未接判官 |

## 1. 总体方案：把质量定义切换为"对标盲评胜率"

一句话：**所有框架改动用同一把尺子验收 —— 与真榜单书的分层盲评 win-rate。**

```
                    ┌─────────────────────────────────┐
                    │  对标语料库（分层注册表）          │
                    │  T1 头部榜单 23 本 / T2 完本均值   │
                    └──────────┬──────────────────────┘
                               │
        ┌──────────────────────┼──────────────────────┐
        ▼                      ▼                      ▼
  ① 判官校准              ② 成对盲评 Arena         ③ 弃书曲线对比
  真书喂进自家闸门         同题材同章位             前30章逐章弃书
  → 修判官刻度            position-swap            概率曲线 vs 真书
        │                      │                      │
        └──────────────────────┼──────────────────────┘
                               ▼
                    ┌─────────────────────────────────┐
                    │  验收线（config 化）              │
                    │  vs T2 win-rate ≥ 50%           │
                    │  vs T1 win-rate ≥ 35%           │
                    │  弃书曲线 ≤ T2 均值              │
                    └──────────┬──────────────────────┘
                               ▼
              每一项质量欠债的修复 = 改动 → Arena 前后对比
              → 达标 commit / 不达标迭代或回滚（闭环）
                               ▼
                    ④ 自学习：失败归因批次聚合
                    → 方法论补丁提案（人审入 config）
```

为什么贴合实际：

1. **不造新轮子**——语料已切章、A/B 盲评基建已有 50 个脚本验证过模式，Arena 是把两者接起来，不是从零写评估系统。
2. **判官校准放在最前**——如果《大奉打更人》的章节在我们闸门链里拿不到高分，后面所有分数都不可信。这一步成本最低（一天），决定全盘刻度。
3. **验收线可证伪**——"win-rate ≥ X%"能跑出来、能回归，不像"达到榜单水准"这种无法验收的表述。
4. **诚实边界**——文本盲评不输真书 = "榜单级文本质量"；真正"上榜"还含运营/投放/题材时机，框架只对前者负责。

## 4. 风险与现实约束

1. **判官成本**：Arena 一轮（20 对 × 双向 × 3 判官）约 120 次判官调用，用 Haiku 档判官控制成本；校准跑批同理。
2. **真书风格偏移**：T1 多为起点系长篇（2015–2021），番茄短平快风格与其有差异 —— 分层时给番茄向题材配 T2 番茄风格样本，验收线按目标平台选层。
3. **盲评污染**：判官可能识别出知名真书（《将夜》文本可被模型背出）→ 盲评 prompt 去书名/人名化处理 + 用"哪段更可能让读者追更"而非"哪段是名家"。
4. **版权**：真书文本只存在于本地卷与 `.distillation_private/`（已 gitignore），repo 只进 hash 注册表与统计分布。
5. **跑书时勿重启栈**（历史教训，避免重复 self-heal 踩踏）。

### 6.2 关键实验结论

**① 判官校准（113 真书章节）**：LitStyle 判官给框架产出 80 分、给《亵渎》《将夜》级真书 47.5 分 —— 内部判官奖励辞藻密度（框架自己优化的方向），不奖励读者价值；T1(47.5)>T2(33) 相对序正确。⇒ 绝对分不可作达标证据，已加真书锚点修刻度；Arena 相对盲评为主尺。AI 味检测器方向正确（真书 0 vs 框架 4），但会误杀古龙式短句（《情人箭》=100）。

**② 判官自偏好定量**：同一批对战，同源判官（MiniMax）win-rate 比跨家族（DeepSeek）高 0.15-0.20。⇒ 验收一律 `--judge deepseek`。

**③ 首轮达标结果（跨家族判官）**：exorcist-detective vs T1 = 0.625（3W/9T/0L）、vs T2 = 0.833（8W/4T/0L），双线过验收线；弃书曲线 8 章位全程不低于 T2。

**④ 梯度归因（L0 裸模型→L4 全框架，10 章生成 ×双判官）**：
- 裸模型（仅书背景）判官均 41.4、对真书 mini-arena 8/8；
- L1 规划 +1.5、L2 约束 +2.7、L3 工艺 +3.3（判官均 44.7 峰值）；
- **L4 全量 43.2 < L3，AI 味唯一出现在 L4（4.2 万字 prompt）** ⇒ 框架最后一层增量是净伤害，指令稀释复现。
- ⇒ 行动指向：瘦身刀⑥（L3→L4 增量逐块审计裁剪）比继续加层优先级更高，列为 P2 后续主项。

**⑤ 写手模型对比**：qwen3.6-plus ≈ deepseek-v4-pro（46.2）> qwen3.7-max（45.6）> qwen3.7-plus（44.7）> qwen3.6-flash（44.6）。

### 6.3 剩余事项（依赖长时间跑书，已具备自动验证条件）

1. **跑书 A/B 批次**（P2.3-2.5、P3.2 开关验证）：句法节奏/思想内核/爽文融合/oracle 各跑一轮书 —— P4.2 自动回归已上线，每本新书完成即自动出对标报告，验证成本归零。
2. **瘦身刀⑥**：按 ④ 的证据裁 L3→L4 增量（独立审计项，裁前逐闸门核对写手侧指令）。
3. **P4.3 真实市场小流量**（可选，需用户决策）：2-3 本书笔名发番茄回收真实读完率。
