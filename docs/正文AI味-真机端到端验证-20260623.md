## 续：首稿预防真机验证 + mock footgun 根因（2026-06-23 续）

### 根因：首稿"预防"上轮根本没真机测到——写手被静默路由到 mock
- 上轮用 `scripts/ai_flavor_loop_gen.py`（真实写手 `generate_scene_draft`）测预防时返回 **0 词 0 秒**，当时归因为"生成 harness 陈旧/DB 缺数据"。
- **真因**：`generate_scene_draft` 内部 `complete_text(session, settings, ...)` 传的是**入参 `settings`（harness 没传 = None）**，而非 `effective_settings = settings or load_settings()`；`complete_text` 对 None/空 settings **静默退化成 mock 写手**（`model=mock-writer`、空内容）。即"预防验证"测的是 mock，无效。
- 证据：显式 `generate_scene_draft(..., settings=load_settings())` → 真实正文 1099 字、`model=openai/MiniMax-M3`；不传 → `mock-writer` 0 字。

### 修复（additive，零生产风险）
1. `src/bestseller/services/drafts.py`：`generate_scene_draft` 的 writer `complete_text` 调用 `settings` → **`effective_settings`**（生产恒传 settings 故无变化；standalone 调用不再 mock）。
2. `src/bestseller/services/llm.py`：`complete_text` 顶部加根级 guard `if settings is None: settings = load_settings()`——杜绝**任何**调用方漏传 settings 就静默 mock（已确认无调用方/测试依赖 None→mock）。
3. `scripts/ai_flavor_loop_gen.py`：harness 把 `settings` 透传给 `generate_scene_draft`。
- 回归测试：`tests/unit/test_llm_services.py::test_complete_text_resolves_none_settings_to_real_mode`（settings=None → 强制 litellm 不可用 → `provider=="fallback"` 而非 `"mock"`，区分修复前后）。L2：llm+deslop+pipeline **187 passed**。
