# 正文质量 · 增量验证工程流程（TDD 式）

> 目的：在**不动现有框架生产代码**的前提下，建立一套可复现的「测试 → 添加 → 验证 → 决策」流程，
> 从裸模型出发增量加料，判定每一块**该加 / 该删 / 该融合**，最终逼出"最小有效配方"（最优解），
> 再回写框架生产路径（届时走 L1/L2/L3 + A/B）。

## 0. 已确立的前提（前序实验结论）
- 裸模型（minimax-m3 + 一句话）就能写好 → 病根在框架重型 prompt，不在模型。
- tic率/比喻数/否定句数 是**坏指标**（裸写好读版 tic 反而最高）→ 不作主判，仅作红线否决。
- 每个方法论块单看都有正增益，但**堆叠会互相挤压、变成"规则朗读式注水"** → 最优解是"加到拖累拐点就停"。

## 1. 架构：四层解耦
```
标准层 Spec   ── 先行的"测试"：什么算合格 / 什么算更好（红线硬门 + 盲评 rubric + 用户终审）
内容块层 Block ── 候选要素登记表（设定 / 要求 / 方法论），每块独立可开关
评判层 Judge  ── 确定性硬门(单元测试级) + pairwise 盲评(集成测试级) + 用户金标准(验收级)
决策层 Select ── forward selection + 边际增益 + 拖累检测 + 融合检测 → 加/删/融合
```

## 2. 标准层（TDD 的"测试先行"）

### 2.1 红线硬门（确定性·单元测试级，先过才进盲评）
任一不过即判 FAIL，直接淘汰该样本/配方，不进盲评：
- H1 非空且非 ERR/超时；中文字数 ≥ 1800。
- H2 无 markdown 残留泄漏正文（`**`、`##`、行首 `>`、`|表格|`、` ``` `）。
- H3 无标点错乱：引号配对（「」/“”成对）、无 `……。` 混排、无连续 3+ 重复标点。
- H4 无"方法论元话语"泄漏（出现"黄金三章/爽点/钩子/方法论/本章要"等 → FAIL）。
> 红线门是确定性的，等价于 TDD 的单元测试，必须 100% 通过。

### 2.2 盲评 rubric（集成测试级·pairwise）
判官立场固定为"没耐心的番茄/七猫手机读者"，pairwise 比较两配方，维度：
1. 看得懂（机制/处境/人物是否一读即明）
2. 想一口气读下去（钩子与节奏）
3. 没有 AI 腔（不说教、不总分总、不注水）
4. 代入与爽感（动机、智斗、情绪兑现）
- 判官模型：claude-sonnet-4-5（跨家族，避免同源高估）。
- 每对投 **VOTES=5** 票，每票随机交换 A/B 位置消除位置偏差；多数胜。
- 显著性：胜率 ≥ 66%（5票中≥4）记正增益；≤34% 记拖累；其间为持平。
- 降噪：每配方 N=3 采样，取通过红线门的有效篇做代表；关键结论用户复核。

### 2.3 用户金标准（验收级·终审）
每轮把候选代表篇整合进盲评 HTML（含段号），由用户人眼盲评确认方向。
盲评与用户判断冲突时，**以用户为准**，并记录该冲突（用于校准判官）。

## 3. 内容块层（候选块登记表）
| id | 类别 | 摘要 |
|----|------|------|
| B1 | 要求 | 番茄/七猫规则怪谈调性·短句快节奏 |
| B2 | 要求 | 机制落地律：专名首现一句白话点破"是什么+干啥+代价" |
| B3 | 方法论 | 解谜闭环：发现→懂→应对→执行→反馈 |
| B4 | 要求 | 动机前置：开篇立"非做不可"的私人紧迫理由 |
| B5 | 设定 | 本书设定锚点：字灵根/执笔簿/血墨代价 |
| B6 | 方法论 | 章末钩子：结尾留强钩 |
| B7+ | 方法论(重) | 黄金三章合同 / 爽点四拍 / 世界观锚点 …（压力测试用，逐块验证拖累拐点）|

## 4. 测试流程（如何评一个配方）
1. 用配方 = 一句话设定 + 已选块文本，生成 N=3 篇（写手固定 minimax-m3，超时自动重采）。
2. 每篇过红线硬门 → 取有效篇。
3. 配方代表篇 = 有效篇中（按需）最长/随机一篇。

## 5. 添加流程（如何引入候选块）
- 每块写成**一句可执行的写作指令**，挂在 user prompt 的【额外要求】区。
- 块必须正交、单一职责（一块只表达一件事），便于独立验证与融合。
- 新块先登记进登记表（类别 + 摘要 + 文本 + 来源）。

## 6. 验证流程（greedy forward selection + 边际/拖累/融合）
1. 当前配方 = L0（裸）。
2. 每轮：对每个未固化候选块 b，生成「当前配方 + b」，pairwise 盲评 vs 当前配方。
3. **加**：选边际胜率最高且 ≥66% 的块固化。
4. **删**：在当前(更强)配方上胜率 ≤34% 的块淘汰（即使它单加到裸模型时为正——这是叠加拖累）。
5. **融合**：若两块单独都正、且合并成一句后代表篇盲评不降分且更短 → 合并为一块（降 prompt 负载）。
6. 重复，直到无块能再显著提升，或连续 2 块拖累 → 停。
7. **拖累拐点压力测试**：把框架里更重的块（B7+）逐块加到最优配方上，记录从第几块开始边际转负 → 得到"加料收益曲线"。

## 7. 决策规则（加/删/融合 判定表）
| 情形 | 判定 |
|------|------|
| 边际胜率 ≥66% | 加（固化） |
| 34% < 胜率 < 66% | 持平：保留更短表述者；倾向不加（省负载） |
| 胜率 ≤34% | 删（叠加拖累） |
| 两块都正且合并后不降分、更短 | 融合 |
| 单加正、叠加转负 | 删（典型注水块，如 B3） |

## 8. 最优解判定与停止条件
- 停止：再无块显著提升，或连续 2 块拖累。
- 产出：①最小有效配方(prompt 文本) ②加/删/融合证据表 ③对应正文样本 ④加料收益曲线。
- 可迁移性：最优配方用 kimi / claude 复跑确认非单模型过拟合。

## 9. 工程实现与可复现
- 实验器：`scratchpad/ladder_runner.py`（配置驱动：BLOCKS / 写手 / 判官 / N / VOTES）。
  - 子命令：`round`（一轮 forward）、`gate`（红线硬门体检）、`html`（盲评页）、`report`（汇总）。
- 结果落 `output/prose-ladder/`：每配方样本 + 每轮 pairwise 记录 + 证据表（JSON），可重算。
- 所有随机用固定种子记录；判官调用失败自动重试；坏样本自动重采并标记。

## 10. 风险与降噪
- 判官噪声：pairwise + 5票 + 随机位 + 跨家族 + 用户终审；记录 winner/reason 不一致的票以校准。
- 单模型过拟合：定稿配方多模型复跑。
- 配额/限流：每调用超时 + 重采 + 独立落盘 + 失败可断点续跑。
- 红线门防止"有内容 vs 空"这类污染（前序第一轮曾因 base 超时空样本得出 100% 假胜）。
