# 混合生成模式（整章生成 + 场景定点修复）——设计与开发计划

日期：2026-07-20
状态：待评审
前置证据：`output/generation-mode-ab/20260720-initial/report.md`、`docs/experiments/generation-mode-ab-test.md`

---

## 0. 一页结论

两轮独立证据同向证明：**在同一套章节合同下，整章一次生成的正文质量优于逐场景生成再拼装**。质量分水岭不是生成模式本身，而是**状态连贯性**——逐场景模式每个写手只见上一单元末 600 字，已确立事实（人物已登场、事件已发生、道具是什么）掉出窗口后被重新发明，制造出重复开场、人物二次介绍、状态翻转等硬伤；整章生成天然全程持有状态。

因此本计划把生成主单元切换为**整章生成**，把场景机制重新定位为**规划约束 + 定点修复粒度**：

```
场景卡(规划约束) → 整章一次生成 → 确定性分段 → 分段打分
                                        ↓
              章级门禁 ← 拼回 ← 只重写失败段(带上下文)
                 ↓
          best-of-N 选优晋升
```

不删逐场景路径（保留为 fallback），不动跨章 seam 机制，按书灰度切换。

### 1.1 证据一：真机 A/B（写手 minimax-m3）

### 1.2 证据二：Fable 12 判官独立盲评

同批样本，3 案例 × 正/反位置 × 编辑/读者两视角，换位一致率 **100%**：

| 案例 | 多场景 | 整章一次 | 票型 |
|---|---:|---:|---|
| 停电以前 | 4.83 | 6.90 | 整章 4:0 |
| 账本归谁 | 6.89 | 7.80 | 整章 4:0 |
| 这一炉算谁的 | 7.86 | 6.66 | 多场景 4:0 |
| **总体** | 6.53 | **7.12** | 整章 8:4 |

分差 +0.59，超过实验决策线 0.30。

### 1.3 机制（已逐条 grep 核验）

多场景版硬伤全部是"状态掉窗"的产物：
- 停电以前：老杜二次登场被当陌生人重新介绍；首批货"拿破仑"漂成"桃酥"；停电状态无端翻转。
- 账本归谁："林望不是一个人来的"开场句逐字出现 2 次；钥匙锁在它要开的抽屉里；凭空冒出未设定的"老二/二嫂"；一章被拉成两天。

**反例证明机制**：唯一整章版自己破状态的案例（称"低筋面粉"、和面用"高筋面粉"）同样 4:0 输。判官奖励状态连贯，不奖励生成模式。

### 1.4 对既有认知的修正

生产管线的场景级门禁/重写选优（76% 成稿来自 scene_rewrite）本质是**修复拆场景自己制造的病**的补偿机制，不能当作多场景模式的质量优势引用。接缝补丁（entry_state 台账、splice 门、跨场景去重）是在追赶结构性制造出来的缺陷——正确做法是从源头不制造。

## 2. 目标与非目标

### 目标

1. 新书默认生成单元 = 整章；场景卡保留为规划约束（节拍/必演事件/cut_point）。
2. 修复粒度 = 段：章级验收失败时只重写失败段，不整章 re-roll、不逐场景重跑。
3. 补齐整章路径自己的短板：章内状态连贯守卫、必演事件顺序确定性检查、字数地板。
4. 成本红利落袋：每章 LLM 调用从 9+ 降到 3 以内；消除场景粒度 churn/死锁事故面。
5. 按书灰度、可一键回滚。

### 非目标

- 不删除 scene_by_scene 管线（保留 fallback）。
- 不动**跨章** seam 机制（entry_state 台账、章缝续接、黄金三章合约）。
- 不改判官体系、章级 L4/L5/L6 门禁语义。
- 不在本计划内做前端新建书 UI 选项（先走 book-level 配置，UI 后续单独排期）。

## 4. 目标架构设计

### 4.1 生成层：整章为主单元

- 新增配置 `generation_unit_mode: "scene" | "chapter_hybrid"`（全局默认 + per-book override）。
- `chapter_hybrid` 下 `_chapter_first_requested` 恒为 True，**解除 `chapter_first_max_chapter_number=3` 章号限制**（仅该模式下解除；`scene` 模式行为完全不变）。
- `build_chapter_first_draft_prompts` 保持"场景卡=内部节拍、禁场景标题/契约字段泄漏"的现有约束（`drafts.py:8985-9002`）。
- prompt 预算：沿用 compactor 10k 帽与受保护块清单；新增 prompt 尺寸遥测（字符数落 trace），并加回归测试断言**反AI腔纪律块在整章路径压缩后存活**（compactor 潜伏雷防复发）。

### 4.2 分段层：三级锚点降级策略

整章正文是连续叙事，cut_point 未必逐字出现（历史教训：signature_image 整句 fuzzy 永不匹配 → 无限 churn）。分段只用于**修复定位**，永不因分段失败毙章：

1. **T1**：`chapter_prose_segmenter` 现有 cut_point 模糊匹配。
2. **T2**：必演事件 marker 定位（复用 `generation_mode_ab.py` 的 marker position 法：每场景合同的 required_events 词组在正文中的最早命中位置作为段界候选）。
3. **T3（兜底，fail-open）**：按段落数近似 N 等分。

段 span 附带前后各一个自然段的重叠上下文，供修复时衔接。

### 4.3 评审层：段级打分复用场景评审

- 每段套用对应场景卡合同调用现有 `review_scene_draft` 四维打分（hook/show-don't-tell/感官/冲突/情绪/payoff）。
- 段级 verdict 只产生**修复指令**，不独立毙章；最终裁决权仍在章级 L4/L5/L6 门。
- 开篇章继续豁免推进轴（`_is_opening_chapter` 守卫沿用）。

### 4.4 修复层：段定点重写

新增 `rewrite_chapter_segment`（落点 `reviews.py`，以 `_try_localized_chapter_first_opening_repair` 为模板泛化到任意中段）：

- 输入：前文尾段 + 失败段全文 + 后文首段 + 该段场景卡合同 + 失败 findings + `render_anti_ai_voice_discipline(scope="scene")` + slop 黑名单。
- 输出约束：只写该段正文；首尾句必须与给定前后文自然衔接；禁复述前后文。
- 拼回后跑确定性 splice 校验：无场景标题/契约字段泄漏、章字数增量在带内、跨段近重复检测（复用 `deduplication.py` 现有 detector）。
- **预算**：每章段重写上限（默认 4 次，配置化）；耗尽 → 整章 re-roll（上限 2 次）→ 触顶走 4.5 选优，绝不无限 churn（历史教训：总预算默认 0=无界）。

### 4.5 选优层：章级 best-of-N

- 把 `_promote_best_scoring_scene_draft_on_stall` 的逻辑做章级版：所有整章草稿版本按章级 QualityScore 降序，触顶时晋升最高分版本并打 `auto_accepted_with_debt` 标（沿用现有债务标机制），而非无脑用最后一稿（历史教训：重写耗尽用最差稿）。

### 4.6 新守卫（整章路径短板补齐）

| 守卫 | 形态 | 失败语义 |
|---|---|---|
| 章内状态连贯 critic（新 `chapter_continuity_critic.py`） | 单次 LLM 审读：道具/数量/人名/物理状态/时间的章内前后矛盾，输出 JSON findings | **advisory**，findings 喂给段修复指令；绝不单独 block（吸取 NAMING raw-severity 绕过 audit_only 的教训，走 `l6_write_gate` 统一映射） |
| 必演事件顺序确定性检查 | 移植 `generation_mode_ab.required_event_order` marker 法进章级验收 | order < 1.0 时产出定位到段的修复 finding，advisory |
| 字数地板 | `count_zh_chars` ≥ 章 min（1800，floor-safe 沿用 2400 档配置） | 不足 → 对最薄段做一次扩写 pass，仍不足按现有 floor 流程处理 |

### 4.7 与现有机制的关系

**保留不动**：跨章 seam 全套（`entry_state_ledger`、`chapter_seam`、黄金三章）、章级 L4/L5/L6、判官体系、Mode B 桥（已是整章）。

**降级为 advisory（仅 chapter_hybrid 书）**：章内接缝专用门（`chapter_splice_coherence_gate`、跨场景换皮检测在"整章生成"场景下命中率应趋零，保留检测上报、不 block）。

**保留为 fallback**：scene_by_scene 全管线，per-book 一键切回。

**事件/前端兼容**：段级评审/修复事件映射到现有场景事件 schema（scene_index=段序），进度可视化无需改前端。

## 5. 验证计划

### M0 决策门（默认切换的硬前提，可与 M1 并行开发）

1. **题材回归**：`build_default_cases` 扩玄幻、都市情感、非悬疑职场各 3 组，复用既有 runner 与决策门槛（≥2/3 案例胜出、Δ≥0.30、换位一致率≥75%、覆盖保护）。产物落 `output/generation-mode-ab/<date>-genre-regression/`。
2. **生产级 prompt 复验**：测试书上用真实管线各生成 3 章（`chapter_first` 显式传参 vs scene 默认），带 entry_state 台账与完整物料，盲评 + 确定性指标复核结论不翻转。

**任一不达标 → 不翻默认，混合模式只作为可选模式存在。**

### L1 单测（新增，随各任务落地）

- 模式路由：显式传参 > per-book > 全局；`scene` 模式行为零变化（no-op 对照）。
- 分段三级降级：cut_point 命中/仅 marker 命中/全不命中三态；分段失败绝不抛异常毙章。
- splice 校验器：标题泄漏/字数越带/近重复三类红测。
- 事件顺序检查：乱序/缺失/单事件边界。
- continuity critic：JSON 解析容错（复用 pairwise 恢复法）；findings 只产 advisory。
- 章级 best-of-N：多版本取最高分、非最后一稿；债务标正确。
- 预算耗尽路径：段重写 4 次 → re-roll 2 次 → 选优晋升，全链无 churn。
- 回归守卫全绿（反AI腔、跨书泄漏、既有 76+ 项）。
- 单测显式 `env={}`，禁止隐式读机器 `.env`；**禁止连生产库**。

### L2 归因

每个行为改动 git-stash 前后对照，确认差异只来自本改动。

### L3 真机（依 `dev-verification-standard`）

1. 新开测试书 A（chapter_hybrid）+ 对照书 B（scene，同一构思镜像），live 栈零打桩。
2. 检查点分段验收：构思 → 大纲 → ch1-3 → ch10 结项，每检查点先验 spine 再验正文。
3. 验收指标:每章调用数/tokens、AI 味硬检测、字数带内率、段修复触发率与命中率、章级门一次通过率、盲评（匿名多判官 + 换位）。
4. 运维纪律：rebuild web+worker 后起书；跑书期间不重启栈；测试书用 `focus_` 前缀暂停原因管理。

## 7. 风险与回滚

| 风险 | 概率 | 缓解 |
|---|---|---|
| 整章模式章内状态自破（低筋/高筋类） | 中 | M1 continuity critic + 段定点修复闭环 |
| 分段锚点全不命中致修复定位粗糙 | 中 | 三级降级 + fail-open；粗 span 只影响修复精度不毙章 |
| 必演事件顺序漂移 | 中 | T1.2 确定性检查 + 段修复 |
| 整章欠产（<floor） | 中 | T1.3 扩写 pass + floor-safe |
| 生产 prompt 下结论翻转（AB 光板高估场景劣势） | 低-中 | M0.2 复验是默认切换硬前提 |
| 隐藏的 scene-only 假设（production_state sweep、审稿台等消费场景记录） | 中 | T2.7 事件映射 + M4 真机全链验证；chapter_first 已被 Mode B 长期使用可部分佐证 |
| 题材泛化失败 | 中 | M0.1 三题材回归是决策门 |
| 判官/评审对段粒度阈值不适配 | 低 | 段 verdict 仅产修复指令不毙章，阈值可后续校准 |

**回滚**：per-book `generation_unit_mode=scene` 一键切回；scene 管线全程保留且零改动（T2.1 的 no-op 对照测试保证）。

## 8. 运维与部署注意

- `src/` 与配置是 baked：M1/M2 每批改动需 rebuild web+worker；**勿在跑书时重启栈**（self-heal 踩踏史）。

## 9. 决策记录

- 为什么不直接全量切整章、删场景管线：证据只覆盖 1 题材 3 案例 + 光板 prompt；场景管线是唯一回滚路径；在产旧书不迁移。
- 为什么修复粒度选"段"而不是"重跑场景"：重跑场景=回到三个互相看不见的写手，重新制造接缝病；段修复在整章语境内做局部替换，状态基座不动。
- 为什么 continuity critic 是 advisory：block 路径双轨不一致的教训（raw severity 绕过 audit_only）；且 LLM critic 有误报率，硬毙会复刻 NAMING 误报毙书事故。
