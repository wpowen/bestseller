# 规划产物可读化重设计 · 功能特性记录与验证报告

> 日期：2026-06-25 ｜ 分支：待定 ｜ 关联：设计审查页 `/design/{slug}` ｜ 遵循《开发与验证标准-feature-lifecycle-20260618》

## 0. TL;DR
把 `/design/{slug}` 设计审查页的「规划产物」tab 从 **原始 JSON 墙** 重写成 **按类型的人话卡片视图**（`_meta` 折叠、原始 JSON 收进底部折叠），并在 tab 顶新增 **开写前质量体检面板**（复用 metadata 里已有的 prewrite 就绪度 / 商业化判官 / 各门禁报告）。纯读层、零 token、未访问时字节级不变。

> **二轮迭代（同日）**：首版通用 key/value 渲染仍是「开发者视角」——字段全摊、原始 key、无层次（cast 主角 38 字段全列即一面墙）。改为 **按产物类型的方法论级策展视图**（见 §2.1）：每类只露该看的维度、配「看点提示」、定制版式（力量体系画阶梯 / 世界规则卡片 / 人物档案卡 / 情绪链卡片），其余字段折叠。先用真实数据出 `show_widget` 高保真样稿与用户对齐方向，再落地。

## 1. 背景与根因
用户要「清晰明了地查看最近这些规划产物、评估质量」。现状根因：
- 每个 artifact 点开后是 `JSON.stringify(content, null, 2)`（[novel_design_dossier.html] `loadArtifactContent` / 构思产物内联），一面 JSON 墙；
- 一半是 `_meta` 噪音（input_hash / workflow_run_id / methodology_lineage）；
- premise 正文、kernels、hook_spec、商业化 brief 只在这个 JSON tab 里能看到；
- 「评估质量」无抓手——metadata 里其实已有 `prewrite_readiness_report`（score/passed/warnings/capability_snapshot）、`commercial_planning_llm_judge`、`opening_quality_planning_gate_report` 等判官/门禁结果，但没被呈现。

## 2. 设计与落地

| 切片 | 文件 | 内容 |
|:--|:--|:--|
| 后端·质量抽取 | `services/design_quality.py`（新） | `build_design_quality_reports(metadata)`：把异构的判官/门禁报告归一化成 reports[] + capability_snapshot + headline（score/passed/warn/block + verdict_class）。纯函数 |
| 后端·接线 | `web/server.py`（改） | `_load_project_design_dossier_payload` 增 `quality_reports` 字段（additive，未访问零变化） |
| 前端·可读渲染 | `web/novel_design_dossier.html`（改） | 新增 `renderArtifactReadable`（递归人话卡片：标量→文本、标量数组→chips、对象数组→卡片、`_meta`/原始JSON 收进折叠）+ `renderQualityPanel`（评分/就绪 badge/能力快照/逐报告 + 警告阻断明细）；`loadArtifactContent` 与「构思产物」内联改用可读渲染 |
| 测试 | `tests/unit/test_design_quality.py`（新）+ `test_web_server.py`（改） | 见 §3 |

**设计原则**：纯读不改生成；soft（仅呈现，不阻断）；未访问字节级不变；`_meta` 与原始 JSON 不丢（收进折叠，power user 仍可看）。

### 2.1 按类型方法论级策展视图（二轮）

| 切片 | 文件 | 内容 |
|:--|:--|:--|
| 后端·呈现规格 | `services/artifact_view.py`（新） | `build_artifact_view(type, content) → {title, hint(看点), has_spec, sections[]}`。覆盖 15 类产物，每类的字段选择即方法论（world_spec=力量阶梯+规则+势力；cast_spec=主角档案卡只露金手指/动机/致命缺陷/恐惧/秘密/弧光，藏 32 噪音字段；book_spec=戏剧问题+系列引擎+叙事线+反派阶梯；emotion_kernel=情绪链+炸弹契约+共情契约…）。块类型：prose/callout/fields/cards/chips/ladder。未知类型走 curated fallback（藏 provenance 噪音）。纯函数 |
| 后端·接线 | `web/server.py`（改） | `_load_project_design_artifact_payload` 增 `view` 字段 |
| 前端·通用绘制 | `web/novel_design_dossier.html`（改） | `renderArtifactView(view)` 统一绘制各 block kind + 看点提示；`loadArtifactContent` 优先用 `data.view`，无则回退通用 readable |

**方法论锚定**：字段名本身就是框架方法论（`dramatic_question`/`series_engine`/`anti_commonsense_hook`/`emotion_chain`/`bomb_contracts`/`capability_axes`…）；策展=挑出每类产物在框架里"该被人读来判设计好坏"的维度，配中文友好标签 + 看点提示。

### 2.2 列表重做为「设计阅读菜单」（三轮）

用户反馈：点开后的内容已可读，但**产物列表本身**仍是开发者工作台（统计格子 / 搜索 / 分面 / 类型 slug `book_spec` / `v1`/`approved` 徽章 / "展开后查看原始 JSON"），看着乱、不像给人读设计的入口。

改动（仅前端 `novel_design_dossier.html` 的 `renderArtifacts` + CSS + `loadArtifactContent`）：
- **按阅读顺序分组**（立意与卖点 / 世界观 / 人物 / 剧情结构·卷纲章纲 / 方法论内核 / 开写前体检），非技术 phase。15 类全覆盖、无遗漏（node 模拟核验）。
- 每行只剩**友好名 + 一句看点 + 极淡版本号**；砍掉类型 slug、approved 徽章、JSON 话术。
- **点哪展哪、就地自动加载**（`loadArtifactContent` 改为按钮可选、id 从 `<details data-artifact-id>` 取；复用 `toggle` 监听）。
- 统计/搜索/分面/全版本/编辑/判官评审/榜单对标 **收进一个 `高级筛选 / 原始工作台` 折叠**（能力不丢）。
- 顶部保留质量体检面板。

先用真实数据出 `show_widget` 阅读菜单样稿与用户对齐（默认全收起、点哪展哪），再 port。L3：rebuild web 上线后核验阅读菜单代码在、cast/world view 可加载、/design 200、15 类分组全覆盖。

### 2.3 构思产物也走 view + 评分卡（四轮）

用户点开「构思产物 → story_appeal」仍是深层嵌套 JSON dump——根因：构思产物（`story_appeal`/`hook_candidates`/`commercial_brief`/`concept_methodology`）从 metadata 内联，**没走 `build_artifact_view`**，仍用通用 readable。修：
- `artifact_view.py` 增这 4 类 builder；`story_appeal` 是评分报告 → 新增 **`scorecard` 块**（grade/total + 维度行 `label 得分/权重 理由`，藏 evidence/key 噪音），渲染成 3 张评分卡（简介/书名/立意）+ 综合 + 改进建议。
- dossier payload 增 `conception_views = {key: build_artifact_view(key, value)}`；前端构思产物行改用该 view（无则回退 readable）。
- 前端 `renderAvBlock` 增 scorecard 绘制 + CSS。
L1 +4 测试（scorecard/hook_candidates/commercial_brief），L2 154 passed，node 渲染 story_appeal 评分卡可读，rebuild 上线核验 conception_views 四类全在。

## 3. 验证

**L1**：`tests/unit/test_design_quality.py` **7 绿**（no-op 字节级不变 / prewrite 驱动 headline+snapshot / blocking→fail / 0–1 分归一化为百分 / 字符串状态推断 passed / 缺失空报告跳过 / 按 spec 排序）。`test_web_server` 的 dossier 挂载点断言更新为验证新结构（`renderArtifactReadable`/`renderQualityPanel`/`artifact-readable`）后绿。ruff All checks passed。

**L2**：`test_web_server.py` + `test_design_quality.py` **144 passed / 0 failed**。原先唯一失败 `test_design_dossier_html_contains_expected_mount_points` 断言一条文件里早已不存在的过时串（上一会话经 `git stash -u` 干净树复跑确认为**既有失败**）；本次因重设计该 tab，将该断言更新为验证新渲染结构，失败消除。

**L3（离线·真实数据）**：因 web 容器源码是 **build 时 baked**（`docker-compose.yml` x-volumes 仅挂 docs/output/artifacts，不挂 src），且当时 `custom-xuanhuan-1782362636` 正在 web 进程内 autowrite，**不重启 web**（遵循「跑书时勿重启栈」）。改为：
- 后端 `build_design_quality_reports` 在宿主直连 docker DB 跑真书 `custom-xuanhuan-1782362636` → payload 含 7 份报告、headline score 95/passed、capability_snapshot 齐。
- 前端 `renderArtifactReadable` / `renderQualityPanel` 用 **node + 真实 world_spec 内容 + 真实 quality_reports** 离线执行：可读输出 24961 字符、含「力量体系」标签 + `_meta` 折叠 + 原始 JSON 折叠；质量面板含「开写前质量体检」+ 95 分 + 就绪 badge + 商业化判官报告 + 能力项。去标签预览证实世界规则呈现为「▸诡道留门／说明／剧情后果」式卡片（人话可读，非 JSON）。
- `node --check` 全脚本语法 OK。

**上线说明**：源码 baked → 改动需 `docker compose build web && docker compose up -d --no-deps web` 才在浏览器生效；该操作会中断 web 进程内正在跑的 autowrite，故**延后到该书写完或用户同意中断**再执行。

## 4. 结果与结论
「规划产物」tab 从 JSON 墙变为人话卡片 + 质量体检面板，可在正文前清晰查看并据判官/门禁评估质量。离线真实数据验证通过；上线只差一次 web rebuild（待避开在跑的书）。
