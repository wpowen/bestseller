## 二、全景结论（五条）

1. **格局**：inkos（7.9k，4 个月冲起的写作 OS）与 AI_NovelGenerator（5.6k，弃养）双头；中间 1k-2k 星的中文全自动管线三家（AI-Novel-Writing-Assistant / ainovel-cli / Long-Novel-GPT）；gpt-author 一代单 prompt 路线已全部死亡；学术界 2026 年重心从"生成框架"转向"**评质量/选稿**"（reward model、人类分布百分位、一致性 bug 检测）。
2. **全行业无一家拿得出"质量好"的公开证据**。12 个项目里只有 autonovel 有完整成书+逐章分数账（英文 79k 词）；号称 3000 章/127 万字/百万字的全部零公开文本。中文赛道的"平台连载级产出证据"完全空白。
3. **"确定性门禁+状态回写"路线（我们、天命、inkos、Novel-OS）全部停在"事实连贯"层**。事实不穿帮 ≠ 好看。inkos 37 维审计照样被用户实测出"越写越滑回 AI 味"（Issue #112）——纯 prompt 注入的文风约束长程必衰减，这与我们 M3 大 prompt 服从性问题同病。
4. **质量层是开放战场，best-of-N+盲评选稿全行业空白**。四个同构项目全部没有多路生成对比选稿；唯一近似物是 inkos 的"修订轮最优快照回滚"。谁先把选稿闭环做实，谁就有差异化。
5. **结构复杂度与产出质量不成正比**。我们 34 万行/94 gate/15 judge 是全行业最重的质量结构（没有之一），但和其他家一样拿不出质量证据——**病不在检测不够多**。

## 三、我们框架的问题评估（外部对照互证）

### 3.1 结构层：全面领先，无需自卑

对照表逐维打勾：长程一致性（canon/timeline/snapshot/ledger 族 + pgvector RAG）、合约体系（chapter/scene contract）、软硬分层+追债、方法论资产化、可恢复工作流、多格式导出与发布调度——每一维都超过对比项目的最强者。天命的 15 维快照 ≈ 我们 canon+ledger 的子集；inkos 三层记忆 ≈ 我们 PG 单一真值源+投影的变体。

### 3.2 真正的病：内部诊断与外部证据完全互证

内部 `docs/plans/2026-07-10-novel-quality-remediation-master-plan.md` 确诊的五根因，每一条都能在外部找到镜像：

| 内部五根因 | 外部互证 |
|-----------|---------|
| ① 最终 prompt 无硬预算/冲突裁决 | inkos Issue #112：大 prompt 文风约束长程衰减是行业通病，靠堆 prompt 治不了 |
| ② accept_on_stall 不选历史最佳稿 | inkos 的"最优快照回滚"正是此问题的现成解 |
| ③ is_current 语义让坏稿污染正典 | 天命"回写数据先过门禁再入账"正是此问题的现成解 |
| ④ best-of-N 靠字数/格式启发式，判不出追读欲 | StoryReward 行业级证据：通用判官/RM 系统性偏爱 AI 味稿——绝对分选稿在方法论上就是错的，必须配对盲评 |
| ⑤ 缺人工盲评校准的发布门禁 | WebNovelBench 提供了现成的"人类分布百分位"基准形态 |

### 3.3 我们特有的自伤史（外部项目没有的病，因为它们没跑到这个规模）

记忆中的实证：修订 churn（福星 11 遍、signature_image 无限 reset）、gate 误毙整书（NAMING/LINE_GAP/strict 硬抛自伤链）、题材盲硬编码（探案词毙修仙）、跨书同质化（债务框架五个非生成面藏私货）、判官绝对分不可信。**这些都是"规则很多但缺纪律层"的症状**：verdict 映射被 LLM 拿着、rubric 随被测漂移、修订无止损、检查器无题材激活表。ainovel-cli 的工程纪律（"统计归代码，裁定归 LLM"、确定性 Finding 才有资格阻塞门禁）是同路线里最值得抄的姿势。

## 四、可借鉴机制清单（按性价比排序）

1. **全书级文体统计器**（ainovel-cli `stylestat`）——句式模式章均次数、跨章逐字重复句、章末短句收尾占比、开篇时间词率，纯确定性零 LLM 成本。直击"单章判官对跨章文风固化天然失明"——我们有 deslop 词法层但缺全书级句式回归尺。
2. **修订止损三件套**（inkos `chapter-review-cycle.ts`）：分数门槛 + **净提升 ≥ε 才续修** + **最优快照回滚** + parseFailed 禁止触发自动修订。直击我们的 churn 史。
3. **判官纪律**（ainovel-cli）：判官只打分，verdict 由代码映射（≥80 pass / 60-79 warning / <60 fail）；rubric 版本化快照防"裁判随被测漂移"；判官必须读原文禁止只看摘要。
4. **autonovel 修订闭环四件**：对抗编辑（"砍500词"判官→分类切割清单，OVER-EXPLAIN+REDUNDANT 占 58%）；章节版本 Elo 锦标赛；4 人格读者小组 3/4 共识过滤（单判官噪声的现成解）；高原检测+收敛判据（"措辞从 problems 转向 costs of ambition 就停"）。
5. **回写先过门禁再入账**（天命）：CHANGES 声明自身被校验后才应用到快照，脏状态不进账本——与 master plan 的 promoted-only 正典同构，且补上"回写数据自身的确定性验收"（reader_promise 漂移正缺这环）。秘密知情列表/誓约/截止倒计时三个维度设计值得抄。
6. **审计维度按题材 profile 激活**（inkos `auditDimensions`）：37 维不全开，按 genre profile 选 + 书级增补 + 模式化降级。是我们一系列"题材盲误毙"问题的通用解形——检查器激活表进 genre_taxonomy。
7. **带时效的事实三元组**（inkos facts 表：valid_from/valid_until_chapter）：事实可过期，支持"第 N 章时他知不知道 X"时序查询——跨章事实漂移检测的理想底座。
8. **未知实体门禁**（天命）：新实体>5 或无状态登记的龙套>3 打回——"无铺垫登场伪回调"病灶的现成确定性拦法。
9. **判官防误伤条款**（NovelForge/ainovel-cli）："证据不足必须写入待确认项，不得强行下结论"、"过渡章不因爽点不够机械扣分"——写进判官 prompt 契约。
10. **@DSL 声明式上下文装配**（NovelForge `context_service.py`）：`[filter:content.name in $self.content.entity_list]` 按当前章实体名册动态拉相关卡——上下文装配从代码逻辑升维成可配置声明，可作 context.py 长期演进方向参考。
11. **反例→正例对照表**（inkos writer-prompts）：比禁则列表更可服从的去AI味 prompt 形态——但 Issue #112 证明纯 prompt 长程必衰减，坚定我们"detector→deslop 确定性闭环"路线；对照表作为 deslop 重写 prompt 素材格式。
12. **WebNovelBench 式百分位基准**：把"作品级质量基准缺失"（README 自认缺口）落成"AI 小说在人类网文分布中的百分位"，比绝对分可信。

## 五、演进建议：突破质量瓶颈的路线图

**总纲：停止加规则，转向"选稿-晋升-收敛"闭环。** 横向调研的最大结论是：我们与全行业一起卡在同一层——事实连贯有余，"好看"无解。而唯一拿出成书证据的 autonovel，秘密不在更多检查器（它的机械层比我们简陋得多），而在**修订-收敛-选稿闭环**：每一稿都被对抗编辑、被 Elo 排位、被读者小组共识过滤、修不动就停。

### Phase 0（正在做，优先级不变）：执行 7-10 master plan

晋升状态机 + promoted-only Canon/Snapshot/Retrieval + Prompt Compiler + 独立盲评 Judge。外部调研全面验证了这个计划的方向正确性，无需改向。可吸收的增量：
- 状态机里直接内置**最优快照回滚**语义（inkos）；
- Canon 回写侧加**回写数据自过门禁**（天命）。

### Phase 1：选稿革命（行业空白点，最大差异化机会）

- best-of-N 从"字数格式启发式"换成**配对盲评锦标赛**（Elo 或 Swiss），判官只做 A/B 相对判断，绝对分废弃（StoryReward 证据 + 我们自己的记忆结论一致）；
- 判官从单人格换成 **3-4 人格读者小组 + 共识过滤**（autonovel：3/4 共识才算数），人格对齐我们已有的 genre_persona（下沉男频/女频画像判官已有基建）；
- verdict 映射收归代码，rubric 版本化快照（ainovel-cli）。

### Phase 2：全书级文体回归尺 + 修订止损

- 实现 stylestat 式**确定性全书文体统计器**（句式模式/跨章重复句/章末形态/开篇模式），输出进判官上下文当"统计事实"，并作为整书门禁的确定性 Finding——治文风漂移和结构性 AI 味；
- 所有重写循环加**净提升 ε + 高原检测 + 回滚**三件套，从机制上终结 churn；
- 对抗编辑器（"这章砍 500 词该砍哪"）作为 deslop 的上层：先砍冗余再修词法，OVER-EXPLAIN/REDUNDANT 正是中文 AI 味的同型病。

### Phase 3：作品级质量基准 + 人工校准

- 搭 WebNovelBench 式内部基准：拿 50-100 本真实中文网文（分题材）建人类分布，每本 AI 书出"百分位"报告——把 README 承认的"缺作品级基准"落地；
- 少量人工盲评（每本书 3 章 × 3 人次）标定判官偏差，形成判官校准回路（master plan 第 5 根因）；
- 题材 profile 化检查器激活表（inkos 模式），一次性收敛"题材盲误毙"问题族。

### Phase 4（观察项，暂不投入）

- StoryReward 式专用故事 reward model（若开源权重可用，可替换配对判官的一部分）；
- LongWriter-Zero 的 RL 训练侧路线（需自训模型，超出当前框架边界）；
- 带时效事实三元组改造（inkos facts 表）——收益明确但改造面大，排在正典晋升语义稳定之后。
