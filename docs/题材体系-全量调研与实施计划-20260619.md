## 0. 结论先行

题材在框架里**不是一套体系,而是 5 套互不相认的叫法**:展示层(62卡)、facet 层(primary_genre)、能力层(13品类)、场景库(material_library ~37 自由串)、文笔层(29 pack)。它们各自碎裂、且彼此不对齐 → 不仅"选题材太窄",更导致 routing/检索跨层丢命中(场景库 0 命中是已知反复踩的坑)。

**本计划要做的,不是在展示层加节点,而是引入一套 canonical 题材体系(频道→题材→子题材→标签 + 别名),把 5 层全部收敛对齐**,并补齐落在薄能力桶上的题材。分两大块:
- **A. 对齐(主干,纯加法、零DB迁移)**:canonical taxonomy + 别名统一 + 展示层重构 + routing/检索改走 canonical。
- **B. 补缺(能力层,可分批跟进)**:薄品类(科幻/都市/武侠)、缺失 pack(玄幻/武侠)、参考语料(仅2)、对标基准(薄)。

## 2. 平台市场调研(范式,基于知识)

四层范式,各平台一致:**频道 → 大类 → 二级/子类 → 标签(多选) ＋ 正交(视角/时代/风格/篇幅)**。

| 晋江 | 原创/衍生 | — | **多维正交**:类型(言情/纯爱/百合/无CP)×时代(古/今/未来/架空)×风格(正剧/轻松/暗黑)×主题标签 |
| 七猫/纵横 | 男/女 | 起点式 | 番茄式 |

## 5. 完整实施计划(全题材、全层)

> 原则:A 块纯加法、零 DB 迁移、不碰写手 prompt、soft-only;B 块按优先级跟进,各自独立可交付。每阶段走五阶段 + 三层验证([[dev-verification-standard]])。

### Phase A — 对齐主干(一次性覆盖全题材)
**A1. canonical taxonomy 配置**
- 新增 `config/genre_taxonomy.yaml`:channels + 19题材×子题材 + `aliases`(含 §3.2 全表)+ 每节点 `category`/`pack`/`default_tags`/`power_system`。
- 新增 `tags_additional`(升级流/扮猪吃虎/退婚流/签到/神豪…)合入 `trope_tags`。

**A2. taxonomy 服务**
- 新增 `services/genre_taxonomy.py`(仿 `novel_categories.py`):`load_genre_taxonomy()`、`list_genres(channel)`、`get_sub_genre()`、`canonicalize(genre_str)->canonical`、`resolve_selection(channel,genre,sub,tags)->{genre_str,sub_genre,category,pack,tags}`。

**A3. routing/检索改走 canonical(治 0 命中)**
- `resolve_novel_category`(`novel_categories.py:174`)与 prompt_pack inference 入口先 `canonicalize`;`_GENRE_NAME_KEYWORD_MAP` 收敛为「仅兜底」。
- material_library 检索按 canonical + aliases 匹配(对接 [[genre-scene-bank-material-library]] 的接入点)。

**A4. API**
- 新增 `GET /api/genre-taxonomy`(树+标签+频道+别名)。
- `POST /api/tasks/quickstart`(`server.py:3320`)接受结构化 `GenreSelection{channel,genre,sub_genre,tags,facets,template_key}`;**保留 `genre_key` 老路**(模板)。`server.py:3336` 硬锁改为:selection 走 taxonomy 校验,genre_key 走 presets。
- `POST /api/projects` metadata 增写 `channel/sub_genre/tags/facets`;`genre` 由 `resolve_selection` 组装。**零 schema 迁移**。

**A5. 前端「选题材」重构**
- 频道行(升顶)→ 题材chips(闭合,按频道过滤)→ 子题材chips(联动,含「不限」)→ 流派标签(多选0–8,搜索)→ 折叠高级facet。
- 62卡降级为「热门开局模板」货架(点=回填四轴);脑洞/钩子/concept-lab 保留,作用域改为「已选题材内细化」。

**A6. 62卡→树映射 + 兼容**
- `preset → (channel,genre,sub_genre,tags)` 映射表(设计稿已含节选,实现时补全62条)。
- concept-lab/脑洞入参由 `genre_key` 改 `(genre,sub_genre,tags)`,回归覆盖。

**A 块三层验证**:
- L1:taxonomy 加载;每 sub_genre.category∈13、pack∈现有 pack;default_tags⊆标签池;`canonicalize` 把场景库37串全部映射到 canonical(覆盖率断言);62卡100%落树。
- L2(git-stash A/B):旧 `genre_key` 对全部62卡产出的 `(genre,sub_genre,category,pack,target_*)` **逐字不变**;material 检索命中数 **≥** 改前(别名只增不减)。
- L3 真机:走「男频·末世·天灾囤货·[囤货,升级流,系统]」与「玄幻·异世大陆」(旧体系不可表达)端到端到落库,核验 DB genre 串/metadata/category/pack/场景库命中,A/B vs 旧 apocalypse-supply。

### Phase B — 能力补缺(按 §4 优先级,各自独立)
- **B1**:科幻/都市/武侠 `novel_categories` + `story_design_grammars` 补到 5 阶段格式(对齐厚品类)。
- **B2**:新增 `prompt_packs/xuanhuan-*.yaml`、`wuxia-*.yaml`(现借用)。
- **B3**:`reference_corpora/` 补 玄幻/末世/现代言情/都市(判官+对标)。
- **B4**:material_library 补种 军事/纯爱百合/幻想言情/大女主。
- **B5**:`benchmark_targets` 扩题材;`platform_profiles` 补 晋江/纵横。
每项独立走五阶段 + 三层验证;不阻塞 A 块上线。
