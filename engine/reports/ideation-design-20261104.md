# 选题工坊设计 · 2026-11-04

监工 Claude 写，给 Codex 执行第 24 条时用。用户反馈：网页端选题质量一般、每次生成差不多、缺乏创意。

## 1. 现状诊断

**Evidence（证据）**
- 网页选题只有一次裸调用（`tools/webui/jobs.py:227`），提示词只有一句：“为{题材}生成 12 个选题，每个含 title 和 premise”。题材包 `config/prompt_packs/`、市场画像 `config/market_profiles/` 一概没读。
- `books/webui/.topics/` 里玄幻同一输入连跑的 3 批：
  - “一掌镇乾坤”原样出现了 2 次；
  - “我以凡骨镇仙门 / 我以凡骨铸仙胎 / 我以凡骨镇天门”三批各一个；
  - 退婚、重生魔尊反复出现；
  - 还漏出过英文书名“全宗门都以为我是 farming system's dummy”。
- 悬疑一批全是文艺短名，没有钩子：末班地铁、完美不在场证明、第七位客人、静默楼层……
- 前端按“题材 + 章数 + 想法”缓存（`app.js:114`），条件相同时再点也只会读出旧的那一批，没有“换一批”。

**Inference（推断）**
- 一句话提示词 + 无历史 + 无约束，模型给出的必然是该题材语料的众数，所以“每次差不多”。这和旧框架 2026-07 确诊的“概念层均值回归”是同一个病。

## 2. 市场调研（2026-11-04 番茄当日榜单，FanqieHub，2,190 本，男女频 37 个分类，新书榜 1,080 本）

**Evidence**
- 书名中位数 12 个汉字。72% 的书名是两段式，用逗号或冒号隔开。
- 书名形态分布：

  | 形态 | 男频 | 女频 |
  |---|---|---|
  | 「熟壳：反差钩子」 | 43% | 25% |
  | 「处境，意外结果」 | 31% | 30% |
  | 反问/感叹 | 14% | 11% |
  | 短名 | 10% | 32% |

- 53% 的新书简介第一行是【标签+标签】卖点行，直接宣告爽型，例如“读心+吃瓜+团宠”“战锤+钢铁洪流+无敌横推”。
- 新书榜高频标签：穿越 489、系统 283、开局 100、重生 90、魂穿 88、多女主 79、灵异 75、无CP 51、空间 51、打脸 39、直播 38、求生 33。
- 新书榜头部的共同形状是：大家熟悉的壳，加一个反差变量，让读者一眼就知道爽在哪。下面是今日实例，仅供监工分析，**不得进生成提示词**：
  - 《我都化龙了，你说功法是假的？》
  - 《海洋求生？可我是人鱼公主！》
  - 《让你制作奢侈品，你做龙泉印泥？》
  - 《全民领主：抽到人族，但来自战锤》
  - 《修仙，每天十倍收益结算》
  - 《直播鉴宝：怎么连线的全是鬼啊！》
  - 《破案：我能闻到凶手的味道》
  - 《上朝第一天，吃瓜自爆我女扮男装》
- 金手指写的是具体规则，而不只是“系统”两个字：
  - 每天十倍结算、授徒万倍返还、相亲越奇葩奖励越丰厚、改变历史就变强、一境一大金手指。
- 女频的钩子多是一对人物关系：“老实女人 × 顶级大佬”、反向强制爱、先婚后爱、年龄差、网恋加错人。
- 非遗、古法、本土民俗带来文化自豪型爽点，例如“鬼新娘”“龙泉印泥”“茅山”。

**和旧框架积累的结论对上了（来自归档调研，非今日数据）**
- 新鲜度的合法区间是 0–1 个新变量，而且必须是“熟机制 × 异场景”的嫁接。孤立的新概念在榜上几乎不存在；新东西堆两处以上，读者就看不懂了。
- 榜单从不解释来历，只解释规则。爽型靠句子结构来宣告（数字倍率、两极对比、越 X 越 Y、旁人反应预演），从不自己说“很爽”。
- 好概念不能被读者一眼补全全书，而且自带几百章的引擎：有进度条，有一级一级往上的问题梯。

## 3. 设计：选题工坊（五步，全部落在书目录，可断点续）

```
输入（题材/频道/章数/想法）
 → ① 市场快照（确定性，按天缓存）
 → ② 抽轴发散（代码随机组合，多次并行调用）
 → ③ 确定性筛（俗套/撞车/历史重复/语言/字段）
 → ④ 判官排序（只排序不杀，先验尺子）
 → ⑤ 卡片呈现 + 换一批 / 沿此方向再来 / 自己改
```

### ① 市场快照
- 每天最多拉一次 FanqieHub，必要时加七猫，缓存到 `books/.market/YYYY-MM-DD.json`。拉取失败就用最近一份缓存；一份都没有就跳过，标记为“无市场数据”。整个过程不能阻断选题。
- 题材包到番茄分类的映射写在 `engine/data/ideation/genre_map.yaml`，每个题材包映射到 1–3 个分类。
- 从对应分类的新书榜提取**类别级特征**：
  - 高频标签；
  - 书名形态分布；
  - 熟壳清单，例如全民领主、恐怖游戏、直播、四合院、穿书；
  - 金手指规则类型，例如倍率结算、返还、模拟器、读心、弹幕。
- 真实书名和简介只给 ③ 查撞车、给 ④ 判官做锚点，**绝不进入 ② 的生成提示词**。旧框架四轮定案：提示词里出现的示例会被整批照抄成骨架。

### ② 抽轴发散（解决“每次差不多”）
每个候选由代码先抽好四根轴，模型只负责把它们写成一个故事：

| 轴 | 来源 | 举例（类别级） |
|---|---|---|
| 熟壳 | 市场快照的熟壳清单 ∪ 题材包内置壳 | 宗门、全民降临、直播、年代、穿书 |
| 唯一新变量 | `data/ideation/variables.yaml`：职业 / 地域民俗 / 时代 / 物件 / 规则 / 关系动态，各 30+ 项 | 一门手艺、一种结算规则、一对反差关系 |
| 爽型或情绪型 | 题材包的爽型 ∪ 通用爽型表 | 扮猪吃虎、反差打脸、甜宠拉扯、解谜揭底 |
| 主角欲望 | 通用欲望表 | 活下去、翻身、复仇、守护、发财、被看见 |

- 一批 12 个，由 3–4 次并行调用产出 18–24 个原始候选。每次调用拿到不同的轴组合，同一批里同一个熟壳最多出现 2 次。
- 抽轴用的随机种子写进 `topic.json`，便于复现。
- 用户写了一句话想法时，想法固定为主轴，其余轴照抽，保证仍有变化。
- 每个候选输出这些字段：
  - `title`
  - `hook`：一句话钩子，30 字以内，讲清熟壳、新变量和爽点；
  - `tags`：【】卖点行，3–5 个；
  - `premise`：120 字以内，具体人物、欲望、阻碍；
  - `golden_finger_rule`：金手指的具体规则，没有就写“无”；
  - `opening`：第一章开场画面，一句话；
  - `engine`：长篇引擎，讲清进度条是什么，前 3 级问题梯分别是什么。章数 ≥30 时必填。
- 提示词只写**类别和结构**要求，例如“书名可以是两段式、反问式或短名，按卖点选形态”。不放真实书名，不放反面词表。否定式指令会把禁用词种进模型眼前。

### ③ 确定性筛（代码，不调模型）
- **俗套**：`data/ideation/cliche.yaml`，按题材分组的组合俗套，例如“废柴 + 退婚 + 戒指老爷爷”。双词元同时命中才算俗套，降权到末尾，不直接删除。
- **历史重复**：和本题材最近 5 批已展示的候选比，书名或钩子的汉字二元组 Jaccard ≥0.5 就剔除。“换一批”就靠这一条保证真的换。
- **撞车**：和当日榜单真实书名近似的剔除，并在卡片上注明撞了哪本。
- **语言和名字**：出现英文、繁体、乱码，或者用了烂大街名（复用 `data/` 里已有的名字黑名单，没有就新建）就剔除。
- **字段**：缺字段、超字数的剔除。
- 筛完不足 12 个时补一次调用；仍然不足，就展示实际个数并说明原因，不凑数。

### ④ 判官排序（只排序，不杀，先验尺子再用）
- 一次调用，对候选给 4 轴打分：
  - **不可补全**：读者能否从书名猜到全书；
  - **点击欲**：书名和钩子；
  - **长篇引擎**：按章数要求；
  - **好懂**：新变量 ≤1，没有黑话。
- 判官调用里可以放当日同分类新书榜头部 6 本的书名和钩子作锚点。判官读例证是合法的，写手读例证不合法。
- **先验尺子**：上线前跑一次锚点测试。把当日真实榜单书 6 本和旧生成器产出 6 本混在一起盲排，真实书进前 6 的个数 ≥5 才算判官有效。不达标时，判官分只显示为“参考”，排序改按多样性轮转，并在报告里写明。
- 判官失败或超时，不影响展示，按 ② 的顺序给出。

### ⑤ 呈现与交互（webui）
- 卡片显示：书名、钩子、【卖点】、premise、金手指规则、开场画面、长篇引擎、判官四轴分（标为“参考”）、市场备注（对应哪个熟壳，今日新书榜同壳几本）。
- 按钮：
  - **换一批**：同样的输入重新抽轴，排除历史，不读缓存。
  - **沿这个方向再来**：两种变体。一种保留熟壳、换新变量；一种保留新变量、换熟壳。各出 6 个。
  - **改一改**：打开卡片字段编辑，改完直接开书。
- 选中的卡片完整字段作为 `user_input` 传给 bookengine，而不是只传 premise。
- 每批费用显示在按钮旁，单批 ≤$0.05。

## 4. 代码落点与约束
- 新包 `engine/ideation/`，≤600 行，单文件 ≤500 行，在 `tools/check_scope.py` 里加限额。
- ideation 不 import bookengine。复用 webui 现有的 MiniMax 调用方式，不另起一套客户端。
- 轴池、俗套、映射、名字黑名单全部放 `engine/data/ideation/*.yaml`，不写进代码。
- webui 的改动计入 webui 的 1200 行限额。旧的 `topic_worker` 改成调用 ideation，删掉旧提示词。
- 外部请求只有 FanqieHub 和七猫两个公开榜单接口，不带任何用户数据和密钥。

## 5. 验收

| 项 | 标准 | 类型 |
|---|---|---|
| 换一批 | 同输入连跑 3 批，跨批书名近重复（二元组 Jaccard ≥0.5）为 0；旧生成器同指标作对照 | 自动 |
| 批内多样 | 12 个里不同熟壳 ≥6 个，单一书名形态 ≤60% | 自动 |
| 市场形态 | 书名形态分布与当日新书榜同频道分布的差距写进报告（只报告，不设门槛，防止全员两段式） | 自动 |
| 判官尺子 | 锚点盲排真实书进前 6 ≥5/6，否则判官降为参考 | 真机 |
| 语言/名字 | 英文、乱码、黑名单名 0 处 | 自动 |
| 断点 | 中途杀进程再续，不重复扣费，不重复调用已完成的步骤 | 自动 |
| 读者 | 玄幻、悬疑、女频言情各出“旧 1 批 + 新 1 批”，打乱后放进 `books/blind-ideation/`，由用户盲选 | **Unknown，待用户** |

预算：开发与真机实验合计 ≤$1。
