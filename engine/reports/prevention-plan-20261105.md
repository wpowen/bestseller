## 二、预防方案

### 1. 写书质量：把“好看的结构”写成可检查的规则（第 33 条）
确定性检查优先，模型只负责改写；检查不合格时定向重生成，不硬停书。

- **结构规划（故事圣经）**
  - 每 10–12 章一个阶段（arc）。每个阶段要有：主要地点（与上一阶段不同）、阶段对手、阶段目标、阶段收束事件。
  - 反派分级：每个对手标注层级和退场章；低层级对手必须在所属阶段内退场或降级为背景。
  - 章数 ≥30 的书不允许只有 1–2 个阶段。
- **跨批章纲去重**
  - 生成后一批章纲时，传入已用桥段类型清单和章名关键词表。
  - 章名高频关键词（同一个实词出现在 ≥3 个章名中）触发重写。
  - 相邻 5 章的核心冲突类型不能完全重复。
- **跨章衔接**
  - 每章写完后抽取“结尾地点 / 在场人物”，存进状态。
  - 下一章写之前，把这些作为硬约束传给写手；写完后核对开头地点。对不上就只重写开头段，补上人物的移动过程。
- **人物登场与称呼**
  - 有名有姓的角色首次登场，必须在章纲里标注来历。
  - 正文里出现人物卡没有的外号或自称（如“牛哥”），记为问题并在本章修复轮处理。
- **终稿清洁**（写手落盘时，以及去 AI 写终稿时，各做一次）
  - 删掉正文里的 Markdown 标题、“第X章 / 第X场”行、分隔线、emoji 和异常符号。
  - 清洗用确定性代码，写测试；每章记录清掉了几处。
- **整书体检 `book_checkup.json`**（全书完成后自动生成，只读、确定性）
  - 统计：地点数和阶段分布、每个对手跨越的章数、章名关键词重复、跨章地点断裂次数、格式残留、首次登场缺铺垫的人物。
  - 网页详情页“检测报告”展示这些统计，标为“参考”。
- **验证**
  - 新流程开一本 50 章新书，用上述统计和《一掌镇乾坤》对比。
  - 把用户提供的横评提示交给外部模型，对新旧两书做匿名评审。
  - 评审意见逐条用脚本核对引文和章号，标出核实 / 未核实。最终以用户阅读为准。

### 2. 工程护栏：让漏洞在技术上无法发生（第 34 条）
- **真实书库回归集（解决 D1）**
  - 把现有 4 本书做成只读快照夹具，复制到临时目录使用，覆盖这些形态：
    - 只有草稿、没有终稿；
    - 旧版独立去 AI；
    - 边写边去 AI 的流水线书；
    - 带重命名、带回滚章节的书。
  - 新增 `tools/real_library_smoke.py`：在快照副本上起 webui，逐页请求书库 / 详情 / 阅读 / 导出 / 删除 / 归档，断言没有空白页、没有 4xx/5xx、标题正确、导出只用终稿。
  - 今后每条网页或运行时相关的指令，验收都必须跑一遍并附上输出。
- **书库写保护（解决 D2）**
  - 测试与临时实例默认拒绝把 `--books` 指向仓库的 `books/`，除非显式声明“生产”。conftest 也拦截写入。
  - 新增 `tools/books_guard.py snapshot|verify`，对真实书库做清单 + 哈希快照，监工在 Codex 运行前后各跑一次。
  - `.ops.log` 记录来源：网页点击（带 User-Agent）、API 直调、CLI。删除前把书目录打包到 `books/webui/.trash/`，保留 7 天后清理，误删可以找回。
- **密钥卫生（解决 D3）**
  - AGENTS.md 和每条指令都写明：禁止 `ps`/`pgrep -f`/`env`/`printenv` 这类会打出进程参数或环境变量的命令；查进程只用 `pgrep -x` 或按 PID 看 `comm`。
  - 新增 `tools/redact.py` 过滤器，测试日志和报告落盘前替换所有 `.env` 里的密钥值。
  - 已泄露的 MiniMax 和 DeepSeek 密钥由用户轮换。
- **并行归属（解决 D5）**：每条指令开头写清“可改 / 禁改”的目录。监工发出前检查各条指令之间有没有重叠。
- **外部评审核对（解决 D6）**：新增 `tools/verify_review.py`。输入评审里引用的原文和章号，逐条到书稿里查找，输出核实 / 找不到。外部评审先过这个工具，再进需求。
