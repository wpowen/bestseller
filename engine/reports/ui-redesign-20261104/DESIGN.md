# 书房网页改版设计 · 2026-11-04

监工 Claude 设计，给 Codex 执行第 25 条用。可点击原型见同目录的 [prototype.html](prototype.html)，用浏览器直接打开即可。

用户反馈：新建和看书全挤在一个页面上，看书不方便，没有目录，也没法铺开宽屏；书库里历史书太多，又没有删除入口。

## 1. 现状问题（Evidence）
- `index.html` 只有一页，从上到下依次是开书表单、书库、阅读区（`#reader`，默认隐藏）。点“阅读”后正文在书库下方展开，章节靠下拉框切换。
- 正文版心固定，宽屏两侧大片留白，没有字号、宽度、背景设置。
- 书库没有归档和删除，只能刷新。
- 历史验证书 38 本已由监工按用户指示永久删除（212 MB），现在书库只剩网页建的 4 本。

## 2. 信息架构：四个视图，各管一件事

| 路由 | 视图 | 只做这件事 |
|---|---|---|
| `#/library`（默认） | 书库 | 找书、看状态、开始/暂停、归档/删除 |
| `#/new` | 开新书（三步向导） | 方向 → 选题 → 写作设置 |
| `#/book/<id>` | 书籍详情 | 封面信息、目录、故事圣经、章纲、检测报告、导出 |
| `#/read/<id>/<n>` | 阅读器（全屏） | 只看书 |

- 顶栏常驻：品牌、书库、开新书、总花费进度条、深浅色切换。阅读器全屏覆盖，不显示顶栏。
- 浏览器的前进和后退可用；刷新后停在原来的视图。阅读器打开时显示的视图和书的 id 都从 URL 恢复。

## 3. 各视图要点

**书库**
- 卡片网格，自适应列数。封面是按题材配色的渐变色块，上面写书名（不需要图片）。
- 卡片显示：状态徽标（写作中会闪烁、已完成、已暂停、中断）、进度条、字数、花费。按钮有“阅读”、“暂停/继续”和 ⋯ 菜单。
- ⋯ 菜单：书籍详情、导出、重命名、**移到归档（可恢复，带撤销提示）**、**永久删除**。永久删除要在弹窗里输入书名才能确认；正在写作的书要先暂停，否则服务端拒绝。
- 工具栏：状态分段（全部/写作中/已完成/已暂停）、搜索、排序。末尾放一张“＋开一本新书”的卡片；书库为空时只显示这张。

**开新书（三步向导）**
- 左侧是步骤条，可以点回任意一步。右侧是当前这一步的面板。
- ① 方向：题材按“男频 / 女频 / 其他”分组，做成可点的标签；然后是篇幅预设、每章字数、一句话想法。
- ② 选题：直接嵌入第 24 条做好的选题卡片和三个按钮（换一批 / 沿这个方向 / 改一改）。选中一张后才能进下一步。
- ③ 写作设置：写手、写作预算、去 AI 预算、并发数、是否自动去 AI，并显示费用预估。点“开始写作”后跳到这本书的详情页。

**书籍详情**
- 头部：大封面、状态、书名、一句话简介，加四个统计（章节、字数、花费、创建时间）。主按钮是“继续阅读 · 第 N 章”，N 记在浏览器本地存储里；还有“继续写作/继续去 AI”。
- 标签页：
  - **目录**：多列网格，每章显示序号、章名、版本（终稿/草稿）和字数，没写完的章置灰；
  - 故事圣经（人物卡片网格）；
  - 章纲；
  - 检测报告（标为“参考”）；
  - 导出（五种格式，可选版本）。

**阅读器（重点）**
- 全屏两栏：左边是可收起的目录侧栏（带搜索，当前章高亮，按卷分组），右边是正文。
- 顶栏依次是：目录开关、返回、书名·章名、版本切换（终稿 / 草稿 / **对照**）、复制本章、Aa 阅读设置。顶栏下方有一条全书进度细线。
- **对照模式**：草稿和终稿左右两栏铺满宽度，终稿里改过的地方高亮。这正是用户盲读和验收去 AI 效果要用的。
- 阅读设置弹层：
  - 字号 4 档；
  - **版心宽度 4 档**：窄 / 适中 / 宽 / 铺满，用户要求的宽屏阅读就靠这个；
  - 行距 3 档；
  - 背景：纸 / 护眼 / 夜间。

  设置都记在浏览器本地存储里。
- 键盘：← → 翻章，T 开关目录，Esc 返回详情。
- 章末放“上一章 / 目录 / 下一章”。
- 正文用宋体系衬线字体，首行缩进两字，行距 2。

**窄屏（<900px）**：向导步骤条改成横排，详情页头部压缩，阅读器目录改成抽屉，对照模式改成上下排列。

## 4. 视觉规范
- 沿用现有配色并整理成 token，见原型 `:root`：纸色底 `#f6f3ec`，墨绿主色 `#2f5a46`，金色点缀 `#a0804d`，另有一套夜间配色。
- 标题、书名、正文用衬线字体（Songti SC / Noto Serif CJK SC），界面文字用系统无衬线。
- 卡片统一圆角 14–18px、细边框、柔和投影；按钮分主按钮、普通、幽灵、危险四种。
- 不引入外部字体、CDN 或构建工具，继续用原生 HTML/CSS/JS。

## 5. 后端改动
- `POST /api/action` 新增三个动作：
  - `archive`：移到 `books/webui/.archive/<id>/`，书库扫描会跳过以点开头的目录；
  - `restore`：从归档移回；
  - `delete`：需要请求里带回书名，正在运行的书一律拒绝，只允许删除 `books/webui/` 下的书。
- 书库接口补两项：每章的状态（终稿/草稿/未写）和一句话简介。
- 新增 `GET /api/archive`，列出已归档的书（书库底部放“已归档 N 本”入口）。
- 删除和归档都写一行操作日志到 `books/webui/.ops.log`。

## 6. 验收
- 四个视图都能通过 URL 直达；刷新、前进、后退正常。
- 1440px 宽屏下，阅读器“铺满”档的正文宽度 ≥1200px；对照模式两栏各 ≥560px。
- 375px 手机宽度下没有横向滚动，阅读器目录以抽屉方式打开。
- 归档后书库少一本，撤销后恢复；永久删除必须输入正确书名，删正在运行的书会被拒绝；以上都要有测试。
- 现有功能不能丢：断点续写、暂停/继续、复制、五种导出、去 AI 对照、预算显示。
- 在浏览器里实际截图：书库、向导三步、详情、阅读器（适中 / 铺满 / 对照 / 夜间）、手机宽度。截图放到 `engine/reports/ui-redesign-20261104/shots/`。
- 行数分开算（用户 2026-11-05 定）：webui 的 Python ≤1200；前端 JS/HTML/CSS ≤1500，单文件 ≤800，每行 ≤160 字符。`check_scope` PASS，全部测试通过。写不下时先停下报告，不要自己放宽限额，也不要把代码压成一行来凑行数。
