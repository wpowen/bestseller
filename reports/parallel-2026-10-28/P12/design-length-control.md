## 1. 合同、计数与启用范围

- 协议：`book-length-control-v1`；计量：`export-body-words-v1`，即P11使用的正式拼接清理、去章标题后的CJK字数加拉丁词/数字串数。纯函数只接收已验证的非负整数，不读取正文、SHA、数据库、环境变量或配置。
- 第一版适用于中文项目。旧章节门的汉字/含题口径、缓存字数不能直接当成这个计量；调用方必须从同一采用源重新计算，并保留旧门的独立结果。更严格的平台边界/旧有效合同继续取交集；不能以计量变化绕过它们。英文项目继续旧协议，另行设计。
- **新代码入口的 `protocol=None` 即关闭，返回 `None`，含义是不适用新合同，不是合格，也不替代原门禁。** 仅精确匹配v1时执行新检查；未知协议抛ValueError，禁止静默降级或自动发起付费修复。
- 生产启用必须由可信的新生成合同快照授权，在发正文请求前冻结。不能从“现在的项目开关”推断旧草稿采用哪套规则。当前没有修改settings/config/创建入口，v1没有任何生产调用点。

## 2. 初始章目标与硬区间（已实现）

整书目标B、章数N，冻结原始章目标a_i，必须为正整数且Σa_i=B。调用方可传完整 `planned_targets`；缺省使用商和最大余数分配，前余数章加1字。不要调用会补偿抬高目标或放宽上限的旧归一化路径后再套本合同。

```
L_i = max(1800, effective_platform_min, ceil(0.85*a_i))
U_i = min(3500, effective_platform_max, floor(1.15*a_i))
book_L = ceil(0.85*B); book_U = floor(1.15*B)
```

本库参数 `hard_min_words/hard_max_words` 支持更严格的平台交集；不能把绝对墙放宽到1800以下或3500以上。纯函数不主动识别平台，调用方仍负责解析。

|预设|初始目标|v1默认区间|整书上传长度区间|
|---|---:|---:|---:|
|4章/8000|2000|1800–2300|6800–9200|
|6章/15000|2500|2125–2875|12750–17250|

- 短目标如1500的±15%上界1725低于1800：无合法交集，规划阻塞，不输出一个伪合法短章。1750等目标若交集非空，可在绝对下限与容差内取最接近目标值；记录精确总目标是否仍可达。
- 长目标如4000与绝对墙的交集为3400–3500，目标夹到3500；若整书容差仍无法承载，就返回预算不可行。不是无条件让每章都“按3500写”。
- ±15%对齐当前**上传长度判断**，不是把finalizer现有±10%条件悄悄改掉。主线需显式区分上传合同与更严的编辑目标；在其分歧解决前，v1通过不代表finalizer通过。

## 3. 累计预算与可行性（已实现）

输入为按章序排列的**已采用源前缀**字数，S为其总和、k为其章数。原始a_i和区间始终冻结，不按新目标重置。草稿写完时可用临时分支预览预算；只有正式采用后才替换事实前缀，候选/working current/失败改稿不能重复记账。

1. 剩余各章固定窗口为[L_i,U_i]。剩余总量可行区间为：
   `R_L=max(ΣL_i,book_L-S)`，`R_U=min(ΣU_i,book_U-S)`。
2. `R_L>R_U`：`BOOK_LENGTH_BUDGET_INFEASIBLE`，无targets/next_band，不下发生成请求。已采用章若违反绝对1800–3500则返回 `ADOPTED_CHAPTER_HARD_BOUNDARY`，不因总和合法而给出新目标；这是新计划前置条件，不重写旧回执。
3. 优先分配`B-S`；精确目标不可达但容差可行时，取离它最近的可行R，并显式返回 `exact_target_feasible=False`。此时不得对外宣称精确命中B。
4. 在各章固定窗口内做有界等份分配：先放下限，剩余额度按活跃容量均摊，饱和章退出；整数余数按章序分散。输出targets总和严格等于R。
5. 当前目标q=targets[0]，当前可执行窗口进一步收紧：

```
next_L = max(L_i, ceil(.85*q), book_L-S-Σlater_U)
next_U = min(U_i, floor(1.15*q), book_U-S-Σlater_L)
```

滚动目标的±15%**只与固定窗口取交集**，不能成为新基准向外累乘；最后一章还受整书剩余额度约束。可接受窗口的任一端点都给后续保留一个可行完成方案。完成时没有next_band，只检查最终总量区间及绝对章墙；`feasible=True`仅证明长度条件，绝不授予书籍完成或上传权限。

例如首章已采用2300，4章8000的后三目标为1900/1900/1900；若旧规则下首章已采用2600，则为1800/1800/1800，能回到8000。6章15000若首章3200，余下五章2360；这些旧前缀高于新目标带时保留历史身份，不主动重新审判，但后续新候选受v1限制。

## 4. 候选验收、去AI味与费用上界

**纯判定已实现，调度/持久化只设计。** draft、rewrite、deslop使用同一预算快照，不允许安全建议带只写prompt而审计仍放到3500。边界含等号，无10%警告宽限；超带返回 `LENGTH_CONTROL_UNDER/OVER`。

Deslop有效上限另取 `min(next_U, floor(1.05*parent_words))`。父版本必须是实际父源且SHA/计量一致，不能用相邻版本或缓存替代；缺失/失配在调用侧标Unknown，禁止自动验收。纯函数缺父字数直接抛ValueError。5%不是额外额度；多轮也不能越过冻结章上限与整书累计上限。已超长父稿的子稿必须回到有效区间，不能仅“比父稿短了5%”就放行。

建议主线策略：

- 发初稿前注入极简目标与硬带、剩余预算及停止条件；节点内容须能在窗口内完成，不靠token截断控制正文长度。
- 数值检查先于昂贵语义审校。不合格候选留历史、拒绝采用，给出差额与已冻结的目标；不得切换回旧协议或复制旧高分回执。
- 初稿超限：在原scope预算内最多一次定向重写，禁止新增戏；不足则补必要事件，保留质量底线。每章新增长度修复最多1次，算入原有次数上限，不另开无限循环额度。长度修复仍不合格或预算不足就阻塞，等明确的新授权。
- 普通rewrite/deslop超限：本轮不自动采用；有合格父稿则保留它，原质量问题未解决时仍不能宣布完成。重试必须占原已授权修订预算，长度不合格不得触发额外免费轮次。建议新协议deslop每事件最多2次尝试，且不超过已有更小上限。
- 质量门保持：信息保全、Canon/Timeline、爽点、商业独立样本、同源审校和知识闭合全部仍需通过。长稿压到区间导致质量失败时宁可阻塞，不把梗概当成稿。

这些上限是**待接入策略**，纯函数不发模型请求，也不实现计费账本或重试控制。总费用/调用次数只能由原scope账本守卫；切协议、重算预算不产生新的付费授权。

## 5. 历史兼容与回执设计（只设计）

1. 旧版本、旧已付费响应恢复和旧审校，按其生成时的协议/配置/计量与原始source绑定复验；缺新字段按legacy处理，绝不补写v1。撤销v1开关不能让已生成v1候选重新按旧宽带过门。
2. 一次新正文请求即使来自旧项目，也只有在显式绑定新合同后才用v1。旧项目启用前做预算可行性预检；不可能的原书应先做授权修订/规划，不静默向后摊债。
3. 每个新候选保存 `protocol/count_unit`、原始计划及SHA、整书目标/容差、平台有效边界、采用前缀章序+draft SHA+计数、下一个min/target/max、父源SHA及计数、候选SHA及计数、判定与原scope的调用授权引用。该快照属于审校来源绑定的一部分。
4. 生成中前缀变化时，在采用事务中重新核验前缀身份/锁序或CAS版本。预算过期不自动迁移采用；保留原候选，按新的明确合同重新判定，必要时阻塞。不能通过覆写ChapterModel原始target_word_count消除差额。
5. 旧历史可离线按v1试算，但结果只是审计意见，不能改旧回执或撤销已采用源。混用字数单位、缺采用源、重复章号或非连续前缀必须由接入层拒绝；纯数值函数无法从tuple辨认这些事实问题。

## 8. 原书救援算例与调用预算

原书采用前缀2495+2433+2812=7740；当前合同4章/8000，上传上限9200。末章预算1460低于v1正文下限1800，所以**保持该合同与前三章不变时，无合法第四章方案**。把标题、注释或统计口径当正文补下限不算解法。正式减少章数或提高整书目标是合同变更，需创作收束、审批及完整重验，不在本任务实施。

|末章去题正文假设|前三章至少需减|篇幅数学上的正文改稿下界|
|---|---:|---|
|1800|340|1章定向修订即可；v1滚动窗口下第3章最多2070，实际减742，总书8798|
|2000|540|纯总量算式可缩至2272，但v1当前窗口更严（1800–2070）；缩至2070，总书8998|
|保留已有2599候选|1139|单章最大可减1012（第3章到1800），至少动2个前三章；2599也超过新生成v1带，若重写末章仍须≤2300|

推荐“先授权缩第3章至约2000–2070，再按新预算重写末章”，不强制重写所有旧章以消除旧目标带差异。理想情况下，**前三章压缩只需1次成功正文改稿**；按最多2次定向尝试预留1–2次，未成功则停。另需末章约1–2次正文生成/修订，两者合计2–4次正文调用是预算假设，非成功保证；不是总LLM调用数。新正文会使相关旧审校/知识来源失效，须另算主审、商业独立slots、连续性、知识闭合及整书语义复验，P11统计无法给可靠总调用数。若要求前三章也全部升级为v1区间，则三章都超2300，至少3次成功正文修订，另加末章；这与“只改必要的一章、其余旧章按旧协议”是不同范围。
