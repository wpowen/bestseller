# P4 正文数量与清单一致性原型计划

目标：在 par/P4（基线 refs/tags/e2e17）开发纯离线、确定性优先的检查器，兼容 CheckerReport，不注册门禁。评估原书前三章四类已知问题的召回与 fa14 四章的逐条误报。

步骤：
1. 查找正式导出与采用身份/哈希证据；仅在缺少导出时考虑带 READ ONLY 和 ≤30s timeout 的 SELECT。禁止 Docker、付费模型、生产写入及禁区读取。
2. 写独立失败测试，记录 RED 底层错误与预期差异；实现数字/单位/金额/时长/清单抽取、显式实体别名归一、矛盾检查与 CheckerReport 输出；同一目标最多三次尝试。
3. 定向测试 GREEN；离线运行七章，逐条复核 fa14 告警，保存摘要、计数、SHA 与短样例。正文不写报告、不提交。
4. 独立代码复查，记录未来 audit_only 放置点、重叠检查与模型辅助边界；提交模块与测试到 par/P4，不合并、不推送。

交付：本计划、REPORT.md（≤2 页）、测试 RED/GREEN 证据、输入来源及 SHA 清单、机器评测摘要/人工判断、模块与测试提交 SHA。报告统一位于主仓库新增目录 reports/parallel-2026-10-28/P4/；代码只改 scratch/par-worktrees/P4/。

预计工时：60–90 分钟。每个工作步骤先核验内置盘可用空间；低于 5 GB 停止。保留所有已有文件，禁止清理。若数据不可取得或必须进入禁区，报告 Unknown，不伪造召回或误报。

初始环境：内置盘约 11.5 GiB；首次 worktree 创建因沙箱 EPERM（exit 255）失败，获执行环境授权后第二次成功；没有改主工作区已有文件。
