## 3. 新旧协议和项目默认

拟议根协议为 `reader-first-planning.v1`，分为 generation、reader-review、writer-delivery 三个有版本的子合同。协议配置存在时也不让它自动覆盖历史项目。

1. **新创建**的构思候选在首次生成前写入根协议、配置 SHA、明确用户输入 SHA。`conception.py` 负责正常构思路径；跳过构思直接建项目的入口由主线写入同样标记。以创建动作绑定，不用日期猜新旧。
2. 项目没有标记时走原协议；“已有规划/正文”只用于识别无标记历史项目，不能使已标记的新项目生成后降级。已标记项目全链使用冻结协议；复验旧调用时只在该原请求的限定 scope 选择原协议。未知版本直接拒绝，不能取“最新版本”。显式关闭需在新生成前落盘；已有新版本资产不得混配旧交付器。
3. 主线统一创建标记之前，Q4 可实现的契约是“新构思默认启用 + 被标记项目全链启用”；**不能宣称所有新项目入口已默认启用**。主线创建入口接好且覆盖测试通过，才达到全产品默认。
4. 新请求使用独立 template/version、配置哈希和来源哈希；历史请求、来源、批准回执、旧 prompt 字节不重写。复验按原请求声明协议选择，关闭开关不等于把旧资产追认成新资产。
   旧复验还核验完整策略源码清单：`draft_continuity_revalidation.py` 80附近限制可迁移文件和 AST 差异。改动允许文件后，单测旧提示词字节相等不足以保证旧复验仍可用。主线须提供符合现有授权的新版迁移证明和完整 reference 复验；Q4 不放宽验证器。互认未完成时报告集成待完成，不宣称旧协议生产复验已通过。

## 4. 故事骨架与淘汰赛

最容易产生偏移的接口不是显式命令“写取证小说”，而是把“具体可验收”“可观察行动”“能力证据”“见证槽位”“不可逆状态”连续填成职责与确认程序。上述词本身不是错误；不能按词命中就删除。

生成器先回答人物想得到什么、怕失去什么、对方为什么不肯、这次选择会改变哪段关系。结构字段随后解释已有情节。普通家庭、生活和情感故事不能为了填“阻力”和“代价”自行加入许可、笔录、第三人见证或签字。

排名/淘汰赛保留因果可信度、原输入保真、题材承诺与商业吸引力的现有审校；增加统一解释：人物动机和关系变化可以提供因果，回报可以是靠近、离开、原谅、重新理解，不能因为没有物证或账目而降分。程序设计完整不能补偿人物无欲望、无选择或情感承诺落空。`minimal/external` 的既有代价选择继续生效，不强迫每章新增伤害。

只对最后完整候选增加一次独立骨架读者审校，不让每个候选乘一次新模型调用。现有 tournament 分轴的提示词在原调用中调整，不冒充独立读者评估。

## 5. 传播控制：保留事实，减少重复指令

新规划中按信息作用分配以下内容，保留原始来源指针和完整规划：

|内容|系统应保存|给写手的任务|
|---|---|---|
|人物欲望、矛盾、选择、关系变化|完整规划与审校绑定|本章现场行动与情感兑现，作为主要任务|
|持有人、知情边界、物品现态|事实与来源原值、适用范围|作为不可违反的参考；状态未变时不逐场重述，不要求人物口头确认|
|保管/见证/核验|原输入依据、是否真实改变局势|只有改变当下选择或兑现用户程序承诺的事件才演出；否则不复制成场景、因果、methodology 三份指令|
|时间|已有 canon 的精确信息原样保存|新提案默认哪一天/什么时段；原精确事实不篡改，呈现不必反复报时|
|代价|已成立的资源、责任和后果|人物本章放弃、承担或失去什么；不用每章复述余额、租金和历史支出；正常资源变化仍保真|

去重按原始字段路径/同一语义义务处理，不按“封”“签”等词删句。不得截断有影响的否定、前提、事件顺序或关键时限；冲突时停止并修规划，不能由提示词层偷偷降权。原任务若要求保管，须先修订新规划并完成审校，不能在 `delivery_block` 抹掉它。

新交付 payload 拟用 `approved-current-chapter-delivery.v3-reader-first`，仍绑定完整 approved 对象哈希、readiness receipt 哈希和本章作用域。呈现侧区分 `narrative_task` 与 `continuity_reference`，并记录字段来源；原完整任务可追溯。主线的来源证明消费者若只接受 v1/v2，新 v3 在互认完成前保持不可采用，不能谎称已实现全链集成。

## 6. 两处模型式读者审校

### 6.1 范围和输入

骨架：最终完整候选（脊柱、故事摘要、主要人物、读者承诺）及原用户输入。必须在现有修复结束之后评估；后续内容变化使回执失效。

大纲：全书卷规划摘要、完整章节目标/关系变化/高潮兑现索引和本次写作的完整场景卡。长书分有界批次，末批含全书兑现索引；每批均受预算计数，不冒充一次调用看过整书。首十章之外也不能借旧审校的范围豁免。输入超容量不能裁掉半段大纲后判通过；返回 Unknown 并重新估预算。

长书预先冻结覆盖清单（所有卷/章/场景、source hash、批次ID和全书索引）；缺项或重复错配不得整体通过。每批使用相同四维，整体每维取各批最低值，均分再按同一门线判断；任一批失败/Unknown使整体不通过，不用全书均分掩盖坏批次。最多一次修规划的额度属于整个大纲检查点，不能每批各领一次。修复后，变更批次、依赖其前后状态的批次及全书兑现索引均失效重审；仅完全未变且依赖哈希相同的回执可复用。若重新分批或跨批因果依赖无法证明，全部重审并重新估算调用，不超过总预算继续硬跑。

### 6.2 四维分数（每维 0—1）

|维度|判断|通过线|
|---|---|---|
|`character_emotion_drives_conflict`|读者能否说清人物为什么必须面对彼此，关系和选择是否推进；程序事件是否抢占主轴|≥0.75|
|`reader_promise`|这份规划许诺什么体验，开篇、发展、收束是否一致|≥0.75|
|`emotional_payoff`|铺垫通向哪次具体选择/交流，高潮改变了什么；不是完成手续即情感成立|≥0.75|
|`character_distinctiveness`|主要人物的欲望、反应与说话方式可否互换|≥0.75|

四维等权均分 ≥0.78，且无高严重度未解决问题，才通过。明确程序题材第一维评人物如何驱动程序冲突，不因“有侦查/庭审”扣分。分线为本次待验证的工程起点，**没有真人校准证据**，不可称平台留存预测器。

每个维度须给可定位 field/chapter/scene、源内证据和理由；证据原句与模型原输出仅私有保存，Git 报告只留得分、代码、范围、哈希及概述。缺维度、非有限数、越界、错误来源引文、模板 fallback、调用失败或输入缺段均 Unknown，不能以默认高分放行。判断是模型模拟读者，不能伪装真人。

### 6.3 重试和停下

每个检查点“初次评估 + 最多 1 次修规划 + 1 次复评”，新读者合同每点最多 3 次物理调用（传输不重试时），两点最多 6 次；长书批次另计。每次修复只处理有证据的问题，保留原用户输入、人物与已批准事实。该额度跨 resume、worker 和商业整改累计，不能换 workflow ID 归零。配置 SHA 或 source hash 变更也不得抹去已消费预算。

复评仍失败或 Unknown 则保留候选、回执和已花预算，返回 `needs_user_direction` 的结构化暂停结果及 2—3 个方向：保留人物关系重排冲突、明确选择程序题材、放弃当前候选重新构思。方向来自本书症结，不自行改变用户承诺。主线负责映射到现有合法状态并阻止自动重试；Q4 不擅自扩展状态枚举。

### 6.4 单次成本与商业审校关系

拟议 critic 单次请求输入上限：骨架 12,000 estimated tokens，大纲 24,000；输出上限均 4,096。估算器数字不是供应商实际 tokens。单次账面上界分别为 `12000×P_in/1e6 + 4096×P_out/1e6`、`24000×P_in/1e6 + 4096×P_out/1e6`；P 取实验冻结模型目录的每百万 token 单价与币种。推理 token 若单独计费需单列；价格未知就记 Unknown，不填零。

两检查点无修复新增 2 次评估；各修一次共 4 次评估加 2 次规划修复。修复输入/输出预算沿用实际 planner 上限，另计费用，不能把评估费用冒充整条整改费用。若 JSON wrapper 另做解析修复也须消费物理预算；“每点3次”只在每请求单发、没有隐性解析补发时成立。

现有商业审校不取消，硬约束/来源不降级。商业评分与新四维分别保存，商业高分不能抵消人物/情感失败；新读者通过也不能洗掉 canon 矛盾。refs/tags/e2e17 的 `outline_reader_experience_judge` 已有首十章六维检查（空间、信息密度等），但缺本设计四维，且 fallback 可返回通过、新调用未显式传 project_id。Q4 不改该非授权文件；新检查显式带两种 ID、严格解析。主线决定整合成同次模型审校还是保留原调用，未完成前须把原调用继续计入实验。

## 7. 写手约束与密度上限

主要人物在 cast 阶段建立简短声线资料：常用语域、句长/节奏、称呼、回避什么、冲突中怎样答话、独特生活经验。不能人人同一套责任边界声明，也不强迫反复喊口头禅。模型审校用“隐去姓名后能否区分”的理由判断，不用对白词汇相似度打硬分。

情感重点场景至少落实一段与当下选择相关的具体回忆或已铺垫经历、能落在现场动作上的感官细节，以及一句人物说得出口、能让读者记住的话。三者为场景写法，不是新增三段说明或强塞金句；回忆不能凭空改 canon，证据不足可用当前共同经历。章级高潮位置和关系变化由规划确定，不能只列道理。

默认创作预算（全部书同规则，**是模型评估的建议上限，不是词表质量门**）：

|项目|默认上限|例外|
|---|---|---|
|精确到分钟的报时|无剧情必要时 0；确有必要最多 2 次/章|用户明确程序/倒计时题材，逐项说明其因果作用并绑定配置；不改既有精确事实|
|无变化状态的确认|同一对象最多 1 次/章，合计最多 2 次/章|新人物的误解或实际争执使确认本身改变关系；模型说明变化作用|

|纯程序说明|非明确程序题材建议不超过叙述篇幅 5%|按语义段落评估，不能正则统计后机械删文；超限先提示编辑判断|

有因果作用的重复不等于冗余；超建议值不自动删句、扣字数或判差书。Q1 指标独立报告，不与本表的语义密度混为同一计量。Q4 的 writer 提示词可写这些建议，自动改稿必须遵守主线设计的分流和轮数。
